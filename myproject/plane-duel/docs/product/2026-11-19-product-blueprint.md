## 一、产品定义

### 1.1 一句话

**"三秒开一局的中国式推理对弈"** —— 把从小玩到大的纸笔飞机棋搬进手机，
用"推理出对方机头"这一个动作，做出微信/应用商店里休闲对弈品类的差异化产品。

### 1.2 为什么是这个游戏能成

| 维度 | 飞机对决 | 斗地主 | 象棋/五子棋 | 扫雷类单机 |
|---|---|---|---|---|
| 单局时长 | 1–3 分钟 | 10–20 分钟 | 20+ 分钟 | 无对战 |
| 上手成本 | 会写坐标就会玩 | 要学牌型 | 要学开局 | — |
| 核心乐趣 | **推理**（信息博弈） | 记牌+配合 | 计算 | 运气 |
| 异步友好度 | 高（回合制，可断线续局） | 低 | 低 | — |
| 观战可看性 | 高（双方标记一目了然） | 一般 | 高 | — |

它的独特位置：**比棋牌轻，比休闲游戏"聪明"**。核心乐趣（从机身命中推断机头位置）
天然适合直播和短视频传播——"他是怎么算出来的？"就是内容。

### 1.3 目标用户与场景

| 层 | 画像 | 场景 | 占比预期 |
|---|---|---|---|
| 核心 | 25–40 岁，纸笔游戏世代，通勤/午休 | 碎片时间 2–3 局 | 20%，贡献 80% 时长 |
| 休闲 | 18–30 岁，休闲对弈品类用户 | 等车、睡前 | 60% |
| 社交 | 朋友开黑、宿舍/办公室约战 | 面对面或微信分享链接 | 长尾，但**拉新主力** |

### 1.4 三条设计红线（继承 spec §18.1，产品级重申）

1. **推理不能变成运气**——任何道具、数值都不允许直接增加命中率。
2. **胜负不能直接买**——金币只买门票与外观，绝不买信息、买伤害。
3. **金币不在玩家间流动**——门票归系统、奖励固定（合规边界，spec §18.4）。

这三条同时是**营销话术**："这是一个纯脑子的游戏"——在休闲对弈品类里是稀缺卖点。

## 二、玩法体系

### 2.1 玩法栈（自下而上，每层依赖下一层）

```
L4 社交层   好友约战 · 战队 · 观战 · 战报分享        ← 拉新与留存
L3 成长层   段位 · 赛季 · 任务 · 收藏               ← 长线目标
L2 玩法层   排位 2人 · 休闲 2人 · 混战 3-4人 · 自定义房 ← 核心对局
L1 核心     10×10 单机 回合射击（引擎 DuelEngine）    ← 一切的地基，已完成
```

现状：L1 已完成且经过整枝评审；L2 的自定义房/混战/人机在 P1–P2 里已基本落地；
L3、L4 是本蓝图新增的主体设计。

### 2.2 对局类型矩阵

| 类型 | 段位分 | 金币 | 机器人补位 | 入口 | 目的 |
|---|---|---|---|---|---|
| **排位** 2人 | ✅ | — | 等待 30s 后补位，补位局**不计分**（已定） | 首页主按钮 | 长线留存 |
| **休闲** 2人 | — | — | 快速补位 | 专区 | 新手/老人随意玩 |
| **混战** 3–4人 | ✅（赛季初开放） | — | ✅ | 专区 | 社交传播 |
| **练习** | — | — | 全机器人 | 专区/单机 | 教学、断网可玩 |
| **好友房** | — | — | 房主可加 | 分享链接/房间号 | 拉新钩子 |
| **自定义房**（公开列表） | — | — | 房主决定 | 专区→房间列表 | UGC 规则生态 |
| 挑战赛（P4+） | 活动分 | ✅ | ✅ | 限时活动入口 | 营收与回流 |

**关键原则**：排位是唯一计入段位的常规玩法；一切"补位局不计分"的设计都已确定，
机器人永远不冒充真人计分——这是信誉资产。

### 2.3 深度阶梯（段位驱动的解锁）

| 段位 | 解锁 | 设计意图 |
|---|---|---|
| 新兵 | 入门/标准档、练习、好友房 | 5 分钟看懂全部玩法 |
| 少尉 | 进阶档（12×12 双机） | 引入多机推理 |
| 上校 | 高手档（14×14 三机）、混战排位 | 高手内容与社交场 |
| 元帅 | 赛季限定棋盘皮肤、自定义房"赛事模式" | 身份象征 |

解锁**只放开内容、不给数值**——高段位没有更强飞机，只有更难对手。

### 2.4 段位与赛季

**7 级段位，每级 5 星，星制 + 隐藏分（MMR）双轨**：

```
新兵 → 少尉 → 上尉 → 少校 → 上校 → 准将 → 元帅
（新兵/少尉各 3 星起步，其余 5 星；元帅用分数排名，无上限）
```

- **胜 +1 星 / 负 −1 星**（晋级局、保星局规则同主流 MOBA 简化版：晋级局失败不降级、连败 3 场触发保星）。
- **MMR 匹配**：星数显示给玩家，匹配按 MMR，杜绝代练/演员的可见伤害。
- **赛季 4 周**：结束按段位发赛季宝箱（头像框、棋盘皮肤、金币），元帅档前 1000 名上名人堂页。
- **掉段保护**：新赛季从上一季段位降 1 级起步。
- **双人组队排位**（P3 后期）：好友组队各按自己 MMR 匹配，队伍平均 MMR 进池。组队排位是斗地主/和平精英验证过的最强留存手段，但要求账号系统先稳。

### 2.5 机器人的产品角色（三种，严格区分）

| 角色 | 何时出现 | 界面表现 | 计分段位 |
|---|---|---|---|
| 练习教练 | 练习模式 | 明确"电脑·难度X"徽章 | 否 |
| 补位队友 | 排队超 30s | 头像有"电脑"角标，结算不计分 | 否 |
| 活动 NPC | 挑战赛剧本（如"突破封锁线"闯关） | 有名字的固定对手 | 活动分 |

**永不**：机器人在排位里冒充真人（已定）。技术上靠 `bot/` 模块与真人协议隔离，已实现。

## 三、成长与经济

### 3.1 双货币（spec §18.4 已定，这里补界面口径）

| | 声望（积分） | 金币 |
|---|---|---|
| 来源 | 对局胜负、任务 | 每日签到、看广告、赛季宝箱、购买 |
| 用途 | 段位、排行榜 | 门票（金币场）、皮肤、表情 |
| 通胀控制 | 赛季重置 | 门票是主要回收口 |

### 3.2 外观线（版号前唯一安全的付费方向 → 版号后主力）

- **棋盘皮肤**（纸笔风/军用电台风/霓虹风）——纸笔手绘风做首发免费款，怀旧本身就是卖点。
- **命中特效**：墨点 / 火花 / 像素爆炸。
- **头像框、结算称号**（"读心者""三局封喉"）。
- 全部**无数值影响**，且全部可肝可得（付费只是快一点）——守住红线 2。

### 3.3 变现点排期（合规优先级）

| 期 | 变现 | 依赖 |
|---|---|---|
| M1 | 激励视频：金币场门票补给、结算翻倍、赛季宝箱+1 | 仅广告 SDK，**无需版号，最先做** |
| M2 | 金币场门票（门票归系统，固定奖励） | 金币经济 |
| M3 | 外观直购 / 赛季通行证 | 版号 |
| M4 | 广告移除内购（一次性买断） | 版号 |

### 4.3 关键页规格

**首页【开始】**
- 上半屏：一个超大主按钮（快速开始，记住上次档位）+ 当前段位卡。
- 下半屏：横向滑动卡片——好友约战 / 公开房间 / 练习 / 活动。
- 不放轮播广告位。首屏信息密度对标"微信小游戏入口"，不做大鱼吃鱼那种堆料。

**匹配进度页**（新）
- 显示已等秒数、当前档位人数；15s 后浮现"将为你补入电脑队友（不计分）"——透明度换信任。
- 等待中可随时取消；匹配成功→ 强震动 + 进入摆放。

**对局页**（现有 DuelPlay/MeleePlay 的增强清单）
- 14×14 触控：高手档改"点选→确认开炮"两段式 + 双指缩放（spec §18.3 已定，落码在 P4）。
- 推理提示（提示允许的档位）：候选机头高亮从功能按钮升级为**长按格子查看该格嫌疑度**的探索式交互。
- 对手思考态：3 个拟人化状态点（"正在想"→"犹豫"→"下决定"），成本极低、缓解等待焦虑。
- 关键数据埋点：每发命中/落点都进战报流（回放和分享卡的数据源）。

**结算页**（重做，现在只是 ResultSheet 弹层）
- 全屏：胜负大字 → 双方棋盘并排回放 3 秒 → 段位星数动画 → 金币/经验条 → 按钮组
  「再来一局」「查看战报」「分享」。
- 失败方给"差一点"数据钩子：`你离锁定机头还差 2 发` ——留存靠"差一点"，不靠惩罚。

**分享裂变闭环**（拉新核心路径）
- 好友房 → 一键生成微信小程序卡片/口令 → 点开直接进桌（免注册游客身份）。
- 战报分享：胜负方棋盘 + "第 11 发锁定机头"高光时刻，竖版海报图。

### 4.4 设计语言（Design Tokens）

astryx 是 React 生态，Vue 客户端用不了它的组件，但可以照搬它的方法论：
**先定 token，再谈组件**。新建 `apps/client/src/theme/`：

```css
/* theme/tokens.css —— 值为首版，UI 稿阶段可调 */
:root {
  /* 色板：军绿纸面基调，胜负色只出现在结算 */
  --pd-paper: #f6f1e7;      /* 纸面底（休闲模式默认=纸笔皮肤） */
  --pd-ink: #2c3540;        /* 墨色文字/网格线 */
  --pd-primary: #2f7d5d;    /* 主行动绿 */
  --pd-danger: #c0453a;     /* 命中 */
  --pd-hit: #d97b2f;        /* 部分命中 */
  --pd-gold: #c9a227;       /* 金币/段位 */
  --pd-seat-1..4: 现有 SEAT_COLORS 迁入;
  /* 间距 4 基线；圆角；字号 12/14/16/20/28；动效 120/240/400ms */
}
```

原则：**纸笔质感是品牌**——默认棋盘就是方格纸+手写墨点，命中=墨渍溅开。
差异化不是画得多好，而是"一眼认出是那个纸上的游戏"。深色军用电台风作为第二皮肤。

**无障碍**：命中/未中除颜色外必须有形状差异（●/×），色觉障碍可用；所有触控目标 ≥44px（14×14 棋盘用两段式点选满足）。

## 五、技术架构（目标态）

### 5.1 现状 → 目标 对照

| 面 | 现状（P2 分支） | 目标 | 何时迁 |
|---|---|---|---|
| 会话 | 内存 Map，重启即失 | Redis（桌状态 + 玩家归属） | P3 账号上线时 |
| 持久层 | 无 | Postgres（账号/战绩/金币/皮肤） | P3 |
| 进程 | 单进程 ws | 无状态网关 ×N + 桌分片 | 并发 >3k 桌前不迁（§18 决策不变） |
| 匹配 | 内存队列 | 移入 Redis ZSET（MMR 排序） | P3 |
| 协议 | v3 | v4（登录/段位/战报字段，向后兼容） | P3 |
| 部署 | 文档就绪未落地 | 国内可备案的云 + wss | **本周即可做** |

**架构总图（目标态）**：

```
客户端(Vue3+Capacitor/uni-app 皮) ──wss──> 网关层(鉴权/限流/心跳, 无状态)
                                            │ 按 tableId 路由
                                            ▼
                              对局服 ×N(现 Hub/Table/Engine, 无状态化)
                              │写              │读
                              ▼                ▼
                        Redis(热: 桌/队列/会话)  Postgres(冷: 账号/战绩/经济)
                              │ 局末事件流
                              ▼
                        战绩/经济服务(消费对局事件, 单写者)
```

要点：
1. **引擎不动**。DuelEngine/MeleeEngine 是纯内存权威逻辑，这是最大的架构资产，
   横向扩展靠"一张桌只属于一个对局进程"（tableId→进程 归属表在 Redis），
   不需要引擎支持分布式。
2. **对局与账号解耦**：战绩以事件流落库，对局服永不直写 Postgres——
   账号侧改表不碰对局稳定性。
3. 微信小游戏终态（uni-app 迁移）只换壳不动引擎层，shared 包继续全复用。

### 5.2 客户端架构补强

- 现有 `net/store.ts` 单 store → 按域拆分 `stores/{session,table,game,meta}.ts`（Pinia），页面增多后防止上帝对象。
- 新增 `assets/` 皮肤系统：棋盘渲染已是 DOM（spec §八 决策正确，皮肤=换 CSS 变量+背景图，架构天然支持）。
- 断网单机练习：练习桌逻辑本就在 shared+server 层可跑，加一个 `LocalRoom`（引擎在客户端内存跑同一套）即可离线——这是"地铁上也能玩"的差异化功能，P4 评估。

### 5.3 安全与公平（上线前清单）

- 现有关键设计保留：服务端权威、token 身份、消息限长、心跳踢僵死。
- 补：每连接限频（fire >2 次/秒即丢弃）、协议字段全走 shared 校验（已做）、
  防重放（座位世代号）、服务端对局结果签名（分享卡防伪）。
- 反作弊定性：本作作弊收益=看自己棋盘，作弊动机天然弱；最大风险是**演员刷分**，
  靠 MMR 隐藏分 + 新号窗口期匹配新号化解。
