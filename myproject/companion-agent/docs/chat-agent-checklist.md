## 14. 独立评审（第 1 轮，2026-11-09）

由一个不带作者上下文的评审对照文档与源码执行，报告 20 项。作者逐项核对了关键结论（B1、M10、m14、m15、m20 与 uvicorn 停机顺序），全部属实，处理如下：

| # | 级别 | 问题 | 处理 | 位置 |
|---|---|---|---|---|
| B1 | 阻断 | 登录键正则拒绝所有真实 token（Java 是标准 Base64，含 `+/=`） | 正则改为 Base64 字母表 | D §4 |
| B2 | 阻断 | steer、取消、首 token 状态只在单进程内有效 | 新增 Redis 回合控制面：锁、回合状态、控制流、正文缓冲；判定与投递用 Lua 原子执行 | D §6.2；A §5.1–5.2 |
| B3 | 阻断 | 「运行中但未吐字」时合并无法实现 | 合并改为中止并用同一 turn_id 重跑；不加等待；工具执行后或重跑 2 次后不再合并 | D §6.3 |
| M4 | 重要 | 空闲会话没有 disposition | 新增 `started` | D §6.1；C §2.1、§3.2 |
| M5 | 重要 | 没被注入的 steer 会丢 | 回合结束时转回队列并发 `input.queued` | D §6.4；C §3.2 |
| M6 | 重要 | 事件名与字段跨文档不一致；缺取消事件；多端看不到合并/插话的消息 | D §7.2 定为唯一权威事件表；新增 `message.created`、`turn.cancelled` 等；A、C 对齐 | D §7.2 |
| M7 | 重要 | `interrupted` 与 `turn_interrupted` 不一致；「继续」没有接口 | 统一为 `turn_interrupted`；新增 continue 接口 | O §2.3、§6.2；D §6.7 |
| M8 | 重要 | 回合进行中打开会话只收到半截增量 | 首连发 `turn.snapshot` | D §7.3；A §5.4 |
| M9 | 重要 | 事件缓冲比一个长回答还小 | 增量合并后写入（50ms / 64 字符）；正文另存 `turn:{tid}:text` | D §7.3 |
| M10 | 重要 | 工厂强制加入 `ask_clarification` | `ToolVisibilityMiddleware` 过滤掉；context 用 Mapping 并设 autonomous 兜底 | P §2.2 |
| M11 | 重要 | 中间件位置跨文档矛盾；插话文本绕过 safety | 两套链统一定义；safety 移到提交时对每条输入执行 | A §2.2；T §1 |
| M12 | 重要 | 跨应用记忆隔离靠自觉 | 每个应用一个只能访问自己 collection 的 Qdrant 令牌；验收用越权读取测试 | D §10.7 |
| M13 | 重要 | 注销需要改 Java，且 Java 访问不到内部接口 | App 发起 `DELETE /me` + 每日对账（只读 Java 用户表） | O §3 |
| m14 | 次要 | 同步钩子在 `astream` 下抛错 | 图内中间件只实现异步钩子 | P §2.4；T §1 |
| m15 | 次要 | `PromptMiddleware` 无锚点会落到最内层 | 全部显式锚点，装配时断言顺序 | P §2.4 |
| m16 | 次要 | 缺 `action` 消息类型；历史窗口单位不适用合并回合 | 已加 `kind='action'`；窗口按回合分组 | D §3.3；P §6.6 |
| m17 | 次要 | 排空失败无限重试 | 3 次后置 `failed`，用户手动重试 | D §6.5、§3.3 |
| m18 | 次要 | 客户端用 `regenerate()` 重试没有回复的失败回合 | 新增按回合重试接口 | D §6.7；C §4.2 |
| m19 | 次要 | 记忆作用域自相矛盾；路由与客户端不一致 | `agent_id` 不参与召回；`kinds` 过滤的取舍写明；路由以 D §7.1 为准 | D §10.5、§10.7 |
| m20 | 次要 | 人设体积与预算不一致；vision 开关无效；残留旧客户端引用；`persona_guard` 代码按 CJK 检查输入 | 体积与预算对齐；图片走多模态内容块；引用更正；代码问题列入迁移表 | P §4.5、§6.1、§2.6；A §4.3 |
| 补充 | 重要 | 评审标为「未核实」：uvicorn 停机会等 SSE 长连 | **已核实属实**，且 lifespan 关闭钩子排在等待之后、永远不会执行。改为独立进程 + 接管退出信号 | P §3.1、§3.5 |

**结论**：文档层面的 20 项全部处理。仍然只能靠代码关闭的是第 13 节的三项实测。
