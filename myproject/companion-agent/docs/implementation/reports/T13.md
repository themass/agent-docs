## 本轮修复的问题（全量测试暴露的）

1. **迁移时丢失的导入**：`adapters/delivery/memory.py`（`DeliveryReceipt`、`DeliveryError`）、`app/proactive/router.py`（`DeliveryPort`、`SendRecorder`、`logger`）、`adapters/mcp/livekit_toolsets.py`（`McpRegistry`）、`api/livekit/sessions_router.py`（`SessionService`、`SessionError`）。
2. **角色目录路径错位**：`bootstrap/container.py` 的 `PROJECT_ROOT` 少算一层（`parents[2]` → `parents[3]`），导致角色卡找不到，主动消息与对话测试失败。
3. **会话路由 422**：`api/livekit/sessions_router.py` 残留 `from __future__ import annotations`，FastAPI 无法解析函数内定义的请求模型，请求体被当成查询参数。已删除该导入。
4. **旧的 `test_brain.py`**：按 T4 之前的客户端接口编写，无法导入。已按 LangGraph 的 `astream(stream_mode="messages")` 形状重写（8 个用例）。
5. **迁移环境**：`migrations/env.py` 用同步引擎执行迁移，但连接串是 `+aiomysql`。现在迁移时换成 `+pymysql`。
6. **依赖声明**：`pyproject.toml` 补上 `boto3`、`aiomysql`、`pymysql`。

## 实际发现并修正的设计问题

- **TOS 预签名地址**：botocore 对自定义 endpoint 即使设置了 `virtual` 寻址，预签名 URL 仍是路径风格（`https://tos-s3-cn-beijing.volces.com/{bucket}/{key}`）。job-come 使用同一套配置（`libs/agentkit/storage/object_store.py`）。**这一点只能在线上 TOS 上验证**，若 TOS 拒绝路径风格，需要改成 `{bucket}.{host}` 形式的 endpoint。
- **MariaDB 与 MySQL 8 的差异**：本机预检用的是 MariaDB 13，只能验证 SQL 与迁移的基本正确性。`FOR UPDATE SKIP LOCKED` 的并发认领，必须在线上 MySQL 8 上确认。

## 线上结果（2026-11-09，MySQL 5.6.40 + 共用 Redis）

环境：`vpn` 库（与 Java 后端共用），表名统一 `ca_` 前缀（迁移版本表 `ca_alembic_version`）；Redis 与 job-come 共用，键统一 `ca:` 前缀；TOS 桶复用 `sspacee`，测试前缀 `companion-test/`。

- 全量：**397 通过**，0 失败。
- 实测建表（5.6.40-log）：`alembic upgrade head` 建出 12 张 `ca_` 表（含版本表）；`ca_` 表中 JSON 列 0 个（`meta`/`payload` 等为 `MEDIUMTEXT`，应用层编解码）；未使用 `SKIP LOCKED`、`JSON_OBJECT` 等 5.7+ 语法。
- 非 `ca_` 表数量：迁移前后均为 119，未改动 Java 与其它应用的表。

线上测试中修正的问题：
1. **MySQL 5.6 DATETIME 四舍五入**：`run_after` 写入 `02:46:20.997` 会变成 `02:46:21`，刚到期的任务暂时不可认领。写入与比较两侧都截到整秒。
2. **首 token 前的合并竞态**：Lua 判定为合并时，后台协程可能还没读到控制消息，首 token 已产出，合并会被丢掉。运行器改为在输出开始前和第一个工具调用前同步读取控制流；撤销阶段时退回 pre_output。新增回归测试。
3. **测试时序依赖**：合并测试原先靠 sleep 0.3 秒等待，改为事件门控。
4. **任务认领测试的去重键**：改为每次运行唯一的键，避免残留数据干扰。
