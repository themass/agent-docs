# T11 报告：解题与上传

日期：2026-11-09。依据：D §9、O §5、P §5.5。

## 做了什么

1. **解题 skill** `skills/public/problem-solving/SKILL.md`：读题 → 分析 → 推理 → 校验 → 答案；题目什么语言就用什么语言；`steerable: false`（解题中途不接受插话，只排队，D §9）；`model_scenario: solve_text`，有图片时 `solve_vision`。
2. **上传策略** `domain/uploads/policy.py`（纯逻辑）：按文件头判类型（JPEG、PNG、WebP、HEIC），不信扩展名与 Content-Type；单张 ≤ 8 MB；像素上限；长边缩到 2048；JPEG 质量 85。
3. **图片处理** `adapters/storage/images.py`（Pillow）：解码 → 按方向转正 → 缩放 → 重新编码为 JPEG，并清空元数据（EXIF 包括 GPS 被去除，已验证）。解码失败统一为用户可见的拒绝，不泄露库内部信息。
4. **对象存储端口** `ports/objects.py`；内存实现（开发用）；OSS 适配只声明接口，**明确失败**，不假装上传成功。
5. **上传服务** `app/uploads/service.py`：校验 → 处理 → 存私有桶（key 为 `uploads/{owner}/{ulid}.jpg`）→ 记录。读取只给签名 URL（5 分钟），别人的 id 返回 404。
6. **存储**：`UploadStore` 端口与 `MysqlUploadStore`。
7. **接口** `api/http/routers/uploads.py`：`POST /uploads`（原始字节，201；拒绝 422）、`GET /uploads/{id}`（签名 URL）。

## 验证（本任务范围内）

- 类型判断：PNG 识别正确；仅靠扩展名或伪造头部的内容被拒绝。
- EXIF：带 GPS 的 PNG 处理后输出为 JPEG，EXIF 为空；大图按长边 2048 缩放。
- 拒绝：HTML 文本、空文件、伪造 PNG 头 → 422（或服务层的 UploadRejected）。
- HTTP：上传 201；本人读取 200；他人读取 404；HTML 上传 422。
