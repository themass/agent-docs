# T10 报告：后台任务进程

日期：2026-11-09。依据：O §1、§2、§3。

## 做了什么

1. **纯规则** `domain/jobs/policy.py`：重试退避 1、4、16、64 分钟（O §2.1 的 1、4、16 再延伸一步）；尝试次数用尽置 `dead`；租约 5 分钟，每 60 秒续租；租约过期的 `running` 任务视为崩溃，由下一轮认领重新拿走。
2. **端口** `ports/jobs.py`：`JobStore`（入队、认领、续租、完成、失败）。
3. **MySQL 实现** `adapters/store/mysql/jobs.py`：认领用 `SELECT … FOR UPDATE SKIP LOCKED`，同一事务里置为 running；`dedupe_key` 唯一约束防止重复入队。
4. **执行循环** `app/jobs/worker.py`：执行中续租；续租失败则放弃结果；处理函数异常只记录异常类型（不记录异常文本，避免泄露用户内容）；未注册的 kind 直接 dead。
5. **已接线的任务** `app/jobs/handlers.py`：
   - `confirmation.expire`：过期的待确认置 `expired`（条件更新）。
   - `audit.trim`：工具审计超过 90 天删除。
6. **进程入口** `companion/worker_jobs.py`：`python -m companion.worker_jobs`，需要 `COMPANION_MYSQL_URL`。
7. **存储补充**：`ConfirmationStore.expire_due`、`ToolCallStore.trim_before`（端口与 MySQL 实现）。

## 验证（本任务范围内）

- 退避序列与死信：第 1–4 次失败分别排期到 1、4、16、64 分钟后；第 5 次（上限）置 dead。
- 执行循环（内存认领）：成功 → done；处理函数失败 → 退避排期，错误记录为异常类型；未知 kind → dead。
- 两个已接线任务的参数（截止时间）正确。
- `lint-imports`：7 KEPT。
- **未验证**：MySQL 上的 `SKIP LOCKED` 认领与租约回收（需要真实 MySQL，留到 T13）。
