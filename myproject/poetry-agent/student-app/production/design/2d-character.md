# 2D 数字人方案(诗人角色)

- 日期:2026-11-06;状态:方案稿,供用户决策。
- 范围:「见」这一步里学生看到的诗人(杜甫等)的 2D 形象与动作。不含 3D、不含视频生成。
- 约束(已定):不做 GPU 生产;口型不必匹配;文字永远是降级终点;所有人物形象都是演绎,必须带「演绎」标识。
- **核实状态**:凡标「待用户核实」的条款、价格、授权,我没有查证,不能当作已确认。成本数字全部是估算,须以实际报价替换。

## 1. 先说结论

1. **现在**:用代码生成的分层 SVG 占位角色(已完成,`published/characters/du-fu/`),先让学生端把状态切换、说话动作、降级链跑通。
2. **下一步(不需要外包)**:在同一份 `character.schema.json` 下,把占位角色升级为「简易分层动画」:换一套有风格的美术(用户或美术提供),动作仍由 manifest 的 tracks 描述。这一步不引入新运行库。
3. **有预算再做**:外包 Live2D 或 Spine 角色包。只替换 manifest 的 `renderer` 与 `entry`,前端的状态机、降级、字幕、气泡都不改。
4. 无论哪一步,**口型不要求对齐**(第 3 节),所以不需要口型驱动的流水线,这是省钱的最大一项。

## 2. 方案对比

| 方案 | 表现力 | 制作门槛 | 包体(估) | 运行时依赖 | 许可与成本 | 适合阶段 |
|---|---|---|---|---|---|---|
| **CSS/SVG 分层(当前)** | 低到中:呼吸、点头、眨眼、低头、行礼,可做手绘质感 | 低:会画矢量图即可,动作写在 JSON | 小:占位 21 KB;手绘版估 100–400 KB | 无,浏览器原生 | 无运行库许可问题;美术版权自己管 | 现在,到上线都够用 |
| **序列帧(PNG/WebP)** | 中到高:任意手绘动画,表现力取决于画师 | 中:每个状态要画多帧,换装要重画 | 大:每状态几十帧,估 1–4 MB/角色,容易超 5 MB 预算 | 无 | 无库许可;画工成本高 | 只适合少量关键动作(如行礼) |
| **Lottie(AE 导出)** | 中到高:矢量动画,可交互状态切换有限 | 中:需要 After Effects + Bodymovin;状态机要自己拼 | 小到中:估 50–500 KB | lottie-web(MIT,**待核实**当前版本许可) | 工具链成本在 AE 订阅 | 想要流畅的矢量动画又不想上 Live2D |
| **Spine(2D 骨骼)** | 高:网格变形、换装、混合动画 | 中到高:需要 Spine 编辑器与动画师 | 小:估 0.3–1.5 MB | spine-webgl/pixi-spine 运行库 | **Spine 编辑器与运行库的商用授权条款与价格:待用户核实**(架构文档已列为备选) | 有预算、想要细腻表演 |
| **Live2D Cubism** | 高:面部网格变形、眼神、气息,二次元风格成熟 | 高:建模(分层 PSD → 网格 → 参数)专业性强 | 中:估 1–5 MB(含贴图),前端策略预算 ≤ 5 MB | Cubism SDK for Web + pixi-live2d-display | **商用许可条款(发布物标注、月活/营收阈值、是否需要签约)待用户核实**,见 `2026-11-06-qijing-architecture.md` 待办 A-0 | 外包的主选 |
| 3D(Three.js 人物) | 看实现 | 高 | 中 | Three.js | 无库问题 | **否决**:架构文档已定,近景人物质量下限低 |

说明:

- 表中「包体」「制作门槛」是我基于通常做法的**估计**,不是实测。
- Live2D 与 Spine 的许可我**没有核实**。在用户确认之前,任何外包合同和上线计划都不应假设它们的商用条款。
- 水墨风格与 Live2D(偏二次元网格变形)并不天然匹配,可能需要美术方给出「水墨质感的分层图」样稿再判断。这一点也待用户与美术确认。

## 3. 为什么口型不必匹配

1. **读诗学习,不是配音动画**。学生要听清、看懂文字,注意力应该在字幕与诗句上;嘴型精确对齐不增加理解。
2. **口型对齐成本高、风险高**。viseme 驱动需要音素对齐、口型表、外包建模的口型参数,任何一个环节出错都显得廉价(架构文档风险清单已提到「实时水墨人物质量下限」)。
3. **古人像本无依据**。我们没有可靠的诗人画像,形象本就是演绎。不去追求「像在说话」的拟真,反而更诚实。
4. **降级友好**。口型依赖音频;音频缺失时嘴不该乱动。只做「说话中」的泛化动作,音频没了也可以退回 idle。

### 口型之外的替代表现

| 表现 | 作用 | 当前状态 |
|---|---|---|
| 呼吸 | 让人物「活着」,零成本 | 已做(idle/talk 的 body.scaleY) |
| 头部起伏 / 点头 | 说话时的节奏感 | 已做(talk) |
| 眨眼 | 避免僵硬 | 已做(`ambient.blink`) |
| 低头、眉心上扬 | 表达忧伤 | 已做(sorrow) |
| 行礼 | 登场与告别的仪式感 | 已做(bow) |
| 嘴部开合(振幅驱动) | 有音频时轻微开合,不追求对齐 | 已做(`mouth_mode: amplitude`) |
| 手势(抬手、拈须) | 强调与停顿 | 未做;外包版可加 |
| 字幕逐字高亮 | 把注意力引到诗句,同时说明「谁在说」 | 前端任务(B),需要字幕时间轴 |
| 对话气泡 + 『演绎』角标 | 明示台词是演绎 | 前端任务(B);锚点 `speech_bubble` 已给 |

## 5. 与代码的接口(B 已经能消费)

- manifest 格式:`contracts/character.schema.json`。
- 状态名约定:`idle` `talk` `listen` `sorrow` `bow`;每个状态有 `fallback_state`,所有链最终到 `idle`。
- 降级:`degrade.still`(静帧)→ `degrade.text_alt`(文字)。减少动效时只显示 `reduced_motion_state` 的第 0 帧。
- 口型:`mouth_mode: none | amplitude | viseme`。外包 Live2D 通常自带口型参数,但本期不依赖。
- 非 svg-layers 的渲染器用 `entry` 指向外包交付物,状态的 `motion` 给出动作名。

## 8. 验收清单

**机检(`tools/character-check.mjs`,已实现)**

- [ ] manifest 通过 `character.schema.json`
- [ ] 所有图层/帧/entry 文件存在;svg 图层 viewBox 等于画布;SVG 不含脚本和外部引用
- [ ] 必须含 idle;每个状态的 `then`/`fallback_state` 存在,fallback 链到 idle
- [ ] 轨道引用的图层存在;关键帧时间递增;循环状态首尾值一致(否则警告)
- [ ] `mouth_mode=amplitude` 时 mouth 配置存在
- [ ] 总字节 ≤ `budget.max_bytes`
- [ ] 占位角色必须 `not_for_release=true`;代码生成的角色必须标占位

**人工**

- [ ] 5 个状态都能播放,状态切换无跳变
- [ ] 说话动作自然,不诡异;不要求口型对齐
- [ ] 形象带『演绎』标识,没有无依据的服饰/器物细节
- [ ] 与角色 bible 一致,同一角色各状态是同一个形象
- [ ] 静帧与动画是同一形象,背景透明
- [ ] `manifest.rights` 写明来源、作者、第三方运行库及许可
- [ ] 真机(iPad Safari、中端安卓)播放流畅;掉帧时能按 `fallback_state` 降级(**这一项我没有做过,需要真机**)
- [ ] 减少动效模式下只显示静态帧
- [ ] 关闭角色后,文字和字幕仍可完整走完「见」
