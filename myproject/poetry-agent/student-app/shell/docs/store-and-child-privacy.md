# 商店与儿童隐私清单(待用户与法务确认)

**本文件不声称任何合规。** 它只列要点、已经做到的技术约束、以及必须由用户或法务提供或确认的东西。上架前每一条都要有结论。

## 1. 产品事实(决定合规判断的输入)

- 面向中小学生;学生端不做付费(待用户确认);**无广告、无第三方分析/崩溃/广告 SDK**(当前依赖里没有)。
- 学生标识:可重置的匿名设备 id;不收集姓名、学校、位置、通讯录。
- 录音:v1 未接通;接通后仅本地,不上传。
- 学习事件(文字、进度)会上传到自家后端(`/api/student/v1`),家长同意之后才上报(前端 `consent` 机制)。**这一点必须在隐私政策与数据安全表里写清。**

## 4. 中国大陆未成年人个人信息保护要点

需法务逐条确认,这里只列方向:

- 未满 14 周岁的个人信息属于敏感个人信息,处理前需取得监护人**单独同意**(《个人信息保护法》与《儿童个人信息网络保护规定》方向)。
- 监护人同意页面要说明:收集什么、为什么、保存多久、如何查阅/更正/删除、如何撤回同意。
- 默认最小化:不收集的不收集;匿名设备 id 可重置。
- 录音与学习画像:本地优先;上传需要显式监护人同意;可一键删除。
- 没有广告、没有向第三方提供数据。如果将来接入第三方,需重新评估。
- 数据存储地点与跨境传输,若涉及需单独评估。

## 5. 监护人同意与家长闸的做法

**现状**:前端 `parent.js` 的算术题只挡误触,**不是安全验证**(代码注释已承认)。Web 版 `platform-web` 的 `ParentGate` 同样是 localStorage 标记。

**正式版要求(待产品决定)**:
1. 监护人同意页单独成页,记录同意时间与版本号(本地记录 + 后端记录需用户决定)。
2. 家长页的删除、撤回、导出入口需要比算术题更强的闸:建议系统生物识别(`LocalAuthentication` / `BiometricPrompt`)或家长账号密码,由用户决定。
3. 删除入口必须清空:本地安全存储(`secureRemove`)、IndexedDB 资产、录音文件、后端匿名设备记录(需后端接口,见 `docs/handoff/B-needs-from-java.md`)。

## 6. 必须由用户/法务提供或决定的清单

1. 应用正式名称、appId(`org.xuexi.shicishikong` 目前是**占位**,提交商店后不可改)与开发者账号。
2. 隐私政策 URL 与正文(中英文)。
3. 监护人同意文本、撤回与删除流程的书面说明。
4. 是否申请 Apple Kids Category 与 Google Designed for Families。
5. 是否收费;付费方式(影响 Apple 的 IAP 要求)。
6. 生产 API 域名(https),替换 `STUDENT_API_BASE`。
7. 录音功能的上线时间与是否开放上传的产品决定。
8. Live2D Cubism 与 Spine 的商用许可核实(战略文档 §6)。
9. 签名证书与 Keystore(**不进仓库**)。
