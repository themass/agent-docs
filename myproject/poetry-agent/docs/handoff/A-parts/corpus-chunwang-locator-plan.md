**已知风险，必须由人决定：**
- 四份语料都是**繁体「國」**。学生端 text version 若用简体「国」，逐字核对会失败。是否在 text version 上采用繁体、或登记一条简繁对照，是用户的决定；检索层**不做自动繁简归一**（那会改变被核对的文字）。

## 3. 结构化定位符（需用户确认后才能写入 `locator`）

当前 `poetry_citation.locator` 是自由文本（`VARCHAR(300)`）。建议的结构化格式，存为紧凑 JSON 字符串：

```json
{"v":1,"corpus_id":"qts-tangshi300","file_path":"全唐诗/唐诗三百首.json","file_sha256":"d77a…7c7","line":3866,"char_start":12,"char_end":17,"span_sha256":"<span 的 UTF-8 字节 SHA-256>"}
```

- `char_start` / `char_end`：**Unicode 码位**偏移，半开区间 `[start, end)`，从行首计 0。
- `span_sha256`：对该区间文本的 UTF-8 字节求 SHA-256。核对时重算，不一致即拒绝。
- `file_sha256`：与 `poetry_corpus.file_sha256` 一致才可用；语料文件变化后，旧定位符需要人重新确认（§7.4(6)）。
- 示例中的 `corpus_id`、`char_start` / `char_end` 与 `span_sha256` 都是占位，**不是**已登记或已算出的值。

## 4. 检索脚本（待建，计划如下）

输入：登记表导出（JSON，由人从 `poetry_corpus` 导出，**工具本身不连库**）+ 查询串列表。

1. 对每个登记的 `corpus_id`，重算文件 SHA-256；与登记值不一致 → **拒绝该文件**，并报告，不静默跳过。
2. 逐行读取（UTF-8），对每个查询串（精确子串，不做繁简、标点归一）做全部出现位置的查找。
3. 对每次命中，输出一行 JSON：`{corpus_id, locator, text, span_sha256}`。`text` 截断到 300 字以内。
4. 繁简分开查：「国破」与「國破」各查一次，输出里写明命中的是哪一种字形。
5. **不排序、不打分、不输出结论字段**。命中多条全部列出。
6. 输出只写到指定的 stdout 或文件；没有任何数据库写入。

## 5. 核对步骤（由人执行，本次未执行）

- 用 `grep -n` 复现第 2 节的行号，确认与脚本输出一致。
- 对每条候选，用行号与码位偏移取切片，与 `text` 逐字比较，并重算 `span_sha256`。
