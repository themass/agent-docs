## 4. 偏差与决定记录

1. **`poetry_studio_check_log.source_id` 允许 NULL**(契约隐含非空):逐项评审没有来源。
2. **`item_index` 为 `changes` 数组的 0 起始下标**(契约未说明)。
3. **读路由令牌错/未配置 → 403**,与既有 `PoetryAgentOrchestrationController` 一致;写路由按契约 503/401。
4. **studio 令牌与 agent 令牌相同 → 写路由 503**(否则 agent 链路能写来源)。
5. **署名**:`ai` 不做子串匹配,规则见 `docs/studio-governance-api.md`;额外加了中文机器身份词(智能体/机器人/人工智能/大模型/系统/助手)和 `PublicationGate` 的 DEMO 前缀等规则。已知误伤:`Reagent`、小写 `li-ai`;已知漏判:`Ai Claude`。
6. **locator 占位口径**对齐审计 SQL 的 C5(`待%`、含 待核查/待人工/未核对/DEMO/演练),再加 TBD、`n/a/无/暂无/略`、纯标点。比契约清单严格,防止"接口接受、发布前核查又拦下"。
7. **请求体未知字段一律 400**(`BODY_INVALID`);令牌校验先于体解析;体按字符串读取,不回显原文。
8. **`limit`/`offset` 越界返回 400,不静默截断**(与既有 PoetryController 一致)。`limit` 范围 1–200,默认 50。
9. **studio-view 的 claims/citations/sources 是 snapshot 的超集**:作品范围 = 作品本身 + 其背景(背景 claim 的 subject 是背景 id)。`claims_checkable.checkable` = 至少有一条 locator 为 SET 的 claim 数(与来源是否核验无关)。
10. **逐项评审**:PUT 对每个 index 做 upsert(不删除未提及的 index),三个角色都可写;提案行加锁(`FOR UPDATE`)与整体评审串行。全部可执行项被跳过时 apply 仍成功(`applied_operations` 为空);`NOTHING_TO_APPLY` 的 409 留给 BFF(契约 §7.2)。
11. **VERIFY/REJECT 幂等**:已是目标状态返回 200 + `changed=false`,不重复写日志。被阻断的尝试(409)不写 check_log(没有发生写入)。
12. **来源列表主键名为 `id`**(与 snapshot 的 source 一致),契约没写明是 `id` 还是 `source_id`;S2/S4 若期望 `source_id` 需统一。
