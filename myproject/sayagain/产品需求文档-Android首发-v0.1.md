## 1. 产品摘要

### 1.1 一句话

SayAgain 是一个由动漫数字人带领的 Android 英语词汇学习 App，帮助用户把单词和固定搭配从“看过”变成“能理解、能回忆、能在简单情境中选对”。

### 1.2 首发承诺

用户每天打开 App 后，不需要自己挑题或规划路线，就可以完成一轮短而完整的学习：认识新内容 → 在支持下练习 → 不看答案回忆 → 进入适量复习。

### 1.3 首发不承诺

- 不宣传为完整的听说读写课程。
- 不宣传为专业发音评分工具。
- 不承诺一次学习后永久记住。
- 不用连击、徽章或完成数量冒充英语能力。

## 2. 目标用户与待确认前提

### 2.1 当前工作假设

1. 用户以亲子家庭和小学阶段学习为主；孩子在手机上学习，家长负责首次设置、内容选择和安全控制。
2. 孩子具备基础中文阅读能力，英语处于零基础至初级阶段；学习环节以图片、动作和短语音为主。
3. 用户愿意每天学习 5–15 分钟。
4. 首发内容以英文为主，使用中文解释；内容需适配亲子陪学。
5. 首发优先验证“词汇学习闭环”，而不是同时验证全部市场和商业模式。

### 2.2 必须在 PRD 定稿前确认

- 首发年龄：成人、青少年，还是分开设计？
- 首发市场和解释语言：中文、印尼语、越南语、阿拉伯语，或先做单一语言？
- 首发学习目的：日常生活、工作、旅行、考试，还是通用基础英语？
- 家长是否需要账号、跨设备同步和家庭成员管理？
- 首发是否收费，还是先做免费内测？

在这些问题确认前，UI 可以做结构原型，但不能冻结文案、词库方向和商业页面。

## 3. 产品目标与成功标准

### 3.1 用户目标

- 用户能在第一次学习时理解目标词/搭配的核心含义。
- 用户在不显示答案时，能够尝试回忆目标表达。
- 用户能在简单情境中识别或补全固定搭配。
- 用户离开后再次进入，不丢失学习位置和必要进度。
- 用户能看见“今天要做什么”和“哪些内容需要复习”。

### 3.2 首发产品指标（待测试确定阈值）

| 指标 | 定义 | 用途 |
|---|---|---|
| 首轮完成率 | 开始一轮学习后完成该轮的用户比例 | 判断流程负担 |
| 独立回忆率 | 无答案/低提示条件下完成的目标比例 | 判断学习效果信号 |
| 次日复习完成率 | 到期内容中实际完成复习的比例 | 判断复习闭环 |
| 内容错误率 | 试学中发现的词义、音频、答案歧义问题 | 内容质量门槛 |
| 退出恢复成功率 | 退出后重新进入能恢复正确位置的比例 | 判断基础可靠性 |

不得在小样本内宣称长期记忆提升或正式等级提升。

## 4. 首发范围

### 4.1 P0 必须包含

- 首次进入与学习目标设置的最小流程。
- 今日学习入口。
- 单词内容对象。
- 固定搭配内容对象。
- 新内容引入。
- 英文→含义练习。
- 含义/情境→英文回忆练习。
- 图片→词或音频→含义练习（仅适用于素材可靠的内容）。
- 固定搭配补全或情境选择。
- 看答案、提示、答错和答对反馈。
- 当轮再次练习。
- 基础跨日复习队列。
- 学习进度和退出恢复。
- 一个数字人角色的静态/轻量动作和提示反馈。
- 本地内容包和无网时的核心学习能力。

### 4.2 P1 可以加入

- 多个主题词包。
- 词条详情和关联搭配。
- 薄弱项复习。
- 内容下载与版本更新。
- 学习统计。
- 更多数字人动作和角色皮肤。

### 4.3 明确不做

- 自由聊天。
- 完整语法课程。
- 独立阅读和写作模块。
- 云端发音评分作为必经步骤。
- 开放式陌生人社交、自由聊天、公开排行榜和实时陌生人对战。
- 复杂速度模式、押韵题、深度游戏和 Cocos 句子游戏。
- 未审校的 AI 批量题库。
- 复制百词斩的代码、题库、素材、角色和交互文案。

## 5. 内容与学习模型

### 5.1 单词对象

```text
WordItem
- id
- spelling
- pronunciation
- part_of_speech
- sense: 当前要学习的具体词义
- explanation
- example_sentence
- example_translation
- audio
- image_or_scene (optional)
- related_phrases[]
- difficulty
- content_version
```

一个词的不同词义必须分开建模；不能因为用户认识 `hand` 的“手”就认为认识所有词义。

### 5.2 固定搭配对象

```text
PhraseItem
- id
- expression
- category: collocation | phrasal_verb | idiom
- meaning
- pronunciation/audio
- scene_or_image
- primary_example
- example_translation
- example_audio
- highlighted_span
- variant_examples[]
- related_items[]
- content_version
```

固定搭配是独立学习对象。例句必须帮助理解和迁移，不只是装饰文本。

### 5.3 学习证据

每一次练习至少记录：

- 内容 ID 与内容版本；
- 题型与检验方向；
- 是否显示提示；
- 用户回答或选择；
- 判定结果；
- 是否看过答案；
- 用时（可选）；
- 是否为当日新学、当日重试或跨日复习。

浏览内容不计为独立掌握。看答案后再点“认识”必须与无提示正确分开。

## 6. 核心用户流程

### 6.1 首次进入

1. 展示产品价值：每天短时间学习并持续复习。
2. 选择解释语言和学习目标；若首发只有一个选项，则不做复杂问卷。
3. 选择或接受默认词包。
4. 进入今日学习，不强迫用户先注册。
5. 在本地建立匿名学习档案；云同步后续加入。

### 6.2 一轮新学

1. 今日页显示新学数量、复习数量和预计时长。
2. 数字人短暂引入一个目标。
3. 展示英文、声音、含义和必要情境。
4. 用户播放或重复查看，但浏览本身不记掌握。
5. 进入低提示识别题。
6. 进入主动回忆题。
7. 对固定搭配进入补全或情境选择。
8. 答对给简短反馈；答错先给最小必要提示。
9. 同一内容在本轮稍后以不同方向复现。
10. 完成后给出“已接触 / 可继续巩固 / 需要复习”的分层结果。

### 6.3 复习

- 到期内容优先于新内容，但单次积压不能无限增长。
- 同一内容的不同能力方向分开记录，但用户界面不展示复杂算法术语。
- 当日重试和跨日复习要区分。
- 复习反馈告诉用户“这次需要加强什么”，不只显示分数。

### 6.4 退出恢复

- 用户主动退出不丢失当前内容和已完成状态。
- 未提交题目恢复为未完成，不伪造答题结果。
- 音频、图片加载失败时，文本学习仍可继续。
- 断网不阻塞已下载内容的学习。

## 7. Android 产品形态与信息架构

### 7.1 导航建议

首发采用底部三栏，避免功能过多：

1. **今日**：开始学习、继续学习、复习提醒、今日进度。
2. **词库**：词包、主题、搜索、词条和固定搭配浏览。
3. **我的**：学习记录、解释语言、音频、动效、数据和隐私设置。

首发不单独设置“游戏”入口；玩法在学习流程内部服务内容。

### 7.2 核心页面

| 页面 | 主要任务 | 必须状态 |
|---|---|---|
| 今日首页 | 让用户知道下一步做什么 | 新用户、可学习、仅复习、已完成、离线 |
| 词包选择 | 选择内容范围 | 加载、空、已下载、下载中、失败 |
| 内容引入页 | 建立词义与声音连接 | 播放、暂停、加载失败、跳过 |
| 练习页 | 完成一次检验 | 未作答、提示、提交中、答对、答错、看答案 |
| 反馈页 | 解释结果并决定下一步 | 再练、继续、查看例句 |
| 词条详情 | 回顾内容和关联搭配 | 内容完整、缺素材、离线 |
| 复习页 | 处理到期内容 | 有复习、无复习、积压、完成 |
| 设置页 | 控制语言、声音、动效和数据 | 保存、失败、恢复默认 |

### 7.3 视觉形态原则

- 内容优先：英文、含义、题目和操作按钮优先于数字人装饰。
- 数字人占据明确的角色区域，不遮挡题干和答案选项。
- 视觉风格建议“明亮、友好、低压力”，避免幼儿化，除非后续单独选择儿童路线。
- 正确、提示、错误必须同时用颜色、图标和文字表达。
- 关键操作使用大触控区域；不依赖拖拽完成首发题型。
- 学习过程中保持一个主操作，避免同时出现多个同等权重按钮。
- 支持系统大字体、TalkBack、减少动效和静音学习。

## 8. 数字人设计要求

### 8.1 首发职责

- 引入：展示对象、动作和一句简单说明。
- 示范：播放发音或演示具体动作。
- 提示：只在用户请求或答错后出现相关提示。
- 反馈：用短句表达鼓励和下一步。

### 8.2 不应做

- 每道题都自动说话。
- 在用户回忆阶段提前指向答案。
- 用复杂情绪表演替代错误解释。
- 首发加入摄像头动作识别或自由聊天。

### 8.3 资产约束

每个动作需要绑定内容目标、触发时机、持续时间、字幕和静态替代方案。切题时取消旧动作，避免角色与题目不同步。

## 9. 题型矩阵

| 题型 | 检验目标 | P0 |
|---|---|---|
| 英文→含义 | 识别当前词义 | 是 |
| 音频→含义/图片 | 声音识别 | 是 |
| 图片/情境→英文 | 受提示回忆 | 是 |
| 含义→英文 | 主动回忆 | 是 |
| 搭配补全 | 表达块完整性 | 是 |
| 情境选择搭配 | 合适表达选择 | 是 |
| 完整拼写 | 词形记忆 | P1 |
| 口头跟读 | 发音辅助 | P1 |
| 速度模式 | 熟练度/压力 | 否 |

每种题型在内容配置中必须声明：目标能力、答案形式、可接受答案、提示层级、错误解释和完成后状态更新方式。

## 10. 复习状态（首发简化）

建议内部使用以下状态，不把算法名称暴露给用户：

- `new`：尚未学习。
- `learning`：正在首次学习或当日重试。
- `scheduled`：已有下次复习时间。
- `due`：到期复习。
- `needs_attention`：连续错误、提示依赖或跨日失败。
- `mastered_for_now`：近期证据足够，但仍会再次复测。

首发先采用透明、可调的间隔规则；不把尚未验证的算法宣传为个性化最优。

## 11. 非功能需求

- 核心本地内容可离线打开和学习。
- 首次进入不因登录失败而无法体验核心流程。
- 音频播放失败有可理解的文本降级。
- 不在客户端放置云端密钥。
- 内容版本更新不能破坏已有学习记录。
- 采集数据最小化；原始语音首发默认不采集。
- 界面支持 Android 系统字号放大和 TalkBack 基本操作。
- 崩溃、内容加载失败和答题状态变化可被诊断，但不记录不必要的学习隐私。

## 12. 首发验收标准

### 学习闭环

- 新用户能在无需注册的情况下开始一轮学习。
- 一轮学习包含引入、练习、反馈和复现，不只是浏览卡片。
- 单词和固定搭配都能进入学习与复习。
- 浏览、看答案、提示后正确和独立正确可区分记录。

### 交互可靠性

- 答题重复提交不会重复增加进度。
- 退出并恢复不会跳过未完成题，也不会丢失已完成结果。
- 音频/图片失败不让本地文字学习完全阻塞。
- 关键按钮和反馈在大字体及 TalkBack 下仍可理解。

### 教学质量

- 每个首发内容项有经过人工审校的释义、音频、例句和答案。
- 每个题型可以说明它验证的能力。
- 固定搭配不能仅由单词逐字含义推导，必须有独立语境。
- 数字人不会在回忆阶段泄露答案。

### 上线门槛

- 至少一套完整原创内容包通过内容审校。
- 在至少一台真实 Android 设备和一个模拟器完成核心流程验证。
- 有离线、空内容、素材失败、退出恢复和升级兼容测试记录。
- 有隐私政策、内容许可记录和崩溃反馈入口。
