# SayAgain 产品结构与课程体系 v0.1

> **状态：首发产品结构提案，待评审。**  
> 日期：2026-10-13  
> 本文补足现有 PRD 未清楚定义的「课程入口、内容组织、用户选择与数字人教学角色」。它优先于页面美术和技术选型。

---

## 1. 先纠正一个缺口

此前原型只验证了一个最小学习闭环：**认识词 → 回忆 → 固定搭配 → 复习**。它回答了“一个单词怎么学”，但没有回答用户更重要的问题：

> **我为什么学这一组词？我现在应该学哪一条路线？学习完成后能到哪里？**

因此，SayAgain 不能只是一套“每日十个词”的闪卡界面；它应是一个有明确导航和可持续扩展的**词汇课程产品**。

产品结构必须先按“学习意图”组织，再由单词、搭配、图片、情境和数字人活动共同承载。

---

## 2. 核心产品主张

### 2.1 一句话

**SayAgain 是一个由 3D 动漫学习伙伴带领、让用户按自己目标进入英语词汇课程并完成“认识—理解—回忆—表达准备”的移动端学习产品。**

### 2.2 产品公式

```text
用户目标（为什么学）
+ 课程入口（从哪里开始）
+ 内容地图（接下来学什么）
+ 微型学习回合（这一词怎么学）
+ 间隔复习（什么时候再学）
+ 数字人情境教学（为什么这样说）
= SayAgain 学习体验
```

### 2.3 首发要验证的不是“题能不能做”

首发应验证四件事：

1. 用户能否快速找到“适合我”的词汇路线；
2. 用户是否愿意由数字人带领完成一个有情境的微型学习回合；
3. 用户能否从词义识别走到搭配和简单句子；
4. 用户第二天是否知道该复习什么、为什么复习。

## 3. 数字人方向：不是写实数字人，也不做平面幼儿动漫

### 3.1 建议结论

首发采用：

> **原创、风格化的 3D 动漫学习伙伴（stylized 3D tutor）。**

不建议首发采用：

- 写实真人型数字人；
- 只会循环卖萌的 2D 吉祥物；
- 多角色、多皮肤、多剧情宇宙。

### 3.2 为什么不是写实数字人

| 判断维度 | 写实数字人 | 风格化 3D 动漫学习伙伴 | 首发结论 |
|---|---|---|---|
| 亲和力 | 易出现“恐怖谷”，成人也可能有距离 | 亲和、有记忆点 | 选风格化 3D |
| 教学动作 | 口型、手势要求很高，瑕疵明显 | 指向、拿物体、表情足够自然 | 选风格化 3D |
| 美术成本 | 建模、绑定、口型、材质、灯光成本高 | 可复用动作库，迭代可控 | 选风格化 3D |
| 性能与包体 | 模型、视频或实时渲染压力高 | 可以降级为预渲染动画/序列帧 | 选风格化 3D |
| 品牌长期性 | 容易过时或像客服/直播 | 容易形成原创 IP | 选风格化 3D |

### 3.3 数字人的教学职责

数字人不是页面装饰，而是一个**具象化教学工具**。

| 教学节点 | 数字人的动作 | 学习价值 |
|---|---|---|
| 身体器官 | 指向自己的 eye / ear / hand / knee | 建立“英文—视觉—身体部位”直接关联 |
| 动物园 | 指向动物、模仿动作、带出特征 | 帮助语义区分，例如 tiger / lion |
| 职业 | 切换道具/姿势，如 stethoscope、chef hat | 将职业词放进社会情境 |
| 汽车 | 打开车门、指向 wheel / seat / traffic light | 支持部件词与搭配 |
| 国家与旅行 | 指向地图、行李、交通牌 | 连接国名、国籍、城市和旅行表达 |
| 答错 | 给一个线索动作或指向对象 | 降低挫败、帮助重新检索 |
| 完成 | 点头、击掌、总结一条可说的短句 | 正向结束但不喧宾夺主 |

### 3.4 首发资产边界

首发只需一位角色，先准备 6 组可复用动作：

```text
idle / 讲解
point / 指向
listen / 听音
hint / 提示
encourage / 鼓励
celebrate / 完成
```

首发不需要实时口型或自由对话。词条音频由独立、高质量的英语音频承载；角色动作与音频同步到“教学节拍”，但不假装角色在实时说每一个词。

## 4. 课程入口：四条路不是四套重复内容

用户提出的四种组织方式都合理：主题、年级、教材、考级。

但它们不应变成四份不同题库。正确模型是：

> **一个内容对象，一份学习证据，多个课程入口。**

```text
内容对象：apple / close the door / eye / traffic light
                 │
      ┌──────────┼───────────┬─────────────┐
      ▼          ▼           ▼             ▼
   主题路线     年级路线      教材路线        考试路线
   水果         小学一年级    指定教材单元     A2 目标词
```

同一个词可以有不同的**教学编排**和**复习状态**，但不应因入口不同而生成重复词条。

### 4.1 四个首发可见入口

| 入口 | 用户问题 | 适用人群 | 课程单位 | 首发状态 |
|---|---|---|---|---|
| **主题学词** | “我想学某个场景会用的词” | 自学成人、亲子、兴趣用户 | 主题 → 场景 → 单元 | **P0 主入口** |
| **年级同步** | “我现在这个年级该学什么” | K12 学生/家长 | 年级 → 学期 → 单元 | P1，需先确认市场课程标准 |
| **教材同步** | “我在学这本书的第几课” | 有明确教材的学生 | 教材 → 册 → 单元 → 课 | P1，须解决正版/授权/版本问题 |
| **考试目标** | “我为某项考试补词汇” | 考试用户 | 考试 → 能力/词表 → 单元 | P1，使用能力标签，不复制受保护材料 |

### 4.2 “其他”应该是什么

不应无限增加导航入口。建议以下项目作为**筛选维度或第二阶段路线**，而不是一级分类：

| 类型 | 示例 | 产品处理 |
|---|---|---|
| 使用目的 | 旅行、工作、留学、日常生活 | 初期属于主题/场景的标签；验证后可升级为路线 |
| 难度 | 零基础、A1、A2、B1 | 跨课程筛选与推荐标签 |
| 年龄 | 儿童、青少年、成人 | 决定视觉、解释、节奏，不应只做词库筛选 |
| 词性/能力 | 动词、名词、搭配、易混词 | 课程内部练习和复习筛选 |
| 个人目标 | 每天 5/10/20 分钟 | 改变学习节奏，不改变课程结构 |
| 复习原因 | 到期、答错、学过未稳 | 首页任务分配，不是内容入口 |

## 5. 课程内容的层级

### 5.1 统一内容地图

```text
路线 Path
  └─ 模块 Module（例如：我的身体 / 动物园）
      └─ 场景 Scene（例如：看医生 / 在动物园问路）
          └─ 学习单元 Unit（8–12 个核心词 + 3–5 个搭配）
              └─ 学习卡 Learning Item
                  ├─ 单词 / 短语
                  ├─ 释义与发音
                  ├─ 图片或微场景
                  ├─ 例句
                  ├─ 关联搭配
                  ├─ 误区/提示
                  └─ 数字人动作提示
```

### 5.2 主题路线首发样例

首发不应该铺开几十个主题。建议先做一个能体现数字人优势的 MVP 主题包：

> **《我的身体与日常动作》**

理由：身体部位最适合数字人指向教学；内容直观；可自然扩展到看医生、运动、感受和日常动作。

| 模块 | 场景 | 核心学习目标 | 示范内容 |
|---|---|---|---|
| 1. 我的脸 | 指认五官 | 能听懂并指出常见五官 | eye, ear, nose, mouth, face |
| 2. 我的身体 | 指认身体部位 | 能理解常见部位和简单动作 | hand, arm, leg, foot, head |
| 3. 我感觉怎样 | 描述简单身体状态 | 能识别基本感受词 | tired, hungry, thirsty, hurt |
| 4. 看医生 | 简单求助/理解指令 | 知道部位词的情境用法 | open your mouth, raise your hand |
| 5. 动起来 | 动作搭配 | 建立动词 + 部位的常用搭配 | clap your hands, wash your face |

首发首单元建议只做：**“我的脸：5 个词 + 3 个搭配 + 2 个简单句”**。这是能在小范围验证内容、美术、音频与学习效果的真实垂直切片。

### 5.3 每个单元的学习完成定义

一个用户完成一个单元，不是只看到 10 张卡，而是：

- 能在图片/动作辅助下识别目标词；
- 能在无中文答案时选出核心含义；
- 能完成至少一个固定搭配；
- 能在一个简单句中理解目标词；
- 对不会或答错的词生成后续复习任务。

## 6. 首页应该如何组织

首页不应只显示“今天 10 个表达”。它应该回答四件事：

```text
1. 我在学哪条路线？        → 当前路径
2. 今天为什么要学这些？      → 今日计划
3. 我离一个可理解的目标还有多远？ → 路线地图进度
4. 如果我想换目标，在哪里换？ → 内容路径入口
```

### 6.1 首页结构

```text
┌────────────────────────────────┐
│ 早上好，Alex                    │
│ 当前学习路径  [主题学词 · 可切换] │
│                                │
│ ┌────────────────────────────┐ │
│ │ 我的身体与日常动作          │ │
│ │ 第 1 单元：我的脸 · 3/8     │ │
│ │ Milo：今天学 eye、ear、nose │ │
│ │ [继续学习]                  │ │
│ └────────────────────────────┘ │
│                                │
│ 今天的计划                      │
│ 新学 3 个 · 复习 4 个           │
│                                │
│ [探索学习路径]                  │
│ 主题学词 / 年级同步 / 教材 / 考试 │
└────────────────────────────────┘
```

### 6.2 路径选择页

路径选择并不意味着用户每次都重置学习进度。用户切换的是“下一段要学什么”；复习队列始终跨路径显示，避免遗忘原有内容。

```text
学习路径
  [主题学词] [年级同步] [教材同步] [考试目标]

主题学词
  我的身体与日常动作   3/40
  动物园的一天         即将推出
  旅行第一天           即将推出
```

## 7. 首发产品边界建议（重新收敛）

### P0：必须做

- 风格化 3D 数字人一名与 6 个教学状态；
- 主题学习路径；
- 一个主题包《我的身体与日常动作》；
- 其中至少一个完整单元《我的脸》；
- 单词、搭配、简单句和复习闭环；
- 路径切换界面（其余路径可说明“即将推出”，但不假装已经可学）；
- 离线可用的核心内容、图片、音频和角色资源。

### P1：有首发数据后做

- 第二、第三主题包：动物园、职业、汽车/旅行，按用户需求排序；
- 年级同步路线；
- 教材同步路线；
- 考试目标路线；
- 词条详情、学习报告和薄弱项课程。

### 暂不做

- 同时覆盖所有教材、所有年级、所有考试；
- 未明确授权的教材内容复制；
- 为“内容看起来很多”而创建空壳课程；
- 多人社交和复杂世界观。

## 8. 需要你确认的关键决策

为进入技术方案，需要优先确认以下四项：

1. **首发人群**：成人零基础、儿童/亲子，还是小学阶段学生？三者的叙事、角色、解释语言和课程颗粒度不同，不宜混为一个首发版本。
2. **首发课程路线**：是否同意先以“主题学词”作为唯一可学习路线，并以《我的身体与日常动作》作为首发主题？
3. **数字人方向**：是否同意“原创风格化 3D 动漫学习伙伴”，而非写实虚拟人？
4. **内容来源策略**：年级/教材/考试路线先做课程索引与能力映射，待授权和内容编审方案确定后再上线具体课程。

确认后，原型将从“通用 apple 示例”重构为“身体部位主题课程”，并进入 Android/iOS 技术选型与方案设计。

## 9. 产品决策记录（2026-10-13）

以下事项已由产品方确认：

| 决策 | 结论 | 对设计的影响 |
|---|---|---|
| 首发用户 | **亲子家庭 + 小学生** | 首页同时服务孩子的学习任务与家长的可理解进度；文案、角色和课程节奏改为儿童友好，但不低龄化。 |
| 首发学习路线 | **仅主题学词可学习** | 年级、教材、考试作为未来入口展示，不在首发假装具备完整内容。 |
| 首发角色 | **原创风格化 3D 动漫学习伙伴** | 数字人必须为主题课提供动作、指向和情境教学，而非仅做装饰。 |
| 原型课程 | **身体部位主题课** | 核心演示由 apple 改为 eye / ear / nose / mouth；以角色指向动作体现产品差异。 |
| 对垒/PK | **纳入长期产品方向** | 首发不做陌生人实时对战；先设计为家长同意下的家庭/同学异步友好挑战。 |

### 9.1 亲子产品的双用户模型

```text
孩子：想玩得懂、学得会、看到自己成长
家长：想知道学了什么、是否真的掌握、如何适度陪伴
```

因此同一产品需要两层信息：

- **儿童层**：今天的任务、课程地图、角色陪学、轻量挑战；
- **家长层**：已学内容、复习建议、学习时长、掌握证据、家庭成员管理。

孩子默认不接触开放社交、陌生人私信、开放头像/昵称搜索或公开地理位置。

### 9.2 PK 的正确产品定位

PK 不应是“刷题速度竞争”，因为这会奖励猜题和焦虑，而不奖励掌握。建议把它定义为：

> **友好知识挑战：两个孩子在同一主题中完成短回合，比较的是学习完成和复习坚持，不公开羞辱失败者。**

首发后续顺序：

1. **P0：个人主题学习**——先证明学得会；
2. **P1：亲子共学任务**——家长与孩子一起完成主题小任务；
3. **P2：熟人异步挑战**——仅通过家长确认的家庭成员或同班邀请码；
4. **P3：受控班级活动**——需学校/老师场景与单独的安全、审核设计。

P2 的挑战规则建议：

- 同一主题、5 题以内、可在 24 小时内完成；
- 得分由正确率、提示使用和复习完成共同构成，不只比较速度；
- 只显示预设昵称和预设角色，不开放自由聊天；
- 失败反馈为“再练一次即可追平”，不显示公开排名；
- 家长可关闭挑战、限制对象、删除连接。
