# SayAgain 产品设计探索 v0.2

> **定位修正（2026-10-12）：** 用户明确产品是包含闪卡、句子闯关和数字人带学的英语学习 App，口语只是其中一个场景。本文的成人职场／口语主线不再代表整体产品方向；后续讨论见《DISCUSSION-DIGITAL-HUMAN-PRODUCT-v0.3.md》。

> 日期：2026-10-12。性质：讨论稿，不是已冻结 PRD，也不是实施任务。
> 输入：本目录《DISCUSSION-PRODUCT-NOTES.md》《android项目.md》与本轮核查的公开产品资料。
> 关系：保留历史纪要，不覆盖其中的正式规格声明。本轮未在纪要链接所指位置找到 SAYAGAIN.md，不能据此确认既有代码与正式规格的当前状态。

## 1. 最重要的方向判断

建议从“英语跟读纠错工具”扩展为：

**帮助已有一点英语基础、但开口困难的成年人，把工作和生活里需要的短语，练到能够脱稿说出来。**

产品承诺暂定：**每天 5 分钟，把几句真正用得上的英语练到能自己说。**

这不是“背单词 App + AI 聊天 App”的叠加。词汇、跟读、回忆、复习都服务于同一个结果：完成一个具体表达任务。

保留：Android、Google Play、东南亚／中东方向、短练习、可解释反馈、个人开发者可承担的范围。

重新打开的决策：首发国家、细分人群、定价、纠错承诺、是否加入脱稿提取、有效练习的指标口径。

## 2. 公开竞品证据与边界

本轮只核查官方网页和 Play 商品描述，未安装实测、未完成当地商店价格采样，也未系统分析评论。不能据此宣称竞品“不好用”、某国用户嫌贵或存在已证实的市场空白。

| 参考产品 | 本轮可确认的公开能力 | 对 SayAgain 的设计启发 |
|---|---|---|
| ELSA | Play 描述包含发音反馈、场景角色扮演、职业内容，以及可保存词／短语／句子的学习集 | “句级反馈”和“工作场景”本身不是独家差异化 |
| Speak | 官网明确描述 Learn → Practice → Apply，并提供真实对话练习 | 不能把 Speak 简化成纯自由聊天；需要用具体人群和体验验证区分 |
| Cake | Play 描述包含短视频表达、跟读、AI 发音检查、测验与复习 | 内容输入、跟读和复习的组合也已经存在 |
| AnkiDroid | 官方手册说明卡片与间隔重复调度 | 借鉴复习机制，不必移植整个牌组／模板管理产品 |

候选差异化不是“别人没有”，而是需要验证的体验组合：

- 为一个明确职业任务提供短而完整的训练；
- 进入 App 后不需要先找课程，直接知道今天练什么；
- 反馈克制、可信，允许系统承认没听清；
- 下一次打开能再次检验上次的表达，而不只是重复刷题；
- 本地语解释与低成本体验适合所选首发用户。

## 3. 首发用户：先从一个任务切入

### 暂定工作假设

面向一个首发国家中，能理解简单英语、需要与客人进行短句交流的成年学习者。首个场景候选：**酒店／餐饮服务英语**。

选择理由是设计上的可控性：任务可以拆成迎客、点单、确认、致歉等有限动作；不是已经验证了这个人群的需求或付费意愿。

不要同时首发印尼、越南、沙特和阿联酋。先选择最能接触到真实测试用户的国家，而不是只按照市场规模排名。

### 用户故事

“我知道一些词，但客人突然问我时还是卡住。我希望在上班前练几句今天能用的话，不想先上一整套英语课。”

### 需要访谈验证

1. 最近一次需要英语但没说出来，具体是什么场景？
2. 当时是听不懂、想不起词、不知道怎么组织，还是不敢开口？
3. 现在用什么方法解决？有没有实际付费？
4. 在什么时间和地点能出声练习？
5. 更需要本地语解释，还是英语示范？
6. 工作英语会不会太窄？日常／求职需求是否更强？

A1–A2 可作为内容难度的初始假设，但不能凭几句练习把用户正式评为某个 CEFR 等级。

## 4. 核心学习闭环

建议第一版采用：

**场景任务 → 听例句 → 看文跟读 → 短语提示下表达 → 隐藏英文后回忆 → 下次复习。**

这里应区分顺序跟读与严格的同步 shadowing。第一版以“听后再说”为主，避免术语和体验不一致。

### 一张表达卡的内容

| 字段 | 示例 |
|---|---|
| 场景任务 | 礼貌询问客人是否准备点单 |
| 核心表达 | Are you ready to order? |
| 可迁移短语 | ready to… |
| 本地语释义 | 由目标语言使用者审校 |
| 示范音频 | 标准速与可选慢速 |
| 等价回答 | Would you like to order now? |
| 小变体 | Are you ready to pay? |
| 复习提示 | 客人看完菜单，你想询问是否点单，怎么说？ |

第一版的内容单位建议是“表达卡”，不是孤立单词。单词可解释、可播放，但无需另建大型词书、词典和独立积分系统。

### 一次 5 分钟训练：建议测试的结构

- 先检验 1–2 张到期表达卡；
- 新学 2–3 张表达卡；
- 每张最多引导重试两次，之后允许看提示或跳过；
- 以一条隐藏英文的场景回答结束；
- 总结只说明“练了什么、哪些还需提示”，不制造虚假精确分数。

数量和时间是初始体验参数，要根据实际完成时间调整；不要让用户为了满额被迫完成。

### 三类任务必须采用不同判定

| 模式 | 用户目标 | 建议判定 | 禁止混淆 |
|---|---|---|---|
| 看文跟读 | 重现指定句子 | 检查识别文本的覆盖与差异，结合可用音频证据 | 文本匹配不等于发音优秀 |
| 提示表达 | 表达指定意思 | 人工预写可接受表达＋必要时有边界的语义判断 | 不要求与唯一标准句逐字相同 |
| 单词／短语练习 | 记忆或练读目标表达 | 将回忆正确与发音反馈分开 | 看到答案后读出不算独立回忆 |

例：给出“现在可以点单了吗”的场景提示时，Are you ready to order? 与 Would you like to order now? 可以都完成沟通意图。但若任务明确要求跟读前一句，系统可以提示读的是另一种表达，不应判为语法错误。

## 5. 反馈承诺：先可信，再精细

微软官方文档明确区分标准语音识别模型与发音评估专用模型。因此，不能把 ASR 转写差异直接包装成音素发音诊断。

### 第一版建议显示

- “这次识别到：…”；
- “没有识别到 order，试着把这一段再说一次”；
- “意思表达到了，也可以这样说”；
- “这次没听清，可以重录；不影响复习记录”。

### 没有专项证据时不显示

- “你的 /θ/ 一定发错了”；
- “发音准确率 92%”；
- “达到母语水平”；
- 用 LLM 从转写文本推断具体口腔动作或重音错误。

### 结果结构与规则

保留已有 excellent / pass / retry 兼容性的可能，但评估应增加独立的 `unassessable` 状态：录音无效、识别无结果、证据不足或服务不可用。

- `unassessable` 不等于学习失败，也不直接降低掌握度；
- 文本覆盖、语义完成、发音评估分别保留结果与证据类型；
- 第三方没有返回可用置信度时，不能伪造置信度；
- 对 ASR 可疑结果允许回放、重录、标记“识别有误”；
- 用户申诉用于排查，不直接自动标成掌握；
- 对脱稿表达，确定性可接受答案优先；不确定语义评估不强行判错；
- 纠错每次只给一个可行动建议，优先阻碍沟通的问题。

口音目标建议为“容易被理解”，而非强制模仿某一种母语口音。具体公平性需用目标人群音频验证。

## 6. 流程规格（探索级）

### Flow：完成首次表达练习

**Goal：** 用户完成一张表达卡，并知道如何继续练习。

**Entry Points：** 首次打开体验入口、首页今日练习、场景包详情。

**Prerequisites：** 有可播放的内容；云评估需联网；录音前获得麦克风权限。不要把注册作为首次体验的前提。

**Steps：**

1. 选择解释语言与一个练习目标，可跳过非必要设置。
2. 展示一张可立即练的表达卡；先听示范，不提前索取录音权限。
3. 点击“开始说”时说明用途并请求麦克风权限。
4. 点击录音、点击结束；明确显示正在录音和可取消操作。
5. 有效音频进入评估；等待时展示录音回放，禁止重复提交。
6. 显示一条建议；主操作“再说一次”，次操作“继续”。
7. 隐藏英文，以场景提示检查是否能自己表达。
8. 保存结果与下次复习状态；结束后再邀请开启提醒或备份。

**Success Exit：** 完成一次有效表达并进入总结；跟读完成与独立回忆完成分别记录。

**Cancel Exit：** 可随时退出，保存已完成卡片；未完成录音默认丢弃，不偷偷上传。

**Error Handling：**

| 状态 | 用户看到什么 | 恢复方式 | 对学习记录的影响 |
|---|---|---|---|
| 权限拒绝 | 无法录音，可先听示范 | 再次主动申请或系统设置入口 | 不记失败 |
| 静音／过短／环境噪声 | 没收清，请检查环境 | 重录或跳过 | 不记失败 |
| 评估中 | 正在检查，本次录音可回放 | 等待；超时后重试 | 不生成结果 |
| 断网／服务失败 | 本次暂时无法评估 | 本地回放、显式重试 | 标记未评估 |
| 识别疑似错误 | 展示“系统听到的内容” | 回放、重录、反馈识别有误 | 不直接降级 |
| 没有到期复习 | 今天暂时没有待复习表达 | 开始新练习 | 正常空状态 |
| 录音中进入后台 | 明确结束当前录音 | 回到页面重新开始 | 不自动上传残片 |

### 复习规则（可解释的起步方案）

可以先试验 1、3、7 天检查点，不宣称这是已经验证的最佳调度。

分别记录：看文练过、提示下说出、无英文提示说出、延迟后再次说出。只有后两项提供“能够提取”的证据。

当天反复读同一句不等于长期掌握；间隔后的失败可以回到提示模式，而不是清零所有进度。以后有足够日志，再评估更复杂的调度算法。

## 7. 信息架构与关键组件

建议三个主入口：**今天／场景／我的表达**。设置、账户、订阅放到次级入口；不另设 AI 聊天首页。

| 页面 | 主任务 | 第一版核心组件 |
|---|---|---|
| 今天 | 不做选择就能开始 | 到期复习摘要、5 分钟练习按钮、最近一次可见进步 |
| 场景 | 找到一个需要的任务 | 小量场景包、难度与适用任务、下载状态 |
| 我的表达 | 找回练过但仍不熟的表达 | 待复习／仍需提示／能独立说出分类、表达详情 |
| 练习页 | 听、说、看一条建议 | 示例播放器、表达卡、录音控件、反馈卡、继续按钮 |
| 总结页 | 看清本次结果 | 独立说出数、仍需提示列表、下次复习说明 |

### Component：录音控件

- **Purpose：** 用户能明确地开始、结束、取消录音。
- **Variants：** 可录音、录音中、评估中、暂不可用。
- **Data：** 麦克风权限、录音状态、持续时间、提交状态；避免同一录音重复计费。
- **Feedback：** 录音中显示计时和“停止”文本，不只显示动画；评估中禁用再次提交。
- **Edge Cases：** 音频焦点冲突、后台中断、电话打断、重复点击、无有效声音。
- **Acceptance：** 任何状态都能退出；无效音频不生成失败学习结果。

### Component：反馈卡

- **Purpose：** 解释本次结果，并给出一个下一步动作。
- **Variants：** 跟读反馈、语义完成、未评估、识别疑似有误。
- **Data：** 任务模式、识别文本、可用证据、主问题、建议动作、可接受答案。
- **Feedback：** 不自动展开长篇解析；允许回放示范与自己录音。
- **Accessibility：** 差异同时用文字标签说明，不能只有红／绿颜色；TalkBack 朗读结果和按钮用途。
- **Acceptance：** 没有音频级发音证据时，不显示精确音素诊断。

### 样式与适配（暂定规则，不是最终视觉稿）

- 中性背景、一种主强调色；警告与成功颜色只作为辅助。
- 英文表达是视觉中心，释义与教练说明层级稍低。
- 手机采用单列；较宽屏幕限制正文宽度，不无意义拉长按钮。
- 支持系统字体放大、文本换行、屏幕阅读器；不以波形作为唯一录音反馈。
- 如后续选择阿拉伯语，要单独设计 RTL 页面与英语 LTR 片段，不能只翻译字符串。
- 采用点击开始／结束，避免仅支持持续按住的操作。

## 8. MVP 范围与明确不做

### 第一版候选范围

- 一个首发国家，一种本地解释语言＋英语；
- 一个主要场景包，约 20–30 张人工审校表达卡；
- 听示范、看文跟读、隐藏英文的受限表达任务；
- 识别文本展示、可解释反馈、自己的录音回放；
- 基础复习队列与学习记录；
- 无账户首次体验，必要设置与数据删除入口。

离线承诺必须拆开：下载后的示范与内容可以离线播放；云评估不可用时只能录音回放／自评，不能伪装成已经评估。

### 暂不做

通用 AI 聊天、视频内容平台、任意材料导入、海量词书、社区排行榜、多国家同步上线、复杂音素仪表盘、无限生成课程。

注册同步与订阅可在闭环验证后加入；若第一版包含订阅，购买状态、恢复购买与游客绑定必须一起设计，不能只做付费墙。

## 9. 内容、数据与成本边界

- 内容宜先由人编写／审校；AI 辅助变体不等于自动发布。
- 示范音频需有一致的表达与音质，使用许可须另行核验；不先导入影视／视频素材。
- 学习状态与卡片版本关联，内容改动不要导致旧记录被错误解释。
- 原始录音默认不作为永久历史存储；明确云端处理、保留时长和用户删除规则后再上线。
- 不将录音上传日志或默认用于训练；调试音频收集另行取得同意。
- 初期优先成人场景；儿童路线需另开设计与合规工作，不隐性混用。

历史纪要中的 $2.99–3.99/月保留为待验证的价格候选，而非已经成立的定价。

成本测算应包括：

`每付费用户月贡献 = 净收入 − ASR/评估 − 教练生成 − 存储/流量 − 分摊的免费用户成本 − 其他可变成本`

要用真实录音时长、重试率与调用量测算。重复按钮、失败请求与无效音频必须防止重复收费。若成本过高，先减少无必要调用，不能默认转嫁成学习中频繁打断。

## 10. 验证计划与指标

### 第一阶段：验证需求与反馈信任

建议找 8–12 位符合暂定画像的学习者；这是探索性样本，不代表市场统计结论。

先用现有工具或人工辅助完成一轮表达练习，不要求先开发完整 App。观察能否理解指令、愿不愿意出声、是否认为反馈准确、有无实际用途。

ASR 对比不仅测英文词错误率，还要有人工听评标签：能被理解／需要提示／确实缺失／系统没听清。按说话人划分试验集，保留口音、噪声与设备差异；20 条样本只能用于早期排雷，不能据此宣称稳定上线。

### 第二阶段：验证复习与脱稿价值

让同一批用户在延迟后完成隐藏英文的场景表达；比较首次、当天重试和后续复习，避免把看文熟练当成长期学习效果。

建议北极星候选：**每周在到期复习中、无英文答案提示下完成的独立表达卡数（按用户×表达卡去重）。**

配套观察：

- 首次有效录音／首次完整训练完成率；
- 学习者次日、七日回访及再次主动练习；
- 跟读完成率与脱稿表达完成率分别统计；
- 未评估率、识别争议率、人工听评下的误判失败率；
- 有效录音后的反馈等待时间；
- 每有效表达的服务成本；
- 用户是否认为某一表达在现实中有用，而非只看打卡天数。

不在本轮凭空设定“行业合格”留存率。试验前可共同约定内部门槛，并注明只是团队决策标准。

### 第三阶段：再决定投入

- 用户觉得跟读有用但拒绝脱稿任务：检查难度和提示，不立即扩功能；
- 用户主要被识别误判困扰：优先修可靠性，暂停精确纠错承诺；
- 用户喜欢练但不主动回来：检查场景频率、实际用途与复习负担；
- 明确表达了使用价值且愿意付费：再做当地价格测试与订阅设计。

## 11. 实施交接条件

实现目标沿用 Android 原生 Kotlin／Compose＋薄评估服务的候选方向；不因参考 Web UI 模板改为 React 或 Next.js。本轮不创建工程、不安装依赖、不选择最终模型。

进入正式 PRD 前需确认：

1. 首个用户任务与测试用户来源；
2. 首发国家和本地语言；
3. 主承诺是跟读纠错，还是脱稿表达；
4. 语音评估技术能提供哪些证据；
5. 20–30 张卡的内容审校和音频来源。

工程验收至少覆盖：权限拒绝、静音、服务失败、后台中断、重复提交、等价回答、未评估不扣掌握度、字体放大、TalkBack，以及下载内容的真实离线边界。

## 12. 接下来最值得讨论的问题

**用户最希望先解决的是：说不准、不敢开口，还是知道单词却组织不成句子？**

如果选“说不准”，保留更纯粹的跟读工具，尽早验证专项发音评估。
如果选“说不出来”，优先表达卡＋脱稿检验。
如果选“词汇基础不足”，需要更慢的词／短语输入与受控句型练习，不能直接推开放对话。
