## 国内投递环境里会被额外审视的三类经历

这些不是「简历缺陷」，是筛选者在国内招聘里会额外追问的地方。你的任务不是要求候选人掩盖，
而是判断**它有没有被解释**——没解释才会变成风险，解释清楚就是中性信息。

### 外包经历

判据：项目价值、职责边界、成长路径有没有写清。**不要**把「在外包公司」本身报成缺陷。

- 只写「配合甲方团队完成 XX」= 在场证明，缺少职责边界 → `warning`，提示写明独立负责的部分。
- 写清了承接的模块、边界与上线结果 = 正常经历，不报。
- 从外包转到甲方/平台团队并在摘要里交代了转折 = 正向信号，不要报成「跳槽频繁」。
- **不得建议隐藏外包经历**。空出一段时间比外包经历更难看，且删项本身可能是事实隐瞒。

### 频繁跳槽

判据不是次数，是有没有可复述的逻辑。三段各一年但每次补齐明确能力 = 有主线，不报。
多段经历且摘要里完全没有选择逻辑的交代 → `warning`，提示用一句话写明这几段的主线。

### 空窗期

简短说明即可（创业、进修、家庭原因、被裁都是正常理由）。**不要**因为存在空窗期就报问题。

- 时间线上有这个空档、摘要或经历里有一行说明 = 已解释，不报。
- 为了填补空档而改动源档案日期 = 这是 `date_integrity` 的 `error`，与空窗期本身无关。
- 空窗期期间有证书、系统性学习或独立项目 = 已转成积累，不报。

### 玩具项目

外卖系统、秒杀系统、商城、博客、在线教育平台这类题目，风险不在题目本身，而在于它默认缺少
四样东西：**真实场景、独特取舍、复杂问题、结果证明**。

- 只有技术栈罗列、没有以上任何一样 → `warning`，提示补一个真实亮点
  （压测与容量设计、限流/缓存/一致性的具体细节、方案取舍的理由、上线后的变化）。
- 已有其中任意两样 = 可以接受，不报。这是入门项目的常见上限，不是造假。
- **不要**建议删除项目。删掉之后简历只剩空白，对候选人更差。

## 边界

以上全部是 `warning` 级。它们描述的是「材料没写清楚」，不是「说了假话」。
`error` 的定义只在 `severity.md` 里，不因本文件扩大。
