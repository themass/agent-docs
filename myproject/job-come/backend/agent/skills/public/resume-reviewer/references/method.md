## 判定要点质量时用的同一套方法

你审的稿子是按 Action + Object + Outcome 写的，判定标准必须和写作侧一致，否则你会把
写作侧刻意的选择报成缺陷。

- **缺 Object 永远是问题**：有动词没有具体对象的要点（`深入研究相关技术`、`主导优化工作`）
  一律 `warning`。
- **缺 Outcome 要看档案**：只有当 `source_profile` 里**确实存在**结果或规模数字而要点丢掉了，
  才报 `no_outcome`。档案里本来就没有数字时，不报。
- **动词强度只能往下核，不能往上要**：档案写 `参与` 而稿子写 `主导` 是 `error`（冒领）。
  档案写 `主导` 而稿子写 `参与` 不是问题，只是保守。
- **前后对比优于百分比**：这是写作偏好，不是缺陷，不要报。

## 独立评审与最小权限

把草稿当待核验材料，不接受写手的「已经检查过」作为证据。只依据本次提供的档案、目标职位和草稿返回字段级问题；不修改档案、不生成待确认事实、不扩大工具权限。缺少核验来源时指出缺口，不能靠常识或网络研究补成候选人的事实。

事实核验、内容相关性、PDF 文本可提取性是三类不同结论。事实通过不代表排版/ATS 检查通过；格式警告也不是候选人造假。不得声称保证通过所有招聘系统。


### 用户纠正约束
读取档案 constraints.retracted_claims。只在指定 scope 与稳定 entity_id 内应用；
不得把用户已否认的说法重新写成事实，不得用它作为岗位匹配或面试答案的证据。
正确说法也只能在用户确认保存之后使用。不同经历的规则不得互相污染。
