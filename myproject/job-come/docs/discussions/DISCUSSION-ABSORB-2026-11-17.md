# 两个参考项目的吸收方案：skill 还是功能

- **日期**：2026-11-17
- **对象**：[LLawrence233/magic-resume](https://github.com/LLawrence233/magic-resume)、
  [wyh0626/resume-optimizer](https://github.com/wyh0626/resume-optimizer)
- **前置阅读**：[`DISCUSSION-COMPETITOR-SEO-2026-11-17.md`](DISCUSSION-COMPETITOR-SEO-2026-11-17.md)

## 结论先行

| | 许可证 | 吸收形态 | 一句话 |
|---|---|---|---|
| magic-resume | Apache-2.0 + **附加条款禁止 SaaS/商用** | **只学模式，零代码复制** | 功能设计参考图鉴 |
| resume-optimizer | MIT，19 KB 纯 markdown 无代码 | **prompt 资产直接吸收** | 我们缺的评分方法论它已写好 |

判别标准就一条：**内容还是机制**。经验判断、写作标准、评分规则这类「知识」进
agent 的 prompt/skill 层（`backend/agent/`）；交互、渲染、构建这类「机制」是产品功能，
要自己写。magic-resume 几乎全是机制（所以只能看不能抄），resume-optimizer 几乎全是知识
（所以 MIT 之下拿来就能融）。

---

## 一、resume-optimizer → skill 侧（prompt 资产）

MIT、无代码、SKILL.md + references/ 渐进披露结构——它证明了我们 P2 想走的路是对的
（prompt 资产本身可以是产品）。下列条目按「直接改写进 `backend/agent/` 提示体系」处理：

1. **占位符防编造机制** ⭐ 最高价值
   缺证据时输出 `[量化指标待补：QPS/用户数/成功率]` 这样的显式占位符，而不是编一个
   像样的数字。和我们已有的「确认门」是同一哲学：没有经用户确认的话不上简历。
   → 并入简历改写与 reviewer 两侧提示词；导出前质检把「残留占位符」列为阻断项。
2. **三段式链路**：`业务目标/技术挑战 → 关键动作 → 可感知结果`。
   → 作为改写输出的硬格式约束；现已在首页文案承诺过，落到 prompt 里。
3. **2/3 判定标准**：一条描述满足「说清问题 / 说清动作 / 说清结果」中的两条即可放行。
   → 给 reviewer 的二值判定用，比「质量不错/一般」可执行得多。
4. **弱动词黑名单**：负责 / 参与 / 协助 / 配合 → 必须替换。
   → 质检规则 + 改写提示词；指南《量化降级》一文已与产品行为对齐。
5. **量化降级阶梯**：性能 → 业务 → 效率 → 规模 → 风险；拿不到精确值时依次用
   范围、频率粒度、状态迁移、消除的风险、建立的产物。
   → 追问策略的依据：按阶梯从上往下问，问到哪层有答案就停。
6. **中国特化清单**：外包雇主处理、玩具项目识别（外卖/秒杀/商城/博客默认缺
   真实场景·独特取舍·复杂问题·结果证明四样）。
   → reviewer 的风险标注项；首页 FAQ 已承诺「系统会单独列出这类风险」，这条让它成真。
7. **30 秒判定**：模拟面试开场先给整体判断再展开。→ `jc-reviewer` 报告结构。

**不建议照搬**：它的七段式输出契约是给 Claude Code 当 skill 用的文件布局，我们的 agent
有既有会话协议，只取判定标准不取输出格式。

## 二、magic-resume → 功能侧（模式，不碰代码）

Apache-2.0 正文后面挂了双语附加条款：**不得将其用于 SaaS 或以盈利为目的的提供服务**。
所以这一侧全部是「看完它的做法，在我们代码库里自己实现」。按投入产出排序：

1. **模板缩略图生成流水线** ⭐ 与 SEO 直接挂钩
   它用 playwright 无头浏览器把每套模板渲染成截图喂给展示页。我们有现成的渲染引擎
   （`resume_render_engine` 三套版式），缺的就是「定时把样例数据渲染成 PNG 发布」这一步
   ——这正是清单里 `/resume-template` 效果图页的前置。后端本来就用 Chromium 导 PDF，
   边际成本低。**建议先做这个。**
2. **AI 输出 → schema 防御性归一化**：模型返回的结构化结果先过一个宽容解析器
   （类型纠正、丢多余键、拒绝越界枚举），失败则整段降级为纯文本提示重试。
   我们的 profile patch 路径已有确认门，但 MCP handler 层值得加同层防御。
3. **分页/压一页的数学**：字号→行高→页高的显式计算实现「自动压缩到一页」。
   我们模板统一控制排版，这个需求真实存在（中文单页版式），但属于渲染引擎内部改造，
   排期靠后。
4. **预览点击即编辑**：点击 PDF 预览区直接进入对应字段的编辑态，体验好；
   依赖逐元素反向定位，成本高，暂不做。
5. **不学**：localStorage 单文件存储（我们以后端档案为中心，这是产品根基差异）；
   外部 PDF SaaS 依赖（我们有自托管渲染）。

## 三、P2 反向输出：我们的 SKILL.md

resume-optimizer（578 星）验证了「简历方法论作为 skill 分发」这条路。我们手里同样有货：
确认门哲学、占位符机制、导出前质检规则、模拟面试评审标准。吸收第一节后，把这套判定
标准整理成脱敏版 `SKILL.md`（name + description frontmatter，正文渐进披露）发到
skills.sh，`npx skills add` 可装——对舟卡是最便宜的品牌外联，且天然贴我们技术栈。
脱敏红线：不带上任何后端实现细节、API 形状、定价数字。

## 四、落地顺序建议

| 波次 | 内容 | 归属 |
|---|---|---|
| 1 | 占位符机制 + 三段式 + 弱动词表 → reviewer/改写提示词 | skill |
| 1 | 模板缩略图流水线 → `/resume-template` | 功能+SEO |
| 2 | 2/3 判定、降级阶梯追问、中国特化清单 | skill |
| 2 | MCP 层防御性归一化 | 功能 |
| 3 | 我们的 SKILL.md 上 skills.sh | P2 |
| 4 | 自动压一页、点击即编辑 | 功能（需求验证后再排） |

第 1 波两项分别落在提示词和渲染/构建层，互不阻塞，可以并行开工。
