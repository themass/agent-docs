# DISCUSSION-INTEGRATIONS：外部 Skill、MCP 与开源组件

- **状态**：调研与准入规则；默认不启用外部能力
- **最后更新**：2026-10-15

## 结论

V1 不以安装大量 GitHub Skill/MCP 为目标。现有自研 `jc_*` 工具和 `backend/agent/skills/` 覆盖主闭环；外部组件只有在能明确补齐一项已排期需求、满足权限边界且通过测试时才可引入。

## 准入标准

一个外部 Skill/MCP 必须同时满足：

1. 明确的业务价值和责任人；
2. 可审查源码、许可证、维护状态与依赖链；
3. 最小权限：不得默认获得通用网络、浏览器、文件系统、shell 或数据库；
4. 不包含把个人档案事实自动提交的路径；
5. 固定版本或 vendored 副本，可复现安装；
6. 有成功、失败、越权、数据泄露和回归测试；
7. 在 `backend/agent/skills/custom/` 或受控配置中记录来源、版本、权限、启用状态与移除方式。

## 推荐的评估方向（不是默认安装清单）

| 类别 | 候选能力 | 适用场景 | V1 默认 |
|---|---|---|---|
| 文档转换 | MarkItDown / Docling | PDF、DOCX 结构化和质量评测 | 先以本地可复现评测为准，不作为未验证生产依赖 |
| 职位信息 | 受限页面读取 | 读取用户指定的公开 JD | 仅 `jc_job_fetch`，不开放通用 fetch/search |
| 简历/面试 rubric | 社区 Skill 的评分量表 | 丰富 reviewer 或 mock 面试评分 | 抽取规则并审稿，不直接信任或整包接入 |
| 日程 | Calendar MCP | 用户明确授权的面试日程管理 | V2+ 评估 |
| 公司研究 | 搜索/研究 MCP | 用户明确发起的公司调研 | V2+，需网络和数据来源治理 |

## 明确禁止默认启用

- 通用浏览器与任意网站操作；
- 通用网络抓取、搜索或带登录态的页面访问；
- 任意本地文件系统、shell、GitHub 或数据库 MCP；
- 任何可绕过用户确认来修改 profile 的工具；
- 以“自动投递”为目的的招聘站自动化。

每次拟引入外部组件，都要先补一条 ADR/讨论记录或把已确认结论归入 [`../architecture/TECH-AGENT.md`](../architecture/TECH-AGENT.md)。
