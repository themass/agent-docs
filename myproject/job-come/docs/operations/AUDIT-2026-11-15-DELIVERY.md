## 3. 一处路径错误（必须说明）

我长期把 agentkit 源码说成 `libs/agentkit/`，**实际路径是 `docs/libs/agentkit/`**。
仓库根不是 `deepagents/`（它不是 git 仓库），真正的 git 根是 `docs/`。

影响：文档、命令、脚本里的路径有偏差。构建脚本本身是对的（它用相对自身的位置推导），
所以**产物没问题**，但我给负责人的描述有误。

## 4. G8「bug 必须修复」——已修清单

| 缺陷 | 性质 |
|---|---|
| `/admin/metrics` 每次请求 500 | 缺 `from jc.config import settings` → `NameError` |
| `/metrics/snapshot` 500 | 引用 lifespan 局部变量 |
| `snapshot()` 的 `service` 为 `None` | 从 series 标签读，应从 `_state` 读 |
| `enable_multiprocess()` 静默无效 | `ValueClass` 在 import 时固定；改为环境变量 |
| `agent_turns_in_flight` 永不归零 | gauge 用了 `all` 而非 `livesum`；且死后无人清理 → 加 `prune_dead_workers()` |
| `stream_message` 无 `finally` | 中途异常丢行 + 泄漏 inflight |
| `sharing_across_processes` 恒 false | 该键只在路由里补，其它读取方拿不到 |
| `method_*` 面板不存在 | 指标在产，前端根本没渲染 |
| `stream_message` 耗时 0.00003s | async generator 不是协程函数 → 只计了构造 |
| `ensure_deerflow_source` 早退 | 存在即返回，错的 SHA 看不见 |
| 后端以 root 运行 | 造成 root 属主文件 → 每轮 `PermissionError`；已加守卫 |

**关键教训**：这些问题里，**没有任何一个**是 990 个后端单测能发现的——
它们测组件，不测"用户能不能走通一条路"。

### (2) 没有 Grafana 式面板 / 缺 QPS·耗时·核心节点监控 / 列表慢 + 要时间倒序 —— ⚠️ 部分完成

  按场景/按模型、故障转移、失败原因、**核心方法耗时**、**核心方法调用次数**。
- ✅ 排序：已是 `created_at DESC`，不需要改。
- ❌ **没解决"列表慢"**——我只确认了不是排序导致，**没有去优化查询/返回体**。
- ❌ **没做真正的 QPS 面板**（当前是累计计数，不是每秒速率）。

### (3) 两个"思考中" —— ⚠️ 改了，但**没做浏览器验证**
