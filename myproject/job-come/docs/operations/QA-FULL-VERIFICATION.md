## 0. 为什么要重写这一份

之前的验证是**每轮临时写脚本、看输出、不复用**。后果是每轮都在"第一次真正跑某条路径"，
于是每轮都冒出新问题；而 990 个后端测试也没拦住任何一个真实缺陷，因为它们测的是**组件**，
不是**产品行为**。

本文件的唯一目的：把验证变成**可重复、可回归、可交给别人执行**的资产。

### 0.1 三条硬规则

1. **只认证据，不认"应该没问题"。** 每个用例必须产出：截图 / 接口响应 / DB 查询之一。
   没有证据 = 未通过。
2. **失败必须可复现。** 报告里写清：账号、档案 ID、会话 ID、trace_id、时间点、操作序列。
   无法复现的失败，单独归为 `UNREPRODUCIBLE`，不算通过也不算失败。
3. **区分"没做过"和"做失败"。** 页面上没出现入口，和入口点了报错，是两个不同缺陷。

## 1. 环境、账号与测试前置

### 1.1 生产服务

```bash
# 在部署机上确认（不要用 root 跑服务）
./scripts/backend.sh status
./scripts/frontend.sh status
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/health
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3001/
```

### 1.2 账号矩阵

| 角色 | 用途 | 说明 |
|---|---|---|
| 普通用户 A（新注册） | 全旅程主账号 | 从零注册，走完建档→简历→JD→面试 |
| 普通用户 B | 权限隔离验证 | 用 B 的会话访问 A 的资源，**必须 403/404** |
| 管理员 | 后台面板验证 | `User.role = admin`；`/admin/*` 全部依赖它 |
| 游客 | 免登录路径 | `POST /guest/session` |

> **注意**：管理员角色与普通角色必须是两个不同账号。历史上出现过"产生数据的账号没有权
> 限看面板，能看面板的账号没产生数据"，导致面板从未被真正打开过。

### 1.3 测试数据准备（每个用例开始前重置）

| 数据 | 如何准备 | 用完是否需要清理 |
|---|---|---|
| 已确认档案 + 至少 2 段工作经历 | 上传一份真实简历 PDF，或 `POST /profiles/from-text`（≥80 字） | 保留 |
| 绑定岗位的档案 | `POST /jobs/profiles/{id}/parse` 建 JD | 保留 |
| 模拟面试额度 | 会员等级满足 `full` 模式要求 | 注意配额消耗 |

**已知产品约束（不是 bug，不要记为缺陷）**：

- 粘贴文本 < 80 字会被拒绝——低于此阈值结构器会编造内容。
- `mode=target` 的模拟面试**必须**绑定 `job_id`，否则返回
  `409 目标岗模拟需要先选择岗位；无 JD 可使用练手模式`。
- 新建档案没有岗位时，模拟面试走不通，需先建 JD 或切到有 JD 的档案。
- 导出前质检**永不阻断下载**；质检失败也要能下载。
- 匹配分数、覆盖度、岗位标准检查**一律是建议**，不阻断。

## 3. 执行流程

### Phase 0：基线（15 分钟）

```bash
./scripts/backend.sh status && ./scripts/frontend.sh status
git log --oneline -1
```

记录：commit、backend/frontend pid、`/health` 码。**之后所有报告都引用这个基线。**

同时抓一次 `/metrics/snapshot` 存为 `baseline-snapshot.json`，用于末尾对比。

### Phase 1：纯 API 冒烟（不需浏览器，30 分钟）

按 A → M 顺序用脚本打接口。目的：把"接口级明显坏了"和"UI 渲染坏了"分开。

要求：
- 每个请求保存 `method path status 耗时 响应体前 200 字` 到 `api-log.jsonl`。
- 401/403 的用例要**先确认真实权限**再判失败。历史上把预期 401 当成 bug 报过一次。

### Phase 2：Playwright 端到端（主体工作）

**建议**：把 Playwright 装进 `frontend/web`，配置写一次，用例按上面的 ID 组织。

```bash
cd frontend/web
npm i -D @playwright/test
npx playwright install chromium
```

要求：
- 每个用例一个 spec 文件，文件名即 ID：`a-01-register.spec.ts`。
- 失败时自动截图 + 保存 console 错误 + 保存网络请求。

- 关键断言要断**内容**，不只是"元素存在"：
  - 错：`expect(page.locator('.thinking')).toBeVisible()`
  - 对：`expect(page.locator('text=思考中')).toHaveCount(1)`
