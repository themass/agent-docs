# REVIEW-ROLE-FAMILIES：各岗位族的面试追问方向，请行业内的人审校

- **生成方式**：由 `python -m jc.coach.family_review` 从代码生成，不要手改本文件；审校意见写在表里的“你的意见”列，或另存一份。
- **为什么需要**：下面的内容是我们起草的，没有行业专业人士看过。自动测试只能查结构，查不出“这条追问在行业里是否问到点上”。
- **怎么用**：每个岗位族一节，发给做这一行的人，让对方填最后的表。不要求逐条改写，指出“这条不对”“缺了这条”就够了。
- **没覆盖的**：`general`（岗位族无法判定时用的中性族）不带任何追问方向，所以不在这里。题库、评分锚点的行业差异也不在这里。

## 后端 / 服务端研发（`backend`）

**追问方向**（面试官据此追问，评审据此判断回答是否站得住）

- 为什么选这个方案，放弃了什么，代价在哪里
- 规模和瓶颈：量级是多少，第一个撑不住的是什么
- 出过的问题：怎么发现、怎么定位、怎么避免再来一次

**成果通常这样衡量**（只当作追问的方向，不替候选人编数字）

P99/P95 延迟、QPS/TPS、可用性 SLA、成本节省、故障率与恢复时长、容量与规模

**工作的对象通常是**

服务、接口、链路、存储、集群、中间件、数据一致性方案

**审校意见**

| 问题 | 你的意见 |
|---|---|
| 这三条追问方向，是这个行业面试里真会问的吗？有没有该问却没写的？ | |
| 有没有哪一条在你们行业里是外行才会问的、或者问了反而显得不专业？ | |
| 成果指标和工作对象：哪些不该出现，哪些缺了？ | |
| 按初级、中级、高级、专家，问法应该怎么变？ | |
