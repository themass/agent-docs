| 项 | 内容 |
|---|---|

| 日期 | 2026-09-06 |
| 关联 | [档案与简历编辑设计.md](档案与简历编辑设计.md) · [简历解析与导出.md](简历解析与导出.md) |

## 1. 产品定义

用户要的不是「界面双语」，而是 **投递物三选一**：

| 轨 `track` | 用户看到的 | 文件形态 |
|------------|------------|----------|
| `zh` | 中文简历 | 1 份 PDF/Word，中文一页 |
| `en` | English resume | 1 份 PDF/Word，英文最多两页 |
| `bilingual` | 双语简历 | **同一份** PDF/Word：先中文全文，再英文全文（中英对照） |

无论上传的是中文还是英文原件，系统都 **自动生成中、英两份展示稿**；双语轨是把这两份按固定顺序装进一个文件，而不是再翻译第三次。

核对页（Layer 1 Profile）仍用 **原文语言** 编辑事实，避免用户对着翻译稿改公司名/日期。

```text
上传中文或英文简历
        │
        ▼
  检测 source_locale（zh | en）
        │
        ▼
  Profile 存原文事实（真相源，只一份）
        │
        ├─ localize → i18n.zh-CN  （原文轨几乎零成本拷贝）
        └─ localize → i18n.en-US  （跨语言翻译，LLM）
        │
        ▼
  自动生成 ResumeDraft × 2（zh-one-page / en-two-page）
        │
        ▼
  用户选择：中文 | 英文 | 双语 → 预览 / 导出
```

## 2. 不做什么（边界）

- 不做整站 UI 中英切换。
- 不把 Profile 拆成两个档案（切换档案 ≠ 切换语言）。
- 双语 **不是** 左右分栏、也不是每条 bullet 中英夹杂（难排版、难审稿）。M1 双语 = **顺序对照：中文稿 + 分页 + 英文稿**。
- 专有名词不擅自意译：公司名优先官方英文，没有则保留原文；数字/日期不编造。

## 3. 数据模型

继续用现有三层，只加「语言覆盖层」。

### 3.1 Profile（仍一份真相）

`jc_profile.locale` = **源语言**（ingest 检测，用户可改）。

`payload.meta` 增加：

```json
{
  "source_locale": "zh-CN",
  "i18n_status": {
    "zh-CN": "ready",
    "en-US": "pending | ready | failed"
  }
}
```

`payload.i18n`（与 experiences[].id 对齐，禁止另造经历）：

```json
{
  "zh-CN": {
    "summary": "…",
    "headline": "高级后端工程师",
    "experiences": [
      { "id": "exp_1", "title": "高级后端工程师", "highlights": ["…"] }
    ],
    "education": [{ "id": "edu_1", "degree_line": "本科 · 计算机" }],
    "skills_line": "Go · Kafka"
  },
  "en-US": {
    "summary": "…",
    "headline": "Senior Backend Engineer",
    "experiences": [
      { "id": "exp_1", "title": "Senior Backend Engineer", "highlights": ["…"] }
    ],
    "education": [{ "id": "edu_1", "degree_line": "B.S. in Computer Science" }],
    "skills_line": "Go, Kafka"
  }
}
```

公司名、学校名、日期、联系方式以 Profile 原文为准；i18n 只覆盖 **需要翻译的展示字段**（title / highlights / summary / degree 文案）。

### 3.2 ResumeDraft（按轨各存一份）

现有 `locale` + `template_id` 已够用，**查询必须带 locale**（今天 `get_latest_draft` 只按 elevation 取最新，中英会互相覆盖，必须改）。

| track | draft.locale | template_id |
|-------|--------------|-------------|
| zh | `zh-CN` | `zh-one-page` |
| en | `en-US` | `en-two-page` |
| bilingual | `zh-en` | `zh-en-bilingual` |

双语 Draft 的 `sections` 不重新写 bullet，只引用：

```json
{
  "track": "bilingual",
  "zh_draft_id": "rdft_…",
  "en_draft_id": "rdft_…",
  "zh_sections": { },
  "en_sections": { }
}
```

生成双语稿 = 拼已有中英 sections，**不再打一次 Writer**。中或英缺失时禁用「双语」并提示先等另一侧完成。

### 3.3 索引

`get_latest_draft(profile_id, elevation_level, locale)`  
可选后续 unique：`(profile_id, elevation_level, locale, job_id)` 取最新即可，不必立刻加 DB unique。

## 4. 流水线

### 4.1 检测源语言

规则（无 LLM）：

1. 抽取文本后统计 CJK 码点占比。
2. `cjk_ratio ≥ 0.15` → `zh-CN`，否则 `en-US`。
3. 写入 `profile.locale` + `payload.meta.source_locale`。
4. 核对页提供「原文是中文 / English」更正，更正后重跑 localize。

### 4.2 何时生成中英稿

| 时机 | 行为 | 是否阻塞上传 |
|------|------|----------------|
| Ingest 成功 | 源语言 i18n 直接从 payload 投影；目标语言走 `LocalizeService`（LLM） | 否，后台 |
| 用户确认档案 | 按当前 elevation **重跑** 中+英 Writer | 否，预览显示生成中 |
| 用户改 Profile 事实（patch/confirm） | i18n 目标语言标记 stale，后台刷新 | 否 |
| 用户点「生成预览」 | 若该轨已 ready 则直接渲染；stale 则同步重生成该轨 | 是（当前轨） |

原则：**上传秒回**；语言轨是异步产物。UI 用 `i18n_status` 显示「英文稿生成中…」。

### 4.3 LocalizeService（翻译层，不是 Writer）

新 prompt：`prompts/elevate/localize.md`。

输入：`ProfilePayload` + `target_locale`。  
输出：上面的 `i18n[target]` JSON。

硬规则：

- 不得新增/删除 experiences（id 必须对齐）。
- 不得改日期、不得发明指标。
- 公司/学校：有通用英文则用（ByteDance / Tsinghua），否则原文。
- 中→英：过去式成就句；英→中：书面简历体，不口语。

源语言侧：`i18n[source] = project_from_payload(profile)`，不调用 LLM。

### 4.4 Writer（拔高层，按轨各一次）

`ResumeElevator.build_sections(profile, locale=…)` 读 **该 locale 的 i18n**，再拔高。

- 中文轨：读 `i18n.zh-CN` + `zh-one-page`
- 英文轨：读 `i18n.en-US` + `en-two-page`
- 失败回退：规则引擎用 i18n 字段拼 sections（已有 `ResumeDraftBuilder`）

确认档案后 **并行** 跑 zh / en 两次 elevate（`asyncio.gather`），各写一条 draft。

### 4.5 双语渲染

新模板 `templates/resume/zh-en-bilingual.html`：

```text
[中文 zh-one-page 正文]
<div class="page-break"></div>
[英文 en-two-page 正文]
```

导出 PDF 时 `@page` + `page-break-before: always`。Word 用两个 sect 或两套 docxtpl 段。

Reviewer：双语导出 **分别审** 中英 sections，任一侧 `error` 则该侧标红，仍允许先下另一侧单语；双语下载要求两侧都 `passed`（或用户勾选「忽略警告」—— M1 不做，跟现有门禁一致：error 阻断）。

## 5. API

保持现有 elevate/export，把 `locale` 扩展为 track：

| 参数 | 值 |
|------|-----|
| `locale` | `zh-CN` \| `en-US` \| `zh-en` |

新增（列表状态，供 UI 三按钮）：

```
GET /profiles/{id}/resume-tracks?elevation_level=elevated
→ {
    "source_locale": "zh-CN",
    "tracks": {
      "zh-CN": { "status": "ready", "draft_id": "rdft_…", "reviewer_status": "pending" },
      "en-US": { "status": "pending", "draft_id": null },
      "zh-en": { "status": "blocked", "reason": "en_not_ready" }
    }
  }
```

`POST /profiles/{id}/localize`：手动重译（用户改了源语言或对译文不满意）。

## 6. UI

优化预览顶栏 **三个互斥选项**（替换现在的两个）：

```
[ 中文简历 ]  [ 英文简历 ]  [ 双语对照 ]
```

- 未就绪：按钮 disabled + 「生成中」
- 失败：可点「重试翻译」
- 导出区跟随当前轨；双语时文案为「导出中英对照 PDF」
- 核对页不展示译文编辑（M1）；译文只出现在预览。若用户要改英文表述 → Agent「把英文 summary 改短一点」走 profile i18n patch（可 P1）

## 7. 与现有代码的差距

| 现状 | 必须改 |
|------|--------|
| 预览只有 zh / en 两按钮 | 加 bilingual |
| `get_latest_draft` 不按 locale 过滤 | 加上 `locale=` |
| Writer 直接吃原文 payload | 先 localize 再 elevate |
| 无 `payload.i18n` | ProfileMeta + i18n 块 |
| 无双语模板 | `zh-en-bilingual.html` |
| 上传后不生成第二语言 | ingest 后异步 localize + 双轨 draft |

## 8. 实施顺序

1. **查询修复**：`get_latest_draft(..., locale=)`，避免中英稿互相覆盖（现在就会踩）。
2. **源语言检测** + `payload.i18n` 结构 + `LocalizeService`。
3. Ingest/确认后后台生成 zh+en draft。
4. UI 三轨切换 + tracks 状态接口。
5. `zh-en-bilingual` 模板与导出门禁。

## 9. 验收

- 上传中文 txt → 中文预览有内容；数十秒内英文预览可开；双语 PDF 第一段中文、分页后英文。
- 上传英文 txt → 对称。
- 改源语言开关 → 重译，experiences id 仍对齐，不出现多出来的公司。
- 仅中文 ready 时，双语按钮不可点。
- Reviewer issues 按当前轨展示；双语列出两侧 issues。

## 10. 成本（用户付模型费）

每次确认大约：localize ×1（跨语言）+ writer ×2。问候/核对不触发。双语导出 **0 次额外 LLM**。
