# 档案编辑内容丢失与保存入口修复

日期：2026-10-20，Asia/Shanghai。

## 已确认的代码缺陷

1. ProfileStudioEditor 的 props 同步 effect 在照片未变化时直接返回服务端 payload，重新读取、Agent 更新等会覆盖未保存输入。
2. 编辑状态由表单自身持有；收起表单或切换步骤卸载组件后，重新展开只能获得服务端旧值。
3. 保存入口仅在长表单末尾，顶部确认档案独立调用确认接口，不先保存输入。

以上是已确认的丢失路径；不能据此断言用户这一次具体操作命中了哪一条，也不能声称已找回未提交的原始输入。

## 修复

- 新增纯函数 profile-draft 状态策略，以及 useProfileDraft。草稿由 resume-agent 页面持有；编辑器是受控表单，折叠和步骤切换不销毁草稿。
- 顶部工具栏常驻保存按钮、已保存/未保存/保存中状态；编辑器上方另有 sticky 保存入口，移除原底部唯一保存栏。
- 相同内容的重新读取不清空输入。新服务端事实与未保存内容并发时保留草稿并提示版本冲突，禁止盲目覆盖。照片单字段变动可单独吸收。
- 保存使用草稿基准版本做 CAS；旧响应不回退版本，重复保存共享进行中的请求，保存期间新输入仍保留为待保存编辑。
- 确认档案先等待保存成功，失败或仍有待处理输入就不确认、不跳转。已确认档案的进入预览入口也先保存。
- 未保存时禁用切换/新建档案；步骤栏禁止直接进入旧内容预览。
- 刷新/关闭使用 beforeunload 保护，页面链接离开前确认；支持 Ctrl/Cmd+S。此版本不声称覆盖所有浏览器 SPA 历史后退路径或浏览器进程崩溃。
- 冲突时可显式下载未保存 JSON 备份；放弃输入并加载新版本必须再次确认。下载是用户触发的恢复副本，不作为业务主存储；不自动将简历写入 localStorage/sessionStorage。

## 验证

frontend/web 内执行：

```sh
node --test tests/*.test.cjs
./node_modules/.bin/tsc --noEmit
```

结果：70 项前端测试通过；TypeScript 检查通过。新增 16 项测试覆盖状态策略、失败重试、并发请求、在途输入、冲突、离开保护和确认前保存顺序。Hook 测试使用隔离的生命周期 harness，确认入口执行实际组件事件回调；不等同于真实浏览器端到端验收。

Google Chrome 当前页面只读检查确认热更新后出现顶部「档案已保存 / 保存修改」；未向用户实际档案写入测试数据。尝试隔离 React 页面进行完整浏览器验收时，浏览器自动审批服务返回 overloaded / stream disconnected，未执行导航；没有绕过审批或换浏览器执行。临时内存验收服务已停止。

未修改后端、数据库或迁移，未重启用户服务。无法恢复此前从未提交、且已从旧表单内存丢失的文字；是否存在已保存的历史版本需要另行核实，不能把截图文字当成已恢复的数据写回。
