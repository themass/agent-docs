## 0. 边界（整份计划都遵守）

**做：** 接到现有 FastAPI / Profile / Job / Application / Agent。UI 中文；投递物继续走中/英/双语轨。

**不做：** vendor `career-ops` / `ai-job-search` 整仓；`get_jobs` 类自动投；LinkedIn/BOSS 默认爬虫；隐身面试辅助；把 `jc_profile` 改成 `cv.md`。

**已有、本计划不重复建设：** 三轨导出、reviewer 出门、`apply-pipeline`、`POST .../parse-url`、`/applications` 列表、Campaign warmup/target、coach-mock 五维。本计划加深评估与漏斗，**不削弱拔高**。

**冻结修正（2026-09-06）：** 匹配分只做建议（练手 / 主攻 / 缺口列表），**任何推荐档都允许、且默认提供拔高与导出。** career-ops「低于 4.0 不建议投」可以显示，但不能挡住改稿——练手岗更需要拔高。

## 1. 来源 → 我们要的能力

| 来源 | 借什么 | 落到 JobCome |
|------|--------|----------------|
| career-ops | 整体判断分、分数中立信号、A–H、评完必进漏斗、数字出处、Cover 只起草、零 token 发现 | `fit_score` 契约、Application 状态、Cover 导出、可选 ATS；**不**用低分阻断拔高 |
| ai-job-search | Drafter–Reviewer 串行、outcome 反哺 fit、面试绑已投材料 | reviewer 强制、`outcome` 回写、mock `draft_id` |
| jobsync / job-ops | 自托管看板、漏斗转化、跟进日期 | `/applications` 看板 + Campaign |
| Resume-Matcher | 关键词缺口解释、Cover 流程 | fit Block B + Cover skill |
| OpenResume | 四步解析算法（规则层） | ingest 增强，LLM 结构化仍为主 |
| JSON Resume | 进出口适配 | `profile` import/export，内部仍用 payload |
| reactive-resume / rendercv | 模板与 ATS 文本层 | 不换主模板引擎；审稿加「纯文本层关键词」 |
| offer-toolkit-skill | 中英 JD 解码、STAR 故事库结构 | fork 进 `skills/custom/`，写库走 MCP |

## 2. 分期（约 6 周，可插在 Phase 2 体验闭环之后、Scout 之前）

### 第 1 周 — URL 抓 JD + 匹配报告 + 照常拔高（P0）

目标：用户**粘贴招聘 URL（或正文）→ 抓取 JD → AI 算人岗匹配**；同时**一键进入按该 JD 的拔高/导出**。低匹配只提示「更适合练手 / 缺口如下」，**绝不禁用优化预览或导出。**

后端已有 `POST /jobs/profiles/{id}/parse-url`（httpx 拉公开页）和 `/fit`；缺的是前端闭环，以及 fit 从「一个分数」变成报告。

| 交付 | 改哪里 | 验收 |
|------|--------|------|
| 岗位录入 UI | 粘贴 URL **或** 正文；URL 走 `parse-url`，成功后自动 `fit` | 中文：「粘贴招聘链接」「粘贴职位描述」；失败时提示改贴正文（JS 站点抓不到） |
| 扩展 `FitScoreResponse` | `schemas/job.py`、`jc_job.fit_report` | 五维 + 缺口/硬卡 + 真实性（G 不进总分）；`recommendation` 仅文案 |
| 重写 `fit_score.md` | 匹配解释 + **可拔高方向**（对着缺口改表述，不编造经历） | `no`/`caution`/`go` 都返回 `elevate_hints[]` |
| 拔高入口 | 匹配页主按钮始终是「按该岗位优化简历」→ elevate/preview（带 `job_id`） | API：`apply-pipeline` **不**因 `recommendation=no` 拒绝 |
| JD 页展示 | 中文：匹配度、缺口、建议投/练手、真实性提示 | 无 English 按钮文案 |

来源：用户需求（URL→JD→匹配）+ career-ops A–H（报告形态，不用其「低分禁止改稿」）。

抓取范围：公开 HTML（现有 Scout-lite）。登录墙 / 纯前端渲染失败则请用户粘贴正文；Playwright 抓 JD 不进第 1 周。

### 第 2 周 — 评完必进漏斗（P0）

目标：每个评估过的岗都有状态，不是只有「点过导出」才出现在投递记录。

| 交付 | 改哪里 | 验收 |
|------|--------|------|
| Application 状态机 | `jc_application.status`：`evaluated` / `skipped` / `applied` / `interviewing` / `rejected` / `offer` | Alembic；旧行：有 `applied_at` → applied，否则 evaluated |
| fit 成功即 upsert Application | `FitScoreService` / job_service | 评完刷新 `/applications` 能看到 |
| 看板 UI | `/applications`：按状态分列 + 跟进日（note 或新字段 `follow_up_on`） | 拖拽或下拉改状态；**不**触发外发 |
| skip 理由 | 低分一键「不投」 | 计入 Campaign 统计，不污染 fit 校准 |

来源：career-ops tracker、jobsync 看板。已有 `Application.resume_variant_id` 继续绑导出稿。

### 第 3 周 — Cover / 邮件起草（P1）

目标：任意匹配档都可出一页 Cover 和一封申请邮件草稿；系统不发送。低匹配时文案强调可迁移能力，按钮不禁用。

| 交付 | 改哪里 | 验收 |
|------|--------|------|
| Cover 模板 | 与当前 locale 轨一致的 HTML（中/英，双语=中文 Cover + 分页 + 英文 Cover） | 导出按钮中文：「导出求职信」 |
| `Localize` 不管 Cover 事实 | 数字/公司名回 Profile | reviewer 扫 Cover 硬事实 |
| 邮件草稿 API | 主题 + 正文 + 附件清单；存 Application.note 或 `cover_draft` JSON | 复制到剪贴板；无 SMTP |
| 任意匹配档都可起草 | 主按钮「生成求职信」始终可点；`no` 时旁注「匹配偏低，信里会强调可迁移能力」 | 与第 1 周一致：不挡出门 |

来源：career-ops cover/email、Resume-Matcher Cover。

### 第 4 周 — 出处与面试绑版本（P1）

目标：拔高和故事不能把数字洗成已核实；模拟面看到的是投出去的那一版。

| 交付 | 改哪里 | 验收 |
|------|--------|------|
| `star_stories[].provenance` | `profile_payload.py`：`source=profile\|user\|derived-unverified` | overlay/i18n 不得把 derived 数字写进英文稿当事实 |
| reviewer 规则 | 无出处量化 → issue | ExportPanel 能看到 |
| mock 绑 `draft_id` | `/coach-agent?job_id=&draft_id=` | 题目与 highlights 来自该 draft |
| outcome 回写 | 面试结果 → Job/Application；可选校准 fit bands | 与现有 Campaign `fit_calibration` 接通 |

来源：career-ops story provenance、ai-job-search `/outcome`。

### 第 5 周 — 解析与进出口（P2，可并行）

| 交付 | 改哪里 | 验收 |
|------|--------|------|
| markitdown 可选预处理 | ingest：PDF/DOCX→MD 再进 structurer | 无二进制时跳过，不挡上传 |
| JSON Resume import | `POST /profiles/import` 映射到 payload | 不成为内部 schema |
| ATS 文本层检查 | reviewer：导出 HTML 抽纯文本 vs JD keywords | 只报告缺口，不自动塞假关键词 |

来源：markitdown、OpenResume、JSON Resume、Resume-Matcher。

### 第 6 周+ — 发现层（Phase 3，默认关）

| 交付 | 说明 |
|------|------|
| 公开 ATS 适配器 | Greenhouse / Ashby / Lever **官方 JSON**，零登录 |
| Scout 页 | 收藏 → parse → fit → 进漏斗（第 2 周状态） |
| boss-agent-cli | `extensions_config` 默认 false；只读 JD |
| 去重 | company + title + url_key |

**禁止：** JobSpy 打 LinkedIn/Indeed 默认开；get_jobs；服务端持用户招聘站 Cookie 代投。

来源：career-ops providers、boss-agent、JobSpy 仅作「不要学它的默认范围」的反面教材。

## 3. 建议实施顺序（依赖）

```
URL/正文 → 抓 JD → fit 报告 + 始终可拔高
         │
         ├──► 漏斗状态机（建议 skip，不强制）
         ├──► Cover（始终可起草）
         └──► mock 绑 draft + outcome
ingest / JSON Resume 可并行
Scout（漏斗稳定之后）
```

战役看板（PHASE2 P2-A）与第 2 周漏斗合并做：warmup/target 是 **Job.tag**，状态机是 **Application.status**，不要两套看板。

## 4. 本计划不包含

- 付费墙、社区题库、LiveKit 语音（仍按 PHASE2/路线图后置）
- LaTeX 主路径（rendercv / Awesome-CV 只作视觉参考）
- 第二套 CLI 产品

## 5. 验收总口令

内测用户可以：粘贴招聘 URL 或正文 → 看到 JD 与匹配报告 → **无论分高低都可按该岗拔高并导出** → 可选标记不投/已投 → 用当时那份稿模拟面。全程无自动提交。
