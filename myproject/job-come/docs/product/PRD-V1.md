# PRD-V1：主动跳槽工作流闭环

- **状态**：已确认，V1 上线范围
- **最后更新**：2026-10-16
- **适用范围**：产品、设计、研发、测试、发布决策

## 1. 产品定位

JC 是服务于**主动跳槽、寻求职业提升的泛知识工作者**的 Web 产品。第一批用户聚焦互联网行业的全部知识工作岗位：研发、产品、设计、运营、市场、销售、客户成功、项目/交付、数据、HR、财务、法务等；不服务蓝领工人，也不将产品局限为研发岗位工具。

产品帮助用户把真实职业经历转化为可信、可修改、可用于面试表达的求职材料，并围绕目标岗位持续准备与复盘。成功标准不是生成一份文档，而是让用户以更清晰的职业叙事、更高质量的材料和更充分的准备主动冲击目标机会。

## 2. V1 用户与核心场景

| 用户 | 典型场景 | V1 必须解决的问题 |
|---|---|---|
| 有工作经历、准备换工作的互联网知识工作者 | 手中有旧简历、项目材料与目标 JD | 快速建档，保证事实可核对，再形成针对性简历 |
| 已有目标公司或目标岗位的用户 | 需要判断简历与岗位差距、准备面试 | 将 JD 转为岗位要求与差距分析，生成练习与复盘素材 |
| 已进入面试流程的用户 | 需要沉淀真实问题并迭代回答 | 保存面试记录、个人题库、回答和反馈，重复训练 |

### 产品原则

1. **事实优先**：原始经历、用户确认和 AI 建议必须可区分；不能把推断写成事实。
2. **用户最终确认**：模型不能自行确认档案变更；涉及事实的 patch 必须由用户明确确认。
3. **允许表达拔高，不允许虚构**：优化可提升表达强度，但必须能回到真实经历，并经得起模拟面试追问。
8. **不代投递**：不替用户提交申请、填写站点或发送消息。
5. **目标岗位驱动**：匹配分数用于诊断与建议，不得阻断简历修改或导出。
6. **数据归属隔离**：账号、档案、职位、会话、导出和面试记录必须进行归属校验。

## 3. V1 交付闭环

1. **上传与建档**：上传 PDF、Word 或图片简历，解析为档案草稿。
2. **核对与确认**：用户编辑结构化档案；完成确认后，事实变更可追踪。
3. **简历优化**（步骤 3）：生成可审阅的优化版本和 `elevation_map`；每处改动标注所用的强化手段（补量化、加结果、强化主导性、明确对象、对齐岗位等），三档优化强度控制的是措辞离原文的距离，任何档位都不新增事实。
   同一步骤提供**证据补全**：系统按岗位族定位「本该有成果却没写出来」的要点，逐条向用户提问；
   用户填写的答案作为真实事实回填档案，下一次生成直接使用。
   同一步骤还提供**写作偏好**：显式切换目标岗位族，并选择最多 2 个**包装角度**
   （规模 / 主导 / 结果 / 深度 / 协作 / 岗位对齐）决定同一批事实先讲哪一面；不选则用岗位族推荐组合。
   角度只改呈现顺序与侧重，**不新增事实、不抬高动词强度**，也不放宽质检门禁。
   页面同时显示**经历覆盖度**：源档案中被生成稿漏掉的要点会被点名列出，可一键重新生成。
   我们**不以编造数字的方式让简历看起来更强**——理由与替代手段见
   [`../architecture/TECH-RESUME-WRITING.md`](../architecture/TECH-RESUME-WRITING.md) 第 3.6、11、12 节。
4. **导出前质检与导出**（步骤 4）：独立页面，先过质检（`error` 阻断、`warning` 仅提示），
   同时给出**投递前体检**（估算篇幅、要点条数与最长要点、岗位用词覆盖）和**经历覆盖度**复核；
   这两项一律为建议，不阻断导出，并提供返回步骤 3 的入口。
   通过后导出 PDF、DOCX、HTML 三种格式，内容一致。
5. **JD 解析与匹配**：粘贴 JD 或在受限条件下读取公开职位页，得到职责、要求、来源和匹配/差距分析。
6. **模拟面试**：`warmup` 可不绑定 JD；`target` 必须绑定 JD。按一题一答保存答案、反馈和最佳答案。
7. **真实面试复盘**：记录公司、岗位、日期、轮次、问题与复盘，沉淀到个人题库后可继续练习。
8. **账户与安全**：注册、登录、邮箱验证、密码重置、会话管理与资源归属校验。

## 4. V1 页面与能力边界

| 页面/入口 | 用户结果 | 关键能力 |
|---|---|---|
| `/resume-agent` | 已确认档案、优化简历与导出物 | 上传解析、三栏编辑、确认、证据补全、岗位族与包装角度选择、优化预览（强化手段 + 变更对比 + 经历覆盖度）、Agent 对话、独立导出页（质检 + 投递前体检 + 覆盖度 + PDF/DOCX/HTML） |
| `/jobs` | 结构化 JD 与匹配报告 | 粘贴/受限读取、来源记录、差距分析 |
| `/interviews`、`/bank` | 可复用的练习与题库 | 模拟、答案、反馈、真实题归档 |
| `/applications`、`/campaign` | 自己维护的目标机会与节奏 | 申请漏斗和准备节奏，不代表自动代投 |
| `/settings/account`、`/auth/*` | 可管理的用户账户 | 个人配置、链接/4 位码邮箱验证、找回/修改密码、退出登录 |

## 5. 不属于 V1

以下三项是**下一个版本**的核心方向，不能出现在 V1 已交付或验收通过的表述中：

1. LiveKit 实时语音模拟面试；
2. 手机端体验；
3. 用户使用 Zoom 或腾讯会议进行真实面试时，实时听取面试官问题并提供答案建议。

上述第三项涉及隐私、授权、平台政策、实时性和安全边界；进入研发前必须完成单独的合规、安全与交互设计评审。

## 6. V1 发布判定

V1 的代码目标是一个可上线、可让首批用户完成全闭环的版本。发布必须同时满足：核心流程可用、真实依赖环境可连通、权限边界有效、导出质量通过、监控/备份/回滚已演练。具体门禁和当前状态以 [`../operations/QA-TESTING.md`](../operations/QA-TESTING.md) 为准。
