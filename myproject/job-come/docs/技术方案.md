## 0. 工程原则（冻结）

### 0.0 硬标准摘要

| 项 | 冻结 |
|----|------|
| Python | **3.11+**（推荐 3.12） |
| LLM Trace | **Langfuse Cloud** + LiteLLM callback |
| 复用 | 工具进 **`jobcome/common/`**（后端）、**`apps/web/lib/`**（前端）；禁止散落 `util.py` |

详见 [工程规范.md](工程规范.md)。

### 0.1 面向对象

| 原则 | 要求 |
|------|------|
| **类封装行为** | 业务在 Service / Adapter / Store 类中 |
| **文件是实现细节** | 模板、Skill 正文经 `SkillCatalog`、`ResumeRenderEngine` 访问 |
| **配置与任务对象化** | `AppConfig`、`AgentTask`、`ExportJob` |

### 0.2 高内聚、低耦合、边界清晰

```text
apps/web/          产品 UI（简历 Agent 页、面试辅导 Agent 页）
jobcome/common/    跨域可复用（trace、ids、crypto、logging）；禁止散落 util
jobcome/api/       HTTP → Service
jobcome/services/  业务编排
jobcome/models/    数据结构
jobcome/stores/    MySQL / S3
jobcome/adapters/  DeerFlow、LiveKit、导出、异步 ASR（上传文件）
jobcome/livekit/   LiveKit AgentWorker 胶水（不改 livekit-agents 源码）
jobcome/agent/     Skill、MCP Server（对接 deerflow harness，不改 deer-flow 核心）
```

**跨模块**：只传 `id` 或 DTO；Store 不跨模块直接调用。

### 0.3 DeerFlow 底座策略（冻结）

| 原则 | 含义 |
|------|------|
| **不改 deer-flow 源码** | 上游 [deer-flow](https://github.com/bytedance/deer-flow) 的 **`deerflow` harness 包**当黑盒；升级 = pin 版本号 |
| **不用 IM 产品层** | **不**引入 `deer-flow/app/channels`；C 端入口仍是 JobCome Web + FastAPI |
| **只二次封装** | JobCome 通过 **`SKILL.md` + MCP Server + `extensions_config.json`** 扩展 |
| **跟社区同步** | `pyproject.toml` pin `deerflow`；CI 冒烟 INGEST + MOCK 两条 Skill |
| **业务真相在 JobCome** | 档案、题库、导出在 **MySQL + S3**；LangGraph thread 只做对话态 |

| DeerFlow 擅长 | JobCome 自己做 |
|-------------|----------------|
| LangGraph Agent 循环、middleware、MCP、Skill 目录 | 结构化档案、面试库、抽题、PDF/Word 导出 |
| Run API / checkpointer（Postgres 多副本） | Web UI、**账户/访客**、练手/目标业务规则 |
| `task` 子 Agent、tool_search | 简历编辑器、模拟面试产品流程 |

未来 **手机录音 / 实时语音**：见 [§1.3 LiveKit](#13-实时语音-livekit)（M2+）；异步上传转写仍走 `AudioTranscriber`。

### 1.3 实时语音（LiveKit）

**定位**：LiveKit 只管 **实时音视频传输 + VAD/STT/TTS 管线**；**不改 LiveKit 上游**。认知与 Tool 仍走 **DeerFlow 文本轮次** + JobCome MCP（与 agentmemory 文档中「LiveKit + DeerFlow」一致）。

```text
┌──────────── Web / Mobile ────────────┐
│  文字模式          │  语音模式（M2+）   │
│  SSE / Chat UI     │  LiveKit Room UI  │
└─────────┬──────────┴─────────┬─────────┘
          │                    │ WebRTC
          ▼                    ▼
   DeerFlowSessionClient    LiveKit Server（黑盒）
          │                    │
          │                    ▼
          │            jobcome/livekit/AgentWorker（自研胶水）
          │                    │ 每轮：音频→STT→文本
          └──────────► DeerFlow run_conversation（文本）
                              │ MCP
                              ▼
                         JobCome Services / Stores
                              │ 文本回复
          ◄───────────────────┘
                    TTS → 音频回房间
```

**三层分工（均不 fork 上游）**：

| 层 | 组件 | 职责 |
|----|------|------|
| **媒体** | [LiveKit](https://livekit.io/) + [livekit-agents](https://github.com/livekit/agents) | Room、Token、WebRTC、STT/TTS、打断 |
| **认知** | DeerFlow Gateway | Skill、多轮对话、调 MCP、会话记忆 |
| **业务** | JobCome | 档案、题库、导出、练手规则 |

**原则**：

1. **不在 LiveKit Worker 里写业务 SQL**；Worker 只调 `DeerFlowSessionClient` 或 JobCome MCP。
2. **不在 LiveKit 音频层直连 agentmemory**；记忆同步在 DeerFlow **文本轮次**前后（prefetch / sync_turn）。
3. **与文字模式共用** `InterviewCoachService` / `ResumeService`；仅 `InteractionChannel` 不同。

**交互通道抽象（JobCome 内）**：

```python
class InteractionChannel(ABC):
    @abstractmethod
    async def start(self, spec: CoachSessionSpec) -> SessionHandle: ...

    @abstractmethod
    async def close(self, handle: SessionHandle) -> None: ...


class TextInteractionChannel(InteractionChannel):
    """MVP：DeerFlow SSE / Gateway API。"""
    def __init__(self, deerflow: DeerFlowSessionClient): ...


class VoiceInteractionChannel(InteractionChannel):
    """M2+：LiveKit Room + AgentWorker。"""
    def __init__(
        self,
        livekit: LiveKitRoomService,
        deerflow: DeerFlowSessionClient,
    ): ...
```

| 产品场景 | MVP | M2+ LiveKit |
|----------|-----|-------------|
| 简历优化 | 文字对话改稿 | 可选语音口述经历，STT 后 `profile_patch` |
| 模拟面试 | 文字模拟 | **语音模拟面**（主场景）：考官 TTS + 用户语音答 |
| 真面复盘 | 手填 / 文字引导记题 | 房间录音 → 结束转写 → `interview_save` |
| 手机端 | — | LiveKit SDK 进同一 Room |

**LiveKit 相关包（仅 JobCome 仓库）**：

```text
src/jobcome/
  adapters/
    livekit_room_service.py   # 签发 token、创建/销毁 room
  livekit/
    agent_worker.py           # livekit-agents 入口，胶水层
    stt_tts_config.py         # 厂商配置对象
apps/web/
  components/VoiceCoachRoom/  # @livekit/components-react
```

**API 补充（M2+）**：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/coach/sessions/{id}/voice/token` | 返回 LiveKit `accessToken` + `roomName` |
| POST | `/coach/sessions/{id}/voice/end` | 结束房间；触发转写归档（若录制） |

**节奏**：MVP **不做 LiveKit**（文字 + DeerFlow 先跑通飞轮）；W9–W10 后可开 LiveKit spike（仅面试辅导「模拟面」语音模式）。

## 2. 两大 Agent 产品页

### 2.1 简历优化 Agent 页

**产品形态**：左侧（或分栏）**结构化简历编辑器** + 右侧 **DeerFlow 对话**；用户可 **聊天改稿**，也可 **手动改字段**；最终 **导出 PDF / Word**。

```text
┌──────────────────────────────────────────────────────────────┐
│ 简历优化                                                    │
├────────────────────────┬─────────────────────────────────────┤
│ ProfileEditor          │ ResumeAgentChat (DeerFlow Session)    │
│ · 经历/教育/技能表单    │ · Skill: jobcome-resume-coach       │
│ · 用户手动 edit        │ · 根据 JD 建议拔高句                 │
│ · 与 Profile 实时同步   │ · 调 MCP: profile_patch, elevate    │
├────────────────────────┴─────────────────────────────────────┤
│ [确认档案]  [导出 PDF]  [导出 Word]  ← JobCome API，非 DeerFlow │
└──────────────────────────────────────────────────────────────┘
```

**数据流**：

| 动作 | 负责方 |
|------|--------|
| 用户手改字段 | Web → `ProfileService.update()` → `ProfileStore` |
| Agent 建议改某段 | DeerFlow → MCP `profile_patch` → `ProfileService` → SSE 推前端刷新编辑器 |
| 拔高 / 审稿 | DeerFlow Skill `resume-writer` / `resume-reviewer`（两次 session 或同 session 不同 skill） |
| 导出 | 用户点导出 → `ResumeService.export()` → `ResumeRenderEngine` → S3 下载链接 |

**关键类**：

- `ProfileService` — 档案 CRUD、确认、版本
- `ResumeService` — 触发 DeerFlow 拔高任务、合并 `ResumeDraft`
- `DeerFlowSessionClient` — 创建 session、流式 SSE 转发 Gateway
- `ResumeRenderEngine` — PDF/DOCX

### 2.2 面试辅导 Agent 页

**产品形态**：一种 **辅导工作台**，多种 **模式**（Tab 或向导），底层共用 `InterviewStore` + DeerFlow Coach Skill。

| 模式 | 用户目标 | DeerFlow Skill | JobCome 逻辑 |
|------|----------|--------------|--------------|
| **题库互动** | 练单题、看点评 | `jobcome-coach-drill` | 从 `InterviewStore` 抽题；`MockQuestionPlanner` |
| **模拟面试** | 练手/目标高压面 | `jobcome-coach-mock` | 先 planner 组卷（库内+补充）再开多轮对话 |
| **记真题** | 真面后归档 | `jobcome-coach-archive` | 对话引导录入 → MCP `interview_save` |
| **参考答法** | 迭代最佳答案 | `jobcome-coach-answer` | 对比 `AnswerAttempt` 历史 |
| **（M2）语音模拟面** | 实时语音练面 | `jobcome-coach-mock` + **LiveKit** | `VoiceInteractionChannel` + 同 Mock 组卷 |
| **（M2）语音复盘** | 真面录音 | 同上 | 房间结束 → STT 全文 → `interview_save` |

```text
用户选模式 → InterviewCoachService.start(mode, job_id?)
    → MockQuestionPlanner.draw()（若需要）
    → DeerFlowSessionClient.start(skill_id, context_payload)
    → 流式对话
    → MCP 写 AnswerAttempt / InterviewRecord
```

**关键类**：

- `InterviewCoachService` — 模式路由、session 上下文组装
- `MockQuestionPlanner` — 抽库优先级（PRD）
- `InterviewService` — 记题、题库、最佳答法
- `DeerFlowSessionClient` — 与简历页共用适配器

### 2.3 DeerFlow 与 JobCome 职责切分

```text
DeerFlow 管：Agent 循环、Skill、MCP tool 调用、thread 对话态
JobCome 管：档案 JSON、题库、导出文件、练手达标、页面状态、账户/访客
```

## 3. DeerFlow 集成（不改 harness 源码）

> **Skill + MCP 完整整理**：[`DeerFlow-Agent底座.md`](DeerFlow-Agent底座.md)

### 3.1 扩展方式（仅 JobCome 仓库内）

| 扩展点 | 路径 | 作用 |
|--------|------|------|
| **Skills** | `jobcome/skills/public/` | `resume-writer`、`coach-mock` 等 `SKILL.md` |
| **MCP Server** | `jobcome/agent/mcp/` | `profile_get`、`bank_search`… |
| **配置** | `deploy/deerflow/extensions_config.example.json` | `mcpServers.jobcome` |

### 3.2 `DeerFlowSessionClient`（唯一 import deerflow 的适配层）

```python
class DeerFlowSessionClient:
  """封装 run_agent / thread SSE；业务层只认此类。"""

  async def start_session(
      self,
      *,
      user_id: str,
      thread_id: str,
      skill_hint: str | None,
      metadata: dict,
  ) -> SessionHandle: ...

  async def stream_events(self, handle: SessionHandle) -> AsyncIterator[ChatEvent]: ...

  async def run_once(self, *, skill: str, context: dict) -> ResumeDraft: ...
```

业务 Service **禁止** `import deerflow` 除 `adapters/deerflow_session_client.py` 外。

### 3.3 MCP Tool（DeerFlow 调 JobCome 业务）

| Tool | 调用 |
|------|------|
| `profile_get` | `ProfileStore.get` |
| `profile_patch` | `ProfileService.apply_patch` |
| `bank_search_questions` | `InterviewStore.search` |
| `interview_save` | `InterviewService.archive` |
| `answer_save_attempt` | `InterviewService.save_attempt` |

MCP Server 内注入 `user_id`（来自 Run **metadata**，JobCome API 写入），**不信任模型传入的 tenant**。

### 3.4 鉴权模型：Actor + 能力门禁

请求在 API 层解析为 **`Actor`**（二选一），业务 Service 只认 `Actor`，不直接读 Cookie。

```text
                    ┌─────────────────────────────────────┐
                    │  Request                             │
                    │  Cookie: jc_guest | jc_session     │
                    └──────────────────┬──────────────────┘
                                       ▼
                    ┌─────────────────────────────────────┐
                    │  AuthMiddleware → Actor              │
                    │  · GuestActor(guest_session_id)      │
                    │  · UserActor(user_id, session_id)    │
                    └──────────────────┬──────────────────┘
                                       ▼
                    ┌─────────────────────────────────────┐
                    │  require_capability("export")        │
                    │  require_capability("agent_chat")    │
                    └─────────────────────────────────────┘
```

| Actor | 识别方式 | 默认能力 |
|-------|----------|----------|
| `GuestActor` | HttpOnly **`jc_guest`** Cookie；首访无 Cookie 时 `POST /guest/session` 创建 | `view`, `profile_upload`, `profile_edit`, **`elevate_preview`** |
| `UserActor` | HttpOnly **`jc_session`** Cookie（登录后） | 上述 + `export`, `agent_chat`, `coach`, `settings` |

**规则：**

- 同时带 `jc_session` 时 **以 User 为准**；`jc_guest` 仅在未登录时生效。
- `ProfileService` 校验：`profile.owner` 必须匹配当前 `Actor`（`guest_session_id` 或 `user_id`）。
- **拔高预览**（单次任务）：`Depends(get_actor)` + `elevate_preview`；**Agent 多轮对话 / Export**：`Depends(require_user)`。

### 3.2 访客认领（登录不丢稿）

```text
访客上传/编辑
    → Profile(guest_session_id=gst_xxx)
用户点「登录」→ POST /auth/login { email, password }
    → AuthService.login()
    → GuestMigrationService.claim(gst_xxx, usr_xxx)
         ├─ 账户无 Profile → UPDATE profile SET user_id, guest_session_id=NULL
         ├─ 账户有 Profile + 访客有草稿 → 409 merge_conflict + 两档案摘要
         └─ 成功 → 清除 `jc_guest` Cookie
    → 返回 { user, activeProfileId, mergeConflict? }
```

`GuestMigrationService`（单独类，事务内完成）：

1. 锁定 `guest_session` 行（`FOR UPDATE`）
2. 查询访客 Profile 列表（MVP 最多 1 份活跃）
3. 按产品规则认领或返回冲突
4. S3 对象 key 不变，只改 `profiles.user_id` 元数据
5. `guest_sessions.claimed_by_user_id` 标记，防重复认领

**注册** `POST /auth/register` 同样在最后一步调用 `claim`。

### 3.3 前端 Header 与登录态

完整说明：[前端架构与鉴权.md](前端架构与鉴权.md)（架构、部署、REST/SSE、Cookie `jc_guest`/`jc_session`）。

```text
apps/web/
├── components/layout/AppHeader.tsx      # 登录/注册 | 用户菜单
├── lib/auth/
│   ├── AuthProvider.tsx                 # React Context
│   ├── useAuth.ts                       # actor, user, capabilities

```

**`GET /auth/context` 响应（Header 唯一真相源）：**

```json

  "user": null,
  "capabilities": ["view", "profile_upload", "profile_edit"],
```

## 5. API 概要

### 5.1 账户与鉴权（W0）

| 场景 | API | 鉴权 | Service |
|------|-----|------|---------|
| 登录态（Header） | `GET /auth/context` | 可选 Cookie | `AuthService.context` |
| 创建访客 Session | `POST /guest/session` | 无 | `GuestSessionStore.create` |
| 注册 | `POST /auth/register` | 可选 `jc_guest` Cookie | `AuthService.register` → `GuestMigrationService.claim` |
| 登录 | `POST /auth/login` | 可选 `jc_guest` Cookie | 同上 |
| 登出 | `POST /auth/logout` | User | `AuthService.logout` |
| 忘记密码 | `POST /auth/forgot-password` | 无 | 发重置邮件 |
| 重置密码 | `POST /auth/reset-password` | token | token 校验 |
| 改密 | `POST /auth/change-password` | User | 需已登录 |
| 合并冲突决议 | `POST /auth/resolve-merge` | User | `keep_guest` \| `keep_account` |
| 当前用户 | `GET /users/me` | User | `UserService.get_me` |
| 个人信息 | `PATCH /users/me/profile-meta` | User | 昵称、语言、拔高默认 |
| 数据导出 | `POST /users/me/export` | User + `export` | 异步 zip |
| 删业务数据 | `DELETE /users/me/data` | User | 保留账户 |
| 注销账号 | `DELETE /users/me` | User | 级联逻辑删除 |

**密码：** bcrypt/argon2；重置 token 哈希入库、1h 过期。邮件经 `EmailAdapter`（开发环境可 log 到控制台）。

### 5.2 业务 API（能力标注）

| 页面 | API | 鉴权 | Service |
|------|-----|------|---------|
| 简历优化 | `POST /profiles/upload` | **Actor**（Guest/User） | `ProfileService` |
| 简历优化 | `GET /profiles/{id}` | **Actor** 属主校验 | `ProfileService` |
| 简历优化 | `PATCH /profiles/{id}` | **Actor** + `profile_edit` | 手动编辑 |
| 简历优化 | `POST /profiles/{id}/elevate` | **Actor** + `elevate_preview` | `ResumeService.elevate`（DeerFlow Writer **单次**调用，非 chat session） |
| 简历优化 | `GET /profiles/{id}/elevate/preview` | **Actor** + 属主校验 | 当前档位 `ResumeDraft` 预览 |
| 简历优化 | `POST /resume-agent/sessions` | **User** + `agent_chat` | `ResumeService.start_agent_session` |
| 简历优化 | `GET /resume-agent/sessions/{id}/events` | **User** | SSE |
| 简历优化 | `POST /profiles/{id}/export` | **User** + `export` | `ResumeService.export` |
| 面试辅导 | `POST /coach/sessions` | **User** + `coach` | `InterviewCoachService.start` |
| 面试辅导 | `POST /coach/sessions/{id}/messages` | **User** | 用户作答 |
| 面试辅导 | `POST /interviews` | **User** | `InterviewService.archive` |
| 题库 | `GET /bank/questions` | **User** | `InterviewService` |

**FastAPI 依赖示例：**

```python
def get_actor(request: Request) -> Actor: ...
def require_user(actor: Actor = Depends(get_actor)) -> UserActor: ...
def require_capability(cap: str):
    def _dep(actor: Actor = Depends(get_actor)): ...
    return _dep
```
DeerFlow MCP **仅**在 `UserActor` 的 Agent Session 中启动；`user_id` 写入 session metadata，不信任模型参数。

## 7. 风险

| 风险 | 缓解 |
|------|------|
| DeerFlow 偏 IM/CLI，Web 需自建 UI | 本来就要 Web 产品页；只借 Agent 引擎 |
| upstream 破坏性升级 | pin 版本 + CI 冒烟 + Skill 契约测试 |
| 双写混乱（编辑器 vs Agent） | `ProfileService` 单一写入口；patch 带 `source: user|agent` |
| 导出质量 | `ResumeRenderEngine` 独立于 DeerFlow |
| LiveKit 延迟/成本 | MVP 文字先行；语音仅面试模式；可配置 STT/TTS 厂商 |
| 双通道会话状态 | `CoachSession` 统一 `session_id`；文字/语音互斥或升级同一 handle |
| 访客草稿认领失败 / 冲突 | `GuestMigrationService` 事务 + 409 冲突 UI；E2E 覆盖 US-0.8 |
| 访客刷上传 / 刷拔高 | IP + `guest_session` 限流；拔高预览每日配额；未认领 30 天清理 |

## 8. 云主机部署与 DeerFlow 配置（C 端）

详见 [`DeerFlow-Agent底座.md` §6](DeerFlow-Agent底座.md#6-部署要点c-端云主机)。摘要：

```text
Internet → Nginx → jobcome-api（公网，鉴权 + SSE）
                 → jobcome-web
                 → deerflow run_agent（内网，可与 api 同进程 MVP）
                 → PostgreSQL（业务 + LangGraph checkpointer）
                 → extensions_config.json + skills 卷
```

| 配置 | 文件 |
|------|------|
| MCP | [`deploy/deerflow/extensions_config.example.json`](../deploy/deerflow/extensions_config.example.json) |
| Skills | `job-come/skills/public/` 挂载到 DeerFlow `skills/` |
| **不开 IM** | 不使用 `deer-flow/app/channels` |

**调用路径：** `DeerFlowSessionClient` → `run_agent` / `thread_id` stream；Run **metadata** 带 `user_id`、`profile_id`。
