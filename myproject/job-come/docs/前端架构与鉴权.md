## 1. 前端架构（冻结）

### 1.1 技术选型

| 项 | 选型 | 说明 |
|----|------|------|
| 框架 | **Next.js 15（App Router）** | 不用 Pages Router |
| 语言 | TypeScript | 严格模式 |
| 样式 | Tailwind CSS + **shadcn/ui** | 组件可复制到仓库 |
| 状态 | **React Context**（鉴权）+ **TanStack Query**（服务端数据） | M1 不用 Redux |
| 表单 | react-hook-form + zod | 与 API 校验对齐 |
| Agent 流式 | **浏览器原生 EventSource（SSE）** | 不经 WebSocket（M1） |

### 1.2 架构形态：**SPA 壳 + 直连 API（无 Next BFF）**

```text
┌─────────────────────────────────────────────────────────┐
│  apps/web（Next.js）                                     │
│  · 只负责 UI、路由、客户端交互                            │
│  · 业务 API 全部打 FastAPI，不在 Next 里写业务逻辑        │
│  · 不在 localStorage 存 token（见 §4）                    │
└───────────────────────────┬─────────────────────────────┘
                            │
              credentials: 'include'（Cookie 自动带上）
                            │
┌───────────────────────────▼─────────────────────────────┐
│  jobcome-api（FastAPI）/api/v1/*                           │
│  · 鉴权、Profile、Coach、SSE 代理 DeerFlow                 │
└─────────────────────────────────────────────────────────┘
```

**为什么不用 Next.js 当 BFF：**

- 账户、访客认领、MCP 租户都在 Python 侧，**单一 API 边界**更清晰。
- DeerFlow、导出、队列已在 FastAPI；前端不再绕一层 Server Actions。
- M1 开发时 `next dev` + `uvicorn` 两个进程即可。

**可选（M2+）：** Next `rewrites` 仅做开发代理，生产由 Nginx 统一反代（见 §2）。

### 1.3 目录结构

```text
apps/web/
├── app/
│   ├── layout.tsx                 # 根布局 + AuthProvider
│   ├── page.tsx                   # 首页 / 仪表盘
│   ├── auth/
│   │   ├── login/page.tsx
│   │   ├── register/page.tsx
│   │   └── forgot-password/page.tsx
│   ├── resume-agent/page.tsx      # 访客可进
│   ├── interview-coach/           # layout 内校验 capabilities
│   ├── profile/
│   ├── jobs/
│   ├── settings/
│   └── api/                       # ❌ M1 不放业务 Route Handler
├── components/
│   ├── layout/AppHeader.tsx
│   ├── auth/LoginDrawer.tsx
│   └── ...
├── lib/
│   ├── api/
│   │   ├── client.ts              # fetch 封装（见 §3）
│   │   ├── auth.ts
│   │   ├── profile.ts
│   │   └── coach.ts
│   └── auth/

│       └── useCapabilities.ts
├── middleware.ts                  # 仅做轻量跳转提示，非安全边界

```

### 1.4 路由与权限（UI 层）

| 类型 | 路由示例 | 前端行为 |
|------|----------|----------|
| 公开 | `/`, `/auth/*`, `/resume-agent` | 直接渲染 |
| 能力门禁 | 导出按钮、Agent 面板 | 读 `capabilities`，disabled + 登录抽屉 |
| 登录专属 | `/interview-coach`, `/settings` | 无 `agent_chat` 时 redirect `/auth/login?next=...` |

**安全边界在 API**：前端隐藏按钮只是体验；**403 以后端为准**。

## 2. 部署：前后端是否独立？

### 2.1 结论：**独立构建、独立进程；生产同域访问**

| 环境 | 前端 | 后端 |
|------|------|------|
| **开发** | `pnpm dev` → `:3000` | `uvicorn` → `:8000` |
| **生产** | Next **standalone** 镜像 → `:3000` | FastAPI 镜像 → `:8000` |
| **用户浏览器** | 只访问 **一个域名** | 见下方 Nginx |

```text
                    https://jobcome.example.com
                              │
                         Nginx (TLS)
                    ┌─────────┴─────────┐
                    │                   │
              /  → web:3000      /api/v1/ → api:8000
              (Next.js)              (FastAPI)
                    │                   │
                    └─────────┬─────────┘
                              │
                    PostgreSQL · Redis · S3
                    DeerFlow worker（内网，浏览器不可见）
```

### 2.2 同域的好处（登录态）

- Cookie 设 `Domain=jobcome.example.com`、`Path=/`，**前后端共享**，无需 CORS 带凭证的跨域麻烦。
- API 基址生产环境用 **相对路径** `/api/v1`（见 §3.1）。

### 2.3 开发环境代理

`next.config.ts`：

```typescript
async rewrites() {
  return [
    { source: '/api/v1/:path*', destination: 'http://127.0.0.1:8000/api/v1/:path*' },
  ];
}
```

浏览器请求 `localhost:3000/api/v1/...`，Next 转发到 FastAPI；Cookie 仍在 `localhost` 下生效。

### 2.4 不做的部署方式（M1）

| 不做 | 原因 |
|------|------|
| 前端直连 `api.xxx.com` 跨域 + JWT localStorage | Cookie 同域更简单、更安全 |
| Next Route Handler 代理全部 API | 重复一层、难维护 |
| DeerFlow 端口暴露给浏览器 | Agent 只经 FastAPI SSE |

## 3. 前后端如何交互

### 3.1 API 约定

| 项 | 约定 |
|----|------|
| 前缀 | **`/api/v1`** |
| 格式 | JSON（`Content-Type: application/json`） |
| 鉴权 | **HttpOnly Cookie**，`fetch(..., { credentials: 'include' })` |
| 错误 | `{ "error": { "code": "...", "message": "..." } }` + HTTP 状态码 |
| 分页 | `?cursor=` / `?limit=`（M1 列表页按需） |

**基址：**

```typescript
// lib/api/client.ts
export const API_BASE =
  process.env.NEXT_PUBLIC_API_BASE ?? '/api/v1';
```

生产不设 `NEXT_PUBLIC_API_BASE` → 走同域 `/api/v1`。  
本地也可设 `http://127.0.0.1:8000/api/v1`（需 FastAPI 配 CORS + credentials，**不推荐**，优先 rewrites）。

### 3.2 两类调用

#### A. 普通 REST（档案、设置、记题表单）

```text
浏览器  POST /api/v1/profiles/upload  (multipart)
        PATCH /api/v1/profiles/{id}
        POST  /api/v1/auth/login
              Cookie 自动附带
        ← JSON
```

封装示例：

```typescript
export async function api<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${API_BASE}${path}`, {
    ...init,
    credentials: 'include',
    headers: {
      'Content-Type': 'application/json',
      ...init?.headers,
    },
  });
  if (!res.ok) throw await parseApiError(res);
  return res.json();
}
```

#### B. Agent 流式（SSE）

```text
浏览器  POST /api/v1/resume-agent/sessions        → { sessionId }
        GET  /api/v1/resume-agent/sessions/{id}/events   (SSE)
              Cookie 自动附带
        ← event: token | tool | done
```

```typescript
const es = new EventSource(
  `${API_BASE}/resume-agent/sessions/${sessionId}/events`,
  { withCredentials: true }  // 若浏览器支持；否则 fetch-stream 备选
);
```

**链路：**

```text
EventSource → FastAPI ResumeService → DeerFlowSessionClient.stream
           → 解析 DeerFlow 事件 → 转成统一 SSE 格式 → 前端逐字渲染
```

面试辅导同理：`/api/v1/coach/sessions/{id}/events`。

### 3.3 核心 API 一览（前端视角）

| 场景 | 方法 | 路径 |
|------|------|------|
| 登录态 | GET | `/auth/context` |
| 注册 | POST | `/auth/register` |
| 登录 | POST | `/auth/login` |
| 登出 | POST | `/auth/logout` |
| 访客 Session | POST | `/guest/session`（首访无 Cookie 时） |
| 上传简历 | POST | `/profiles/upload` |
| 改档案 | PATCH | `/profiles/{id}` |
| 拔高预览 | POST | `/profiles/{id}/elevate` |
| 导出 | POST | `/profiles/{id}/export` |
| 开 Agent | POST | `/resume-agent/sessions` |
| Agent 流 | GET | `/resume-agent/sessions/{id}/events` |
| 模拟 | POST | `/coach/sessions` |
| 作答 | POST | `/coach/sessions/{id}/messages` |

### 3.4 TanStack Query 用法（建议）

| 数据 | Query Key | 刷新时机 |
|------|-----------|----------|
| 登录态 | `['auth','context']` | 登录/登出/注册后 `invalidate` |
| Profile | `['profile', id]` | PATCH / Agent patch 后 |
| 题库列表 | `['bank', filters]` | 记题提交后 |

**登录态不用持久化到 localStorage**；每次进 App `AuthProvider` 拉一次 `/auth/context`。

## 4. 登录态设计（冻结）

### 4.1 原则

| 原则 | 做法 |
|------|------|
| **不用 JWT 放 localStorage** | 防 XSS 偷 token |
| **会话在服务端** | Redis（推荐）或 PostgreSQL `sessions` 表 |
| **浏览器只持 Cookie ID** | HttpOnly + Secure(生产) + SameSite=Lax |
| **权限以后端为准** | `capabilities` 由 API 计算下发 |

### 4.2 两类 Cookie

| Cookie 名 | 何时设置 | 内容 | 有效期 |
|-----------|----------|------|--------|
| **`jc_guest`** | 首访或 `POST /guest/session` | 访客 Session ID（随机，服务端存） | 30 天 |
| **`jc_session`** | 登录/注册成功 | 用户 Session ID（随机，服务端存 `user_id`） | 7 天滑动续期（可配置） |

属性（生产）：

```http
Set-Cookie: jc_session=sess_xxx; Path=/; HttpOnly; Secure; SameSite=Lax
```

**同时存在时：** 以 **`jc_session`（已登录）为准**；`jc_guest` 在 `claim` 成功后清除。

### 4.3 服务端 Session 存储

```text
Redis Key:  session:sess_xxx  →  { user_id, created_at, expires_at }
Redis Key:  guest:gst_xxx     →  { created_at, expires_at }

或 PostgreSQL sessions 表（MVP 可二选一，推荐 Redis）
```

密码重置、邮箱验证用 **一次性 token**（哈希存库，1h 过期），**不走 Session Cookie**。

### 4.4 登录 / 注册 / 登出流程

```mermaid
sequenceDiagram
    participant B as 浏览器
    participant W as Next.js
    participant A as FastAPI
    participant R as Redis

    Note over B,R: 首访
    B->>A: GET /auth/context (无 Cookie)
    A->>A: 创建 GuestSession
    A-->>B: Set-Cookie jc_guest + context(actor=guest)

    Note over B,R: 登录
    B->>A: POST /auth/login {email,password} + jc_guest
    A->>R: 写入 session:sess_xxx
    A->>A: claim_guest_assets
    A-->>B: Set-Cookie jc_session; 清除 jc_guest
    A-->>B: { user, activeProfileId }
    B->>W: invalidate auth query; 刷新 UI

    Note over B,R: 登出
    B->>A: POST /auth/logout
    A->>R: 删除 session
    A-->>B: 清除 jc_session Cookie
```

### 4.5 `GET /auth/context`（前端唯一真相源）

```json
{
  "actor": "guest",
  "user": null,
  "capabilities": [
    "view",
    "profile_upload",
    "profile_edit",
    "elevate_preview"
  ],
  "activeProfileId": "prof_xxx",
  "mergeConflict": null
}
```

已登录示例：

```json
{
  "actor": "user",
  "user": {
    "id": "usr_xxx",
    "email": "u@example.com",
    "displayName": "张三"
  },
  "capabilities": [
    "view",
    "profile_upload",
    "profile_edit",
    "elevate_preview",
    "export",
    "agent_chat",
    "coach",
    "settings"
  ],
  "activeProfileId": "prof_xxx",
  "mergeConflict": null
}
```

### 4.6 前端 AuthProvider（行为）

```text
1. App 挂载 → GET /auth/context（credentials: include）
2. 写入 Context：{ actor, user, capabilities, activeProfileId, isLoading }
3. AppHeader 根据 actor 显示「登录/注册」或用户菜单
4. 导出/Agent 组件：capabilities.includes('export') ? enabled : 打开 LoginDrawer
5. login() 成功 → 再拉 context → router.refresh()
6. 若 mergeConflict → 弹 MergeConflictModal → POST /auth/resolve-merge
```

### 4.7 Next.js middleware（可选、非安全边界）

```typescript
// 仅改善 UX：未登录访问 /interview-coach 时重定向
// 真正拦截仍靠 API 401/403
export function middleware(request: NextRequest) {
  // 可读 jc_session 是否存在（HttpOnly 在 middleware 可读 cookie 名但不应解析业务）
}
```
