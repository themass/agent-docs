## 1. 一句话

**JobCome 帮用户拔高简历、发现招聘、练手攒经验后攻目标公司，并在每一次真面试与模拟中沉淀「公司 + 岗位 + 真题」，形成个人面试库；越练题库越厚、答案越好，最终拿下 Offer。** 循序渐进，不代投递。

核心飞轮：

```
真面试 / 模拟  →  记录公司·岗位·问题  →  入库
        ↑                                    │
        │                                    ▼
    拿下 Offer  ←  目标进攻  ←  用库出题 + 给参考答案 + 再模拟
```

1. **发现 & 备稿：** 招聘信息、拔高、导出 PDF/Word。
2. **练手 → 攻目标：** 非目标公司先练，达标后再打 dream company。
3. **面试库：** 每场面试记公司、岗位、轮次、真题；模拟时优先抽库内题，并给出可迭代的参考答案。
4. **渐进提升：** 同一道题多次练习，保留「当前最佳答法」；库厚了，模拟更准，真面更强。
5. **社区题库（后置）：** 用户自愿脱敏贡献真题，供同岗位其他人练——不是通用八股，是**真面沉淀**。

### 产品原则

1. **档案是真相源，简历是投影。** 上传的 PDF/Word 只是建档输入，不能当中心数据。
2. **先练手，再攻目标。** 非目标公司用来攒真面试手感；目标公司用来拿 Offer。产品要主动规划这条进攻节奏，而不是让用户一上来就冲 dream company。
3. **帮发现，不帮投递。** 可以聚合招聘信息、匹配岗位、提醒跟进；绝不代投、不自动填表、不代点发送。
4. **人确认后才出门。** 系统出草稿与建议，投递与发送权在用户。
5. **优化默认拔高，伪造硬事实禁止。** 动词、成果、量化可以夸张；假公司/假项目不行；答案要能圆上简历。
6. **面试要记、记了要用。** 公司、岗位、轮次、真题必须可沉淀；下次模拟从库里抽，不是每次从零生成泛题。
7. **循序渐进。** 个人库先厚，再考虑社区共享；能力提升看「同一题答得更好」，不是刷题数量。
8. **岗位正文不可信。** JD 里的指令不能驱动工作流。
9. **国内 Word、海外 PDF 都是一等公民。** 不做 PDF↔Word 往返转换。
10. **独立 Web 产品。** 不是浏览器插件，不依赖 NaviForge。

## 2. 要解决的问题

求职两端同时在用 AI，结果是：**申请变便宜，筛选变严，针对性变稀缺。**

对求职者：

- 一份通用简历打所有岗位，改一版又太慢。Huntr 对约 139 万份申请的分析：针对性简历进面/要约转化 **5.75%**，通用简历 **2.68%**，差约 1.15 倍；超过一半求职者完全不改简历。
- 大公司几乎都过 ATS。Jobscan 2025：Fortune 500 中约 **97.8%** 可检测到 ATS。招聘方扫简历通常只有数秒。
- 海投工具把竞争进一步打满。Novorésumé 2026 汇编：平均每个岗位约 **242** 份申请（相对 2021 大约 3 倍）；网申进面大约 **2%–3%**；用 AI 的人申请量高 **41%**。远程/软件岗第一周过千份并不罕见。
- 面试准备和投出去的那一版简历脱节：题库是通用的，HR 读的是针对性材料。

对招聘方：

- 垃圾申请变多。有雇主报告通过招聘板收到的不合格候选人过多（Novorésumé 援引约 60%）。AIHawk 这类批量代投被 The Verge / TechCrunch 写成「求职者开始像发垃圾邮件」。
- 结果是更严的筛选、更多 ghost job、更长周期。Greenhouse 等估计线上职位中约 **18%–27%** 并无真实招人意图；美国一侧调查把平均求职周期放到约 **6.6 个月**。

**JobCome 押的缺口：** 简历工具只管「写出来」，牛客只管「刷泛题」——缺的是**真面真题沉淀 + 对着自己简历练到答得更好**的渐进闭环。

参考锚点（不是对标用户量，是对标工作流）：[ai-job-search](https://github.com/MadsLorentzen/ai-job-search) 作者公开漏斗为 69 份针对性申请 → 20 场一面 → 1 个签约。这是质量路径打得通的存在证明。AIHawk 的 2843 份代投是反模式。

## 3. 行业与市场

### 3.1 行业结构：招聘是双边市场，工具是单边补丁

```
企业招聘预算 ──► 招聘平台 / ATS / 猎头     （付费主体在 B 端）
                         │
                         ▼
                   岗位流 / 聊天 / 网申
                         │
求职者时间 ────────► 简历 / 匹配 / 面试准备   （C 端工具，付费意愿弱、窗口短）
```

要点：

- **钱在企业端。** 中国在线招聘平台收入几乎全部来自企业客户。BOSS 直聘 2026 Q1 营收 20.7 亿元，其中企业招聘收入 20.6 亿。JobCome 若走 C 端订阅，客单价和时长都受「求职是阶段性事件」约束。
- **平台不会把匹配做完。** 平台优化的是成交/聊天/职位消耗，不是某一个候选人的档案诚实度和申请质量。这是独立工具的生存缝。
- **工具层正在被五类产品切开**（国内公开资料横评，2026-08）：专业简历平台、办公套件插件、通用大模型、海外 ATS 工具、平台自带的「AI 求职教练」。JobCome 必须选一条缝，而不是再做一个模板站。

中国网络招聘平台规模口径很乱（约 180 亿人民币量级的平台收入，和把猎头/灵工算进去的更大口径不是一回事）。对 JobCome 有用的不是 TAM 口号，而是：**求职者流量被 BOSS / 智联 / 前程 / 猎聘 / 拉勾 / 电鸭 吸走，简历和面试准备仍是碎片化补丁。**

### 3.2 需求侧：谁在痛、痛多久

| 客群 | 市场事实 | 对 JobCome 的含义 |
|---|---|---|
| 知识工作者社招 | 申请量暴涨、周期变长、针对性简历进面率明显更高 | **首选滩头。** 有存量经历可结构化，付费窗口是「找到下一家」的数月。 |
| 应届 / 校招 | 高校毕业生连续数年维持约 1200 万量级；秋招春招节奏强；牛客/实习僧/超级简历已占位 | 可做，但不是第一期。缺的是项目包装和笔试，不是深度档案。 |
| 海外 / Remote | awesome-remote-job 这类目录说明远程岗信息分散；英文 CV + ATS 是刚需 | 第二期很好的扩展：同一套档案出中英两套投影。 |
| 蓝领 / 低线 | BOSS 2026 Q1 蓝领收入占比首次超过 40%，新增用户里非应届约三分之二是蓝领 | **不做。** 决策在聊天和到岗速度，不在针对性 PDF。 |

滩头用户画像（第一期只服务这一种人）：

> 2–10 年经验的知识工作者（研发 / 数据 / 产品 / 设计 / 运营），正在换工作或同时看国内社招和外企/远程。手里有一份偏平的旧简历，希望改亮、改顺、能导出 Word 就投。接受表达拔高，但不能接受凭空造一家公司和一段假学历。

### 3.3 供给侧：AI 让「写」变便宜，「信」变贵

- 求职者侧：美国调查 2026 年约 **70%–80%** 在申请中用过 AI（Statista / Clutch 量级；Novorésumé 写 74%）。
- 企业侧：约 62% 的人才团队部署了至少一种 AI 招聘工具，但真正跑在半数以上职位上的仍是少数（Recruiting Tech Reviews, 2026）。ATS 全球市场规模被咨询机构放到百亿美元量级，并继续因中小企业上线和 AI 排序而扩张。
- 传统简历代写在美国仍是约 3 亿美元量级的服务（IBISWorld），AI 生成器在用低价打它的交付速度。
- 招聘方开始用 AI 面试/筛选（Greenhouse 2026：约 63% 美国候选人过去半年被 AI 面试过），候选人信任度低。

行业正在进入 **军备竞赛均衡**：双方都用 AI 之后，胜负手从「会不会用 AI」变成「材料是否针对这一岗、面试能否圆上」。JobCome 把「写亮 + 能圆」做成产品，而不是把生成速度或海投做成产品。

### 3.4 中国市场的特殊约束

1. **渠道不是 ATS 一张网。** 中小企业在 BOSS 上直聊；大厂走官网网申 + 北森 / Moka 等 ATS；技术岗还要牛客笔试。第一期 JD 输入必须支持「粘贴文本」，不能赌爬虫。
2. **Word 是国内 HR / 猎头的交换格式。** 只出 PDF 的海外简历工具在国内会卡导出这一步。
3. **个保法。** 简历是敏感个人信息（身份、电话、履历）。Web 产品必须：最小化采集、传输加密、可一键删除、默认不用于训练。不是事后补丁。
4. **平台会自己做 AI。** 智联有职悟空，BOSS 也在岗位侧做助手。独立产品必须在「跨平台、可导出 PDF/Word、能把简历写亮、面试对着导出稿」上比平台插件更深。
5. **秋招 / 春招是脉冲。** 若做应届，节奏必须按校招日历；第一期刻意避开这条脉冲，先吃社招的滚动需求。

### 3.5 机会判断（现在做的理由）

| 窗口 | 判断 |
|---|---|
| 需求已验证 | 针对性材料进面率约 2 倍；用户知道该改，但改不起。 |
| 供给错位 | 海投工具有流量和争议；模板工具有量没有工作流；平台 AI 绑在自家岗位上。 |
| 开源可抄架构、不可抄产品 | `ai-job-search` 证明工作流；它是开发者终端 + 丹麦招聘板 + LaTeX，不是中国用户产品。 |
| 海投开始被惩罚 | LinkedIn 限制自动化、招聘方厌恶垃圾申请。晚做「质量型」比再做一个 LazyApply 安全。 |
| 风险 | C 端求职工具留存差；大模型直接聊天能完成 60 分的改简历；平台可能抄功能。要用「档案 + 证据链 + 导出 + 面试派生」做深，而不是做一个 Prompt 套壳。 |

## 4. 竞品与定位

### 4.1 地图（按工作流切，不按功能清单切）

| 类型 | 代表 | 他们优化的指标 | JobCome 相对位置 |
|---|---|---|---|
| 模板简历 | 超级简历 WonderCV、WPS 简历、Novorésumé | 出一份好看的简历 | 我们从已有底稿建档，不做 5000 套模板商城 |
| 海外求职 CRM | Teal、Huntr | 版本管理、看板、关键词 | 要学版本与跟踪；第一期不做看板 |
| 填表助手 | Simplify | 人在场时的 autofill | 以后可接；不是 MVP |
| 自动投递 | LazyApply、Sonara、LoopCV、FastApply、AIHawk | 投递次数 | **明确不学。** 封号、ToS、注水、招聘方反感 |
| 平台教练 | 职悟空、BOSS 助手 | 留在平台内闭环 | 我们跨平台、可导出、不代发 |
| 面试题库 | 牛客、interviewing.io | 刷题 / 面经 | 我们的是**真面沉淀库**：绑定公司岗位，从用户自己的面试长出来，可渐进共享 |
| 开源工作流 | ai-job-search | 本机、可 fork | 架构对标；产品要服务非开发者 |
| 岗位目录 | awesome-remote-job | 信息索引 | Scout 招聘信息源之一 |

### 4.2 定位句（对外可用）

> 帮你发现招聘信息、拔高简历，先用非目标公司练手，再攻目标公司拿 Offer。导出 PDF/Word，投递你自己来。

### 4.3 差异化三件事（必须同时成立）

1. **剑指 Offer：** 一切服务于在**目标公司**签约。
2. **先练手、后攻目标：** 非目标公司攒真面试经验与真题。
3. **面试库飞轮：** 记真题 → 模拟抽库 → 迭代最佳答案 → 真面再记 → 库越厚越强。
4. **帮发现，不帮投递：** 招聘信息可以帮；投递动作在用户手里。

缺任何一条，就会塌成「又一个 AI 改简历」。

## 5. 产品定义

### 5.0 形态

**独立 Web 应用。** 用户用浏览器完成：建档、拔高简历、导出 PDF/Word、贴 JD、针对性模拟面试与辅导、记录结果，剑指 Offer。

不是 Chrome 插件，不是 IDE 技能包，不依赖 NaviForge。填表助手如果以后要做，也是 JobCome 自己的能力，不复用 NaviForge 代码路径。

### 5.1 核心对象

```
Profile          身份 / 经历 / 技能+证据 / 语言 / 偏好 / 禁区 / 文风 / STAR 素材
ResumeDraft      基于档案的优化稿（含拔高档位）；可直接导出
Job              原文 + 结构化要求 + 公司调研；标签：练手 / 目标 / 观望
JobListing       招聘信息条目（来源、链接、摘要、去重、过期）
Campaign         进攻计划：当前处于练手期还是目标期；练手达标条件
Fit              五维分 + 缺口 + 禁区否决 + 投/不投建议
Package          该岗位简历变体 + 可选求职信 + ATS 检查 + 导出物
InterviewPack    提纲 + 针对性模拟 + 轮次辅导（练手模式 vs 目标模式）
MockSession      单次模拟：从 InterviewBank 抽题 + 生成新题；作答、点评、参考答案
InterviewRecord  一次真实或模拟面试：公司、岗位、轮次、时间、练手/目标、结果
InterviewQuestion 单道真题：题干、类型、来源（真面/模拟/社区）、关联公司岗位
AnswerAttempt      某用户对某题的作答：用户版、AI 参考版、点评、是否当前最佳
InterviewBank      个人面试库（默认）；CommunityBank 社区库（脱敏、后置）
OfferTrack         进面 / 挂 / Offer / 签约；区分练手 vs 目标
Application        用户自行投递后的快照（不执行投递）
```

五条管线：

- **发现机会：** `Profile → Scout → 标记练手/目标 → Fit`
- **备稿：** `Profile → 拔高 → 导出`；有 JD 时 `→ Package`
- **练手 / 攻目标：** `Campaign → 练手期 → 达标 → 目标进攻`
- **面试库：** `InterviewRecord → InterviewQuestion 入库 → AnswerAttempt 迭代最佳答法`
- **模拟 & Offer：** `InterviewBank + 导出稿 → MockSession → OfferTrack → 复盘`

简历渲染：`Profile 或 ResumeDraft JSON → 中文一页 / 英文两页模板 → PDF + DOCX`。对 PDF 抽文本层做 ATS 检查（联系方式是否为真文字、阅读顺序）。禁止 PDF↔Word 互转当编辑器。

### 5.2 智能体角色

| 角色 | 职责 | 硬约束 |
|---|---|---|
| Ingest | 解析底稿，出 Profile 草稿 | 不确定标「待确认」，不把解析阶段写成终稿 |
| Analyst | 打 Fit | 禁区硬否决；语言不够只警告 |
| Writer | 优化底稿 + 出岗位申请包 | 按当前档位拔高；硬事实必须能指回档案 |
| Reviewer | 独立批评 | 抓空话、不可面试的吹嘘、假公司/假学历；不把强动词当错误 |
| Coach | 模拟面试 + 辅导 + **参考答案迭代** | 优先从 InterviewBank 抽同公司/同岗位/同轮次题；结合 Profile 与导出稿给可圆上的参考答法 |
| Archivist | 面试记录与题库沉淀 | 结构化录入公司/岗位/轮次/问题；去重、打标签、链到 Application |
| Strategist | 练手 / 目标进攻节奏 | 建议先打哪些练手岗；何时达标可攻目标；不过早冲 dream company |
| Scout | 获取招聘信息 | 公开源、RSS、粘贴 JD、去重；**不执行投递** |

### 5.3 明确不做（v1）

- **任何形态的代投递：** 一键投递、自动填表、代点发送、Boss/LinkedIn 代投、填表助手
- 隐身浏览器、反检测、绕过登录墙去帮用户「投出去」
- 从第一天就堆**无来源的通用八股题库**（库必须来自真面记录或高保真模拟，可渐进开放社区）
- 语音模拟面试（文字模拟先进 MVP；语音可后置）
- 蓝领 / 兼职 / 劳务派遣场景
- 浏览器插件 / 油猴脚本 / 依赖 NaviForge
- 支付系统（付费模式未定之前不写）

### 5.4 优化与拔高

默认档位是 **拔高**。用户可改成保守。档案里的事实层不变，变的是怎么写。

| 档位 | 做什么 | 例 |
|---|---|---|
| 保守 | 理顺结构、纠错、量化已有数字、删空话 | 「参与后台开发」→「负责订单服务的接口开发」 |
| 标准 | 成果导向、关键词、动词升级 | 「参与」→「负责」；补上可推断的影响 |
| 拔高（默认） | 在能圆的前提下夸张：主导感、范围、数字取上沿、职级措辞靠近目标岗 | 「参与性能优化」→「主导核心链路优化，接口 P99 从 800ms 压到 200ms 量级」 |

允许：更强动词、突出个人贡献、数字取合理上沿、技能排序按目标岗、把模糊职责写成可扫描成果。

禁止：假公司、假学历、假任职时间、从未做过的项目、把别人的产品说成自己从 0 做的。

拔高句写入导出稿时，内部保留「档案原句 → 写出句」，模拟与真面试复盘都按写出句来。

### 5.6 面试进攻策略（练手 → 目标）

JobCome 不帮用户投递，但帮用户**规划怎么打**。核心思路：**先用非目标公司练手，再用充分经验攻目标公司。**

```
建档 + 拔高
    │
    ▼
发现招聘信息 ──► 标记：练手 / 目标 / 观望
    │
    ▼
【练手期】主攻非目标公司
    │  · 导出简历，用户自行投递（产品不代投）
    │  · 真面试前：针对性模拟（练手模式，偏纠错、攒话术）
    │  · 真面试后：复盘挂点，更新 STAR 与拔高句圆场
    ▼
练手达标？（见下）
    │ 否 → 继续练手岗 + 模拟
    ▼ 是
【目标进攻期】集中打目标公司
    │  · 针对性拔高 + 高压模拟（目标模式）
    │  · 真面试 → 复盘 → 迭代直到 Offer
    ▼
目标公司签约
```

**岗位怎么标**

| 标签 | 含义 | 产品建议 |
|---|---|---|
| 练手 | 非目标公司：行业/职级接近，但不是 dream job | 优先推荐先去面，用来攒经验、测简历、练话术 |
| 目标 | 真正想去的公司/岗位 | 练手未达标前只备稿、可模拟，**不建议作为第一战场** |
| 观望 | 暂时不看 | 只存档，不进进攻计划 |

**练手达标（默认建议，用户可改）**

满足其一即可建议开启「目标进攻」：

- 完成 **≥ 3 场** 真实面试（练手公司），且每场事后在系统里做过复盘；或
- 完成 **≥ 5 轮** 针对性模拟（含拔高句圆场），自评「敢去真面试了」；或
- 用户手动切换为「开始攻目标」（尊重主观判断，但弹窗提示风险）。

**练手模式 vs 目标模式（模拟与辅导差异）**

| | 练手模式 | 目标模式 |
|---|---|---|
| 语气 | 纠错为主，允许停顿、追问基础 | 高压、追深挖、模拟终面压力 |
| 重点 | 把拔高句圆顺、STAR 结构、常见挂点 | 业务匹配、文化题、反问、薪资与动机 |
| 复盘 | 记录「第一次卡在哪」 | 记录「离 Offer 差什么」 |

参考 [ai-job-search](https://github.com/MadsLorentzen/ai-job-search) 作者的个案：69 份申请、20 场一面——**量可以少，但每场要有准备**。JobCome 在此基础上加一层：**每场结束必记题，下一场从自己的库里长出来。**

### 5.8 面试库与渐进提升

不是牛客式泛题库，而是**从用户自己的真面试与模拟中长出来的题库**。循序渐进：个人先厚，再可选贡献社区。

**记什么（InterviewRecord）**

| 字段 | 说明 |
|---|---|
| 公司 | 全称；社区贡献时可脱敏为「某互联网大厂 / 某外企」 |
| 岗位 | 职位名称 + JD 链接或摘要 |
| 轮次 | 一面 / 二面 / 技术面 / HR / 终面 |
| 类型 | 练手 or 目标 |
| 时间 | 面试日期 |
| 结果 | 进下一轮 / 挂 / Offer / 待定 |
| 问题列表 | 每题一条 InterviewQuestion |

**每道题记什么（InterviewQuestion）**

- 题干（用户回忆或当场速记，可语音转文字后置）
- 题型：项目深挖 / 八股 / 行为面 / 系统设计 / 业务 case / 反问
- 来源：`真面` | `模拟` | `社区`
- 关联：哪次 Application、哪版导出简历

**模拟时怎么用库（MockSession）**

出题优先级：

1. **同公司 + 同岗位** 历史真题（用户自己的）
2. **同岗位类型**（如「后端 P6」）历史真题
3. **社区库** 同标签题（M3+，脱敏）
4. AI **生成补充题**（仍绑定 JD + 导出稿，不脱离上下文）

每道题走完：**用户答 → Coach 点评 → 给参考答法（可圆上拔高句）→ 用户可保存为「当前最佳答案」**。

**渐进提升怎么衡量**

| 信号 | 含义 |
|---|---|
| 个人库题目数 | 真面沉淀厚度 |
| 同一题 AnswerAttempt 次数 | 是否反复练 |
| 最佳答案版本迭代 | 从「卡壳」到「能讲 2 分钟」 |
| 模拟后自评 / 抽检分 | 练手达标、攻目标前的门禁 |
| 真面挂点标签下降 | 最终是否更接近 Offer |

**社区题库（M3+，自愿脱敏）**

- 用户勾选「贡献到社区」时：去掉可识别信息，保留**岗位类型、公司规模/行业、轮次、题型、题干**。
- 其他用户可按岗位/题型筛选练习，看到社区里的**高赞参考答法**（仍须结合自身 Profile 改写，禁止照搬）。
- 不做付费卖题；价值是网络效应：**练手公司攒的题，帮后来人攻同类目标岗**。

与练手策略的关系：**练手期 = 攒真题 + 攒答法**；目标期 = 用厚库 + 高压模拟打 dream company。

### 5.9 第一期用户旅程（必须能在浏览器里演示）

**阶段零：发现机会（MVP 可先「粘贴 JD + 手动标记」，聚合后置）**

0. 浏览/粘贴招聘信息 → 标记练手 or 目标 → Fit 看值不值得准备。

**阶段一：备稿（用户自行投递）**

1. 上传底稿 → 核对 Profile → 拔高 → 导出 PDF 或 Word。
2. 对练手岗优先出针对性稿；目标岗可先备稿不急着真投。

**阶段二：练手期 + 攒库**

3. 用户自行投递（产品不代投）。
4. 真面前：从个人库（若已有）+ JD 出题，练手模式模拟。
5. **真面后：录入公司、岗位、轮次、面试问题** → 进入个人面试库。
6. 对刚记的题再练一轮，保存「最佳参考答法」。

**阶段三：目标进攻 + 库驱动模拟**

7. 练手达标 → 攻目标岗；模拟优先抽**同岗位类型**历史题 + 高压新题。
8. 每次真面后继续记题、迭代答案 → Offer / 签约。

**MVP 演示成功标准：** 备稿 + 模拟一轮 + **录入至少 3 道真题并生成参考答法** + 第二次模拟能抽到库内题。

**产品成功标准（长期）：** 目标公司 Offer；且用户个人面试库持续增长、同一类题答法明显迭代。

## 6. 目标

### 6.1 北极星与漏斗

**北极星（终极）：用户在目标公司签约 Offer 的比例。**

**四段漏斗：**

| 阶段 | 用户要得到什么 | 核心指标 | 产品能力 |
|---|---|---|---|
| ⓪ 发现 | 知道有哪些岗、先打谁 | 有效招聘信息数、练手/目标标记完成率 | Scout、Fit、进攻节奏建议 |
| ① 备稿 | 能拿去自行投递的亮简历 | 导出完成率、练手岗优先备稿 | 拔高、Package、PDF/Word |
| ② 练手 & 攒库 | 非目标真面 + 真题沉淀 | 练手真面场次、**入库题数**、复盘完成率 | 记公司/岗位/问题、个人 InterviewBank |
| ③ 渐进提升 | 同一题答得更好 | **最佳答案迭代次数**、模拟就绪度 | 库驱动模拟、参考答法、多轮 AnswerAttempt |
| ④ 攻目标 & Offer | 目标公司签约 | **目标公司 Offer 率** | 高压模拟、库内同岗题、OfferTrack |

辅星：

- 建档到可投底稿 **< 15 分钟**
- 有 JD 到针对性终稿 **< 20 分钟**
- 单轮模拟面试 **< 30 分钟** 能走完

刻意不做成北极星的：投递数量、DAU、生成字数、导出次数。

### 6.2 护栏指标（做坏了就停）

| 护栏 | 红线 |
|---|---|
| 硬事实造假 | 出现假公司 / 假学历 / 假任职时间 / 档案里不存在的项目，立刻修 Writer |
| 不可面试的吹嘘 | 拔高句用户自己圆不上（抽检问「这句怎么讲」讲不清）占比过高则降档 |
| 用户改稿率 | 若用户几乎不改就投，Reviewer 可能在放水；若改到重写，Writer 失败 |
| 确认率 | 未确认不得导出为「终稿」；导出记录必须绑定 Profile 版本和拔高档位 |
| 隐私 | 默认不把完整简历明文传到非必要的第三方；可一键删除 |

### 6.3 分阶段目标

**M0 规格（本周，约 3 天）**

- 冻结本文的原则、范围、滩头用户。
- 写出 Profile JSON schema 和一份中文模板 + 一份英文模板的版式约束。
- 准备 3 个真实样本：技术社招、产品社招、中英双语各一。

**M1 可演示 MVP（约 8–12 周）**

- 目标用户：作者自己 + 5 个熟人知识工作者。
- 必须打穿：**备稿 + 记面试（公司/岗位/题）+ 库驱动模拟 + 参考答法迭代**。
- 招聘信息：MVP 至少支持 **粘贴 JD + 手动标记练手/目标**；公开源聚合可 M2 完整做。
- 定量（内部）：
  - 建档 + 拔高导出：确认档案后 **< 15 分钟** 出 PDF 或 Word。
  - 有 JD 时：针对性终稿 **< 20 分钟**。
  - 模拟：对着导出稿完成 **≥ 1 轮** 针对性问答，含拔高句圆场辅导。
- 定性：
  - 真面后录入 **≥ 3 道题** 并进个人库；
  - 第二次模拟能抽到库内题，并产出可保存的参考答法。

**M2 攻目标 + 库加厚**

- Scout 聚合招聘；Campaign 达标；目标模式高压模拟。
- 同岗位题型聚类、挂点标签、最佳答案版本对比（「比上周进步」）。
- OfferTrack 区分练手/目标。

**M3 社区题库 + 规模化**

- 自愿脱敏贡献社区 InterviewBank；按岗位/题型浏览与练习。
- 高赞参考答法（标注须结合自身经历改写）。
- 用漏斗数据校准：练手几场、库多少题后目标 Offer 率最高。

### 6.4 付费（未定，先不实现）

现在不选模式。MVP 做到「能产出可投出的申请包」为止，不接支付、不设套餐墙。

以后单独开一轮时，只作为候选，不作为当前目标：

| 候选 | 备注 |
|---|---|
| 求职季套餐 / 订阅 | 窗口短，年订可能卖不动 |
| 按终稿申请包计费 | 和「拿面试」阶段同向 |
| 按模拟轮次 / 求职季套餐 | 和「打面试」阶段同向 |
| Offer 成功赏金 / 顾问 B 端 | 和「拿 Offer」阶段同向；后置 |
| 用户自带模型 Key | 降低托管成本，影响上手 |
| 托管额度 | 上手简单，成本和隐私叙事都更重 |
| 顾问 / 高校 B 端 | 比散户更愿意为工作流付钱，但不是第一期客户 |
| 招聘平台分佣 | 倾向不做：会把产品推回海投 |

## 7. 节奏

原则：**先打穿「备稿 + 练手标记 + 练手模拟」，再加招聘信息聚合与目标进攻。**

### 7.1 12 周 MVP

| 周 | 主题 | 完成定义 | 验收 |
|---|---|---|---|
| W1 | 档案 | Profile schema、解析 PDF/DOCX、Web 核对页 | 浏览器里上传 3 份样本，人能在 15 分钟内改成「愿意签字」的档案 |
| W2 | 优化 + 导出底稿 | 拔高档位、中文模板、PDF **或** Word 导出 | 不贴 JD，确认档案后能下载一份愿意投的 PDF 或 docx |
| W3 | Fit | JD 粘贴、结构化要求、五维分、禁区否决 | 对同一人两个明显不匹配/匹配的 JD，建议方向相反且说得清 |
| W4 | 练手/目标 | 岗位标签、进攻建议、达标规则（可先写死） | 标 2 个练手 + 1 个目标，系统建议先攻练手 |
| W5 | 练手模拟 | 练手模式 + 首次模拟 | 完成一轮 |
| W6 | **面试记录** | 录入公司/岗位/轮次/问题 | 一场练手面试记 ≥3 题 |
| W7 | **面试库 v0** | 个人库列表、按公司/岗位筛选 | 库内题可被第二次模拟抽到 |
| W8 | **参考答法** | 用户答 + AI 参考答 + 保存最佳版 | 同一题二次练习可对比版本 |
| W9 | 招聘信息 v0 | 粘贴 JD、练手/目标标记 | 岗位与 InterviewRecord 关联 |
| W10 | 目标模式 | 库驱动 + 高压模拟 | 优先抽同岗历史题 |
| W11 | 达标 & Offer 雏形 | 练手达标、记结果 | 库题数 + 真面场次可见 |
| W12 | 演示冻结 | 全链路 | 备稿→模拟→记题→再模拟(抽库)→参考答法 |

并行但不得阻塞竖切：模板美观、品牌名。产品本身就是 Web，不必另做官网。W12 之前不接招聘网站爬虫。

### 7.2 双周节拍（进入开发后）

每个冲刺固定四件事：

1. **一条竖切故事**（本周必须能跑的用户路径）。
2. **一组回归样本**（固定 3 份简历 × 2 个 JD）。
3. **一次硬事实抽检**（抽 5 段：公司/时间/项目是否还在档案里；拔高句是否圆得上）。
4. **一次真人试用**（不是团队成员读自己写的提示词）。

### 7.3 季度节奏（MVP 之后）

| 季度 | 主题 | 进来 | 不进来 |
|---|---|---|---|
| Q0 | MVP | 备稿 / 记面试 / 个人库 / 库驱动模拟 / 参考答法 | 社区题库、Scout 聚合 |
| Q1 | 攻目标 | Scout、达标、目标模式、答案版本对比 | 代投 |
| Q2 | 网络效应 | **社区题库**、同岗题聚类、挂点复盘自动化 | 泛八股导入 |
| Q3 | 加深 | 顾问/高校试点，或浏览器填表（人点提交） | 平台分佣海投 |

每季只设一个「必须打穿」的主题。想加功能先问：它落在漏斗哪一段——拿面试、打面试、还是拿 Offer。

### 7.4 与三个开源项目的关系（执行层面）

| 来源 | 本季度用法 |
|---|---|
| ai-job-search | 抄工作流与命令切分：setup / apply / interview / outcome；抄 Drafter-Reviewer、ATS 文本层、相关度裁页。不 fork 当产品，不绑 Claude Code。 |
| awesome-remote-job | Q2 起当岗位源与远程公司清单；国内源另做目录。 |
| AIHawk | 只参考「人在场的填表」；Q3 再评估。禁止隐身指纹与无人值守提交。 |

## 8. 风险

| 风险 | 为什么致命 | 缓解 |
|---|---|---|
| 做成聊天套壳 | 用户会去用免费大模型 | 强制结构化档案、导出物、溯源、Reviewer |
| 注水被发现 | 一次就毁掉信任 | 护栏抽检；Reviewer 独立上下文；导出带版本 |
| 海投诱惑 | 短期增长快、长期被平台和舆论打死 | 原则写进产品：没有「一键投 50 岗」入口 |
| 隐私事故 | 简历是高敏感数据；Web 意味着数据会过服务器 | 传输加密；可一键删除；默认不用于训练；演示数据脱敏 |
| 平台抄袭 | 职悟空/BOSS 可以加「贴 JD 出简历」 | 跨平台导出 + 证据链 + 面试派生，平台很难为竞争对手岗位做深 |
| C 端留存 | 找到工作就卸载 | 先把工作流做深；付费和 B 端以后再开一轮 |
| 社区题库隐私 | 真题含业务细节，泄露公司或本人 | 默认仅个人库；贡献须显式勾选 + 脱敏预览 + 可撤回 |
| 参考答法抄袭 | 用户照搬社区答案穿帮 | 标注「须结合本人经历改写」；生成时强制挂 Profile 证据 |

## 9. 仍开放的决策

形态、付费、NaviForge、建档导出、拔高、不代投递、练手→目标、**面试库**、终极目标 Offer 已冻。还没拍的：

1. **模型谁付钱：** 用户自带 Key，还是托管额度。影响隐私叙事和成本，可与付费一起想。
