## 1. 一句话

**一个记得你的、随时能语音对话的 AI 伴侣——像朋友或知心姐姐那样倾听与陪伴，在你需要时解答疑问，而不是冷冰冰的问答机器。**

灵感来自电影《Her》，但落地为**真实可交付的产品**：低延迟语音、跨会话记忆、稳定人格、清晰边界。

---

## 2. 愿景与使命

### 愿景（Vision）

> **让每个人在独处或需要倾诉时，都有一位始终在场、记得你、尊重你的对话者。**

不是替代真人关系，而是填补「想说话却无人可找」「问题很小不好意思麻烦朋友」「深夜需要有人听」的空隙。

### 使命（Mission）

1. **陪伴优先**：先听懂情绪和语境，再决定是否给建议或答案。  
2. **记得你**：跨会话延续关系感，自然提起往事，不念档案。  
3. **语音原生**：像打电话一样自然，可打断、可沉默、可短句来回。  
4. **诚实有界**：不冒充真人、不冒充专业诊疗；能力边界说清。

### 长期方向（3–5 年，不绑定 v1）

- 多模态（文字 fallback、可选形象）  
- 更细腻的长期关系模型（目标、习惯、重要日期）  
- 用户完全掌控记忆（查看、编辑、遗忘）  
- 可选本地/混合部署，满足隐私敏感用户

## 3. 我们要解决什么问题

| 现状痛点 | 本产品如何应对 |
|----------|----------------|
| 通用助手像客服：等指令、给长答案、无连续人格 | 默认**倾听模式** + 固定 persona + 短口语回复 |
| 聊完就忘，每次像第一次见面 | **Core + Episodic 记忆** + Hermes recall / session_search |
| 文字聊天缺乏临场感 | **LiveKit 实时语音**：STT → 脑 → TTS，支持打断 |
| 工具型 Agent 太「干活」，破坏亲密感 | v1 **极少工具**，解惑时后台查，嘴上仍像聊天 |
| 恋爱/心理类产品有伦理与合规风险 | 明确定位**朋友/姐姐**，危机话术与免责声明 |

## 4. 产品定位：是什么 / 不是什么

### 是什么

| 维度 | 定义 |
|------|------|
| **品类** | 语音优先的 AI **陪伴 + 轻解惑** 产品 |
| **关系隐喻** | 知心姐姐 / 老朋友（可配置称呼，默认非恋爱向） |
| **交互主形态** | 实时双向语音会话（可辅以文字） |
| **技术形态** | Hermes（大脑与记忆）+ LiveKit（耳与嘴）+ 自研产品层（人格、模式、策略） |

### 不是什么

| 不是 | 原因 |
|------|------|
| 编程 Agent / OpenHuman 式「个人 OS」 | 范围过大，偏离陪伴 |
| 心理咨询 / 医疗 / 法律专业服务 | 合规与能力边界 |
| 虚拟恋爱 / 性向角色扮演产品（v1） | 伦理、审核、预期管理 |
| 又一个通用 ChatGPT 套壳 | 无差异化 |
| Hermes + Letta + OpenHuman 记忆叠罗汉 | 一套脑即可，避免重复注入与延迟 |

## 5. 目标用户与核心场景

### 主用户画像（v1）

- **年龄**：22–40 岁，熟悉语音助手或播客式交互  
- **动机**：倾诉、陪聊、轻量解惑（生活、工作情绪、简单知识）  
- **设备**：手机或 Web 优先（桌面吉祥物为后续可选）  
- **付费意愿**：为「持续记得我 + 无限畅聊」订阅（待定定价）

### 核心场景（按优先级）

| 优先级 | 场景 | 用户说 | 产品应 |
|--------|------|--------|--------|
| P0 | 情绪倾诉 | 「今天好累，老板又…」 | 倾听、复述感受、少说教 |
| P0 | 随口闲聊 | 「你在吗」「陪我聊会儿」 | 自然接话、短句、有温度 |
| P1 | 生活解惑 | 「签证材料要准备啥」 | 切解惑模式，简洁回答 + 是否展开 |
| P1 | 延续关系 | 隔天再打开 | 「上次你说面试周三，怎么样了？」 |
| P2 | 提醒/记事 | 「帮我记住明天给妈妈打电话」 | 写入记忆，适时提起（非日历 App） |
| P3 | 主动关心 | 用户授权后晚间问候 | 克制频率，可关 |

## 6. 核心价值主张

**对用户**：  
「她记得你说过的话，用声音陪在你身边；你想聊就聊，想问也能问，但不会把你当工单。」

**对团队（内部）**：  
「用成熟 Harness（Hermes）+ 实时语音（LiveKit）做薄产品层，把差异化放在 **人格、记忆策略、语音体验**，而不是重造 Agent 循环。」

**差异化三板斧**

1. **关系连续性** — 不是单次 QA，而是越聊越熟。  
2. **语音临场感** — 延迟、打断、句长像真人说话。  
3. **模式分明** — 倾听 vs 解惑，用户无感切换或一句切换。

---

## 7. 产品原则

1. **陪伴 > 正确**：情绪场景不抢答、不堆链接、不上课。  
2. **短句口语**：语音回复默认短；长内容先问「要不要展开」。  
3. **记得但不说破**：提起往事要自然，禁止念 USER.md。  
4. **一个大脑**：记忆与对话状态单一来源（Hermes），不双写。  
5. **工具隐形**：v1 不暴露「正在搜索」；必要时一句话带过。  
6. **可遗忘**：用户可删记忆、可重置关系。  
7. **诚实**：不知道就说不知道；不编造共同经历。  
8. **Fail-soft**：网络/ASR 差时优雅降级文字，不甩锅用户。  
9. **默认非恋爱**：人格与营销避免性暗示；用户自定义边界写入 Core。  
10. **YAGNI**：先跑通语音 + 记忆 + 人格，再考虑形象、通道、工作流。

## 8. 功能需求

### 8.1 Must Have（MVP / v0.1）

| ID | 需求 | 验收标准 |
|----|------|----------|
| F-01 | 实时语音对话 | 用户说话 → ASR → 回复 → TTS；端到端可演示 |
| F-02 | 打断与轮次 | 用户插话可打断播报；不误把「嗯」当结束 |
| F-03 | 固定人格 | system persona 稳定（知心姐姐基调）；称呼可配置 |
| F-04 | 跨会话 Core 记忆 | `USER.md` 类：称呼、偏好、雷区、重要的人 |
| F-05 | 会话结束沉淀 | 值得记住的事写入 Episodic（或 provider） |
| F-06 | 开场个性化 | 再次进入可引用 1 条相关往事（可选关） |
| F-07 | 双模式 | 默认倾听；用户明确要问时解惑（关键词或轻分类） |
| F-08 | 文字 fallback | 语音失败时可打字 |
| F-09 | 免责声明 | 首次使用说明：非专业咨询、AI 身份 |
| F-10 | 单用户单关系 | v1 一个账号一个伴侣实例 |

### 8.2 Should Have（v0.2–v0.3）

| ID | 需求 |
|----|------|

| F-12 | 外挂 semantic recall（Hindsight / mem0）`auto_recall` |
| F-13 | 记忆面板：用户查看/删除条目 |
| F-14 | 语音音色选择 |
| F-15 | 会话摘要推送（可选，每日一句） |

### 8.3 Could Have（v1+）

| ID | 需求 |
|----|------|
| F-16 | 轻量形象 / 口型（OpenHuman 或 LiveAvatar 类） |
| F-17 | 多通道（Telegram 文字同步） |
| F-18 | 主动问候（需授权 + 频率上限） |
| F-19 | 多语言 |

## 9. 记忆与人格（产品层）

### 9.1 三层记忆（简化自 Claude Code / Letta）

```text
Core（常驻）
  人格底线、称呼、沟通偏好、雷区、重要关系一句话
  → 映射 Hermes USER.md + persona 段

Episodic（按需召回）
  「某天聊过换工作」「讨厌被说教」
  → Hermes MEMORY.md + 可选 provider auto_recall + session_search

Working（本会话）
  当前情绪与话题；结束可摘要进 Episodic
  → Hermes 会话历史 + 回合末提取
```

### 9.2 人格（知心姐姐 · 默认）

- 先听清，再回应；少评判，多共情。  
- 可幽默，不油腻；可温柔，不说教。  
- 解惑时：先结论，再一句「要细讲吗」。  
- 禁止：markdown 朗读、列表轰炸、客服腔、「作为 AI 模型」开场（除合规必要处）。

### 9.3 写入策略

| 事件 | 动作 |
|------|------|
| 用户明确「记住」 | 立即写 Core 或 Episodic |
| 会话正常结束 | 后台提取 0–3 条高信号记忆 |
| 可推导信息 | 不存（如可从日历再拉的） |
| 用户说「忘掉」 | 删除对应条目 |

## 10. 体验标准（语音优先）

| 指标 | MVP 目标 | 备注 |
|------|----------|------|
| 首字延迟 | < 1.5s（理想 < 1s） | 依赖模型 + preemptive generation |
| 单句长度 | 中文 15–25 字为主 | 产品层后处理可拆句 |
| 打断成功率 | > 90% 主观可接受 | LiveKit turn detection + VAD |
| TTS | 无 markdown/emoji 读出 | prompt + 后处理 |
| 沉默 | 允许 2–3s 思考停顿 | 避免连珠炮 |

## 11. 技术架构原则

```text
┌─────────────────────────────────────────┐
│  产品层（自研）                           │
│  persona · 双模式 · 记忆策略 · 合规 · UI   │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│  Hermes（大脑）                            │
│  gateway · MEMORY/USER · session_search   │
│  可选 memory.provider (hindsight 等)      │
└──────────────────┬──────────────────────┘
                   │ 文本 in/out per turn
┌──────────────────▼──────────────────────┐
│  LiveKit Agents（语音管道）              │
│  STT · VAD · turn · TTS · room          │
└──────────────────┬──────────────────────┘
                   │
              用户端 App / Web
```

**不采用（v1）**

- OpenHuman 全栈（过重；仅借鉴 voice/记忆设计）  
- Letta 并行（与 Hermes 同质）  
- deepagents 主循环（工具向，非伴侣向）

**仓内资产**

| 组件 | 路径 | 用途 |
|------|------|------|
| LiveKit Agents | `hermes-dev/agents/` | 语音 worker 参考与插件 |
| Hermes | `hermes-dev/hermes-agent/` | 对话 + 记忆 |
| 记忆设计参考 | `agent-research/` Claude/Letta 笔记 | 策略，非运行时 |

## 12. 安全、隐私与边界

| 项 | 要求 |
|----|------|
| 身份 | 明确 AI，不冒充真人 |
| 危机 | 自伤/他伤关键词 → 危机资源话术，不「陪聊糊弄」 |
| 隐私 | 记忆可导出/删除；传输加密；隐私政策 |
| 恋爱/性 | v1 营销与人格默认非恋爱向；用户越界温和拉回 |
| 数据 | 说明记忆存哪（本地/云）、保留多久 |
| 未成年人 | 待定：是否 18+ 或家长模式 |

## 13. 成功指标

### 北极星（待定权重）

**周活跃用户的「有效陪伴时长」**：单次 ≥ 5 分钟的语音会话次数 / 周活。

### MVP 验证指标

| 指标 | 目标 |
|------|------|
| 次日留存 | > 30%（内测） |
| 平均会话时长 | > 8 分钟 |
| 「像真人聊天」问卷 | > 4/5 |
| 「记得我说过的事」问卷 | > 3.5/5 |
| 严重合规事件 | 0 |

### 反指标（避免优化错方向）

- 单轮平均 token 过长  
- 工具调用次数 / 会话过高  
- 用户主动「重置记忆」率异常高

## 14. 路线图

| 阶段 | 时间（示意） | 交付 | 验证问题 |
|------|--------------|------|----------|
| **0 · 技术样机** | 2–3 周 | LiveKit console + Hermes 文本桥接 + 固定 persona | 延迟与链路是否可行 |
| **1 · MVP** | 4–6 周 | Web/手机进房 + Core 记忆 + 倾听/解惑 + 免责声明 | 有人愿意聊第二遍吗 |
| **2 · 记忆增强** | +3 周 | session_search + auto_recall + 记忆面板 | 「她真的记得我」 |
| **3 · 体验打磨** | +4 周 | 音色、打断、主动开场一句 | NPS / 留存 |
| **4 · 可选形象** | 视需求 | 吉祥物或静态头像 + 口型 | 是否提升留存 |

## 15. 非目标（明确不做）

- v1 不做编程、改代码、操作电脑  
- v1 不做 17 通道消息矩阵（OpenHuman 级）  
- v1 不做用户自定义任意人格无审核  
- v1 不做多 Agent 编排、工作流画布  
- v1 不做替代心理咨询的诊断与治疗  
- v1 不自研 STT/TTS 模型（用 LiveKit Inference / 插件）

## 16. 待决问题（请你拍板）

以下确认后，本文档可升为 **v0.2** 并拆工程任务。

1. **产品名与关系设定**  
   - 暂定「知心姐姐」是否 OK？是否要更中性（朋友 / 伙伴）？  
   - 是否允许用户改成恋爱向 persona？（建议 v1 不允许或强提示）

2. **主场景权重**  
   - 你之前倾向 **答疑解惑为主**（选项 2）还是 **陪伴为主**（选项 1）？  
   - 这决定默认模式与 prompt 配比。

3. **首发端**  
   - Web / iOS / Android / 桌面 选哪一个先做？

4. **部署**  
   - 纯云（Hermes gateway 托管）还是本地可选？  
   - 记忆数据驻留地区（国内/海外）？

5. **商业模式**  
   - 订阅 / 按分钟 / 免费+限额？  
   - 是否用自己的模型 key 还是平台统一计费？

6. **合规**  
   - 是否限制 18+？  
   - 国内上架是否需要额外资质叙事？

7. **形象**  
   - v1 纯声音，还是必须要有脸？
