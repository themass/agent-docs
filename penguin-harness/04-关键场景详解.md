## S1 纯文本问答

**目标**：问一句常识/总结题，不碰工具。

**参与**：Human → Session → ContextEngine → LLM → Trace。

**逐步**：

1. `session.run([userText("...")], { approve })`  
2. `ensureReady`（若首次：装工具列表，但本 Task 可能用不到）  
3. `runTurn`：`request_begin` → 流式 thinking/text → 无 tool_call → `token_usage` → `request_end`  
4. Task 结束；UI 显示完整助手回复  

**可见序列（示意）**：

```text
request_begin
partial_thinking… / thinking
partial_text… / text
token_usage
request_end(completed)
```

**失败**：模型一直想调工具——检查 AGENTS.md/Skill 是否过度鼓励工具；或审批默认 deny 导致模型乱试。

**落点**：提示词与模型；不是 Environment。

---

## S2 单工具调用

**目标**：「读取 README 前 50 行并总结」。

**逐步**：

1. 首轮模型产出 `tool_call(read_file)`  
2. `approve` → allow  
3. `Environment.executeTool` 流式/完整 `tool_call_output`  
4. 引擎把该 output 作为下一轮唯一（或主要）新输入  
5. 次轮模型写总结文本，无 tool_call，结束  

**可见序列**：

```text
request_begin
… text? …
tool_call
approval_decision(allow)
partial_tool_call_output… / tool_call_output
token_usage
request_end          ← 可能早于工具完成？单工具时常紧挨
request_begin        ← 第二轮
text（总结）
request_end
```

**失败**：路径越出 Workspace——工具失败 output 回模型，应改路径而非崩进程。

**落点**：文件工具实现、Workspace 选择。

---

## S3 多工具并发

**目标**：一次回复里并行读两个文件。

**关键机制**：审批串行；执行并行；**yield 按完成序**；**喂下一轮按调用序**。

**故事**：

1. 模型依次给出 tool_call A、B。  
2. A 审批通过后开始执行；LLM 仍可继续产出 B。  
3. B 先完成 → 你先在 UI 看到 B 的 output。  
4. A 后完成。  
5. 两者都终态后，引擎按 A→B 重排，再开下一 Request。  

**失败**：自定义前端按完成序拼历史再塞回——与模型上下文不一致。应只渲染。

**落点**：`runTurn` + MergeQueue；见 `source/01`。

---

## S4 审批拒绝

**目标**：危险 `exec_command` 被用户点拒绝。

**逐步**：

1. `tool_call(exec_command, rm -rf …)`  
2. `approve` → deny  
3. 引擎**不**调用 Environment  
4. 合成 `tool_call_output`（aborted，提示 denied）  
5. 下一轮模型改策略或向用户解释  

**失败**：以为 deny 会删掉 tool_call——不会；配对完整是不变量。

**落点**：ApproveFn、Server 审批模式（如只读自动允许）。

---

## S5 Steer 插话

**目标**：模型正在跑长任务，用户追加「先别删文件，只分析」。

**逐步**：

1. Task 进行中，宿主调 `session.steer([userText("...")])`  
2. 返回 true，入 steeringQueue  
3. 当前轮工具收尾后，投递 `[user_steering]` 用户消息（写入 Trace）  
4. 并入下一 Request 输入  

若返回 **false**：当前没有 Task——应 `run` 新任务，而不是 steer。

**落点**：Web「发送」在 running 态应走 steer；idle 走 run。

---

## S6 取消与 carry-over

**目标**：用户点停止。

**逐步**：

1. `signal.abort`  
2. 引擎停 LLM/工具，产出 `abort`  
3. 构造补发：已完成工具的结构化 output；未完成的 interrupted 占位  
4. `run` 返回；下次 `run` 把 carry-over 前置  

**失败**：把中断当成「没发生」删 Trace——破坏配对与分析页。

**落点**：abort 贯通；Session 在引擎未就绪时的 Trace 自写路径。

---

## S7 上下文压缩

**目标**：对话很长，触发压缩或用户手动 compact。

**逐步**：

1. 阈值满足（上下文占用/轮次）或 `session.compact()`  
2. `compaction_begin`  
3. summarize：额外 LLM 请求出摘要；或 discard  
4. 成功：`createLLM` 换新对象，累计 token 交接，Trace rotate  
5. `compaction_end`；后续 run 带着摘要前缀继续  

**失败**：压缩请求本身失败——保留旧上下文，不硬切空。

**落点**：`system_config` 压缩设置；`ContextEngine` 压缩路径。

---

## S8 子 Agent

**目标**：「让子 Agent 去调研子目录并汇报」。

**逐步**：

1. 父模型调 `run_subagent`  
2. 审批通过后 SubagentRunner 开子 Session（深度 ≤1）  
3. 子 Session 自有 Trace；父 Trace 写 subagent 指针事件  
4. 子结束，结果作为父的 tool output 回流  
5. 父模型汇总  

**失败**：子再调 run_subagent——默认深度拒绝。

**落点**：subagent 工具与 `MAX_SUBAGENT_DEPTH`。

---

## S9 Goal 多轮

**目标**：GOAL 文件描述「完成数据分析报告」，自治多轮。

**逐步**：

1. `run(prompt, { goal })`  
2. `runGoalLoop` 每轮调用一次普通 `runTask`  
3. 每轮输入带 goal 协议块；轮次输入会 yield 到流上（与普通 run 不同）  
4. 读 GOAL 状态：continue / complete / blocked  
5. 结束时一条 `goal_finished`  

**失败**：GOAL 文案含糊导致无限 continue——要预算与退出条件。

**落点**：`goal/goal-loop.ts`、GOAL 文件约定。

---

## S10 Web SSE 路径

**目标**：浏览器里点发送，看到流式输出。

**逐步**：

1. Web API 客户端提交 Task  
2. `SessionManager.startTask` → `session.run`  
3. `drive` 循环：读引擎 yield，写 SSE（带单调 id）  
4. 前端按 OmniMessage 聚合 partial→完整  
5. 断线用 Last-Event-ID 补发或要求 resync  

**失败**：前端自己维护「权威 messages」并回传——双真源。

**落点**：`server/src/runtime/session-manager.ts`、web omni 渲染。

---

## S11 Trace 崩溃恢复

**目标**：进程被杀后，重启仍能打开会话。

**逐步**：

1. 崩溃前已 append 的完整行仍在  
2. 可能残行：恢复时补换行再续写  
3. `resumeTrace` 重建引擎可续状态  
4. 用户继续 `run`  

**失败**：只恢复 SQLite 会话列表但 Trace 文件被删——列表有、内容空。

**落点**：备份 `traces/`；理解「文件真源」。

---

## S12 显式使用 Skill

**目标**：用户指定「用 data-analysis skill 做…」。

**逐步**：

1. 消息带 `[use_skills] data-analysis`（或 UI 点选）  
2. 系统提示已有该 Skill 元数据；模型按指示 `read_file` 其 SKILL.md  
3. 后续步骤遵循 Skill 正文（工具调用仍走正常审批）  

**失败**：以为有「skill 工具」——没有；读文件即加载。

**落点**：Skill 正文质量；安装是否在 agent_state。

## 本章总结

1. 每个 Task 都是「多轮 Request，直到无 tool_call」。  
2. 多工具时务必分清 **流序与上下文序**。  
3. 拒绝、中断、压缩都不会破坏「可回放」——它们变成事件与补发。  
4. Goal/Subagent/Skill 是产品能力，但仍落在同一 OmniMessage/Trace 世界上。  
5. Web 只是 SSE Human；真源永远是引擎与 Trace。
