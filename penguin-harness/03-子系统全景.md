## 1. 怎么用这张全景

你会反复遇到两类问题：

- 「这个功能在哪个包？」→ 看挂点路径。  
- 「我该改文件还是改代码？」→ 看「何时改」；能改 Skill/配置就别动引擎。

官方短文仍在 `packages/docs/content/`；本章是把它们串成一张**学习用地图**。

## 2. 核心主干

### 2.1 Agent 与 `createAgent`

Agent 是「有一份持久行为定义的执行主体」。`createAgent` 要么在空目录初始化默认 Agent State（含预装 Skill），要么按 `agentId` 加载已有目录。一个 Agent 可以服务多个 Workspace，但 **Agent State 只有一份**——人格与 Skill 不因工作区复制多份。

创建 Session 时才绑定 Workspace 与模型。也就是说：换目录干活、换模型思考，都是 Session 级决策；Agent 级是「我是谁、我会什么」。

- **挂点**：`packages/core/src/agent.ts`  
- **何时改**：默认装配、子 Agent 深度上限、系统提示装配策略。

### 2.2 Session

Session 是 SDK 对 Human 的主 API：`run` / `steer` / `compact`，以及 Goal 入口。它故意把贵的事（MCP 连接、构建 LLM、new ContextEngine）放进第一次 `run` 的 `ensureReady`，这样构造 Session 可以瞬间完成，连接过程能以事件流形式显示在 UI。

Session 还处理：无视觉模型时的图片折路径、上次中断的 carry-over 输入、abort 时在引擎尚未创建的情况下自己写 Trace。

- **挂点**：`packages/core/src/session.ts`  
- **何时改**：bootstrap 生命周期、Goal 接线、标题生成旁路。

### 2.3 ContextEngine

这是 ReAct 编排内核。它维护线性上下文推进，在 LLM 与 Environment 之间调度，并把可观察动作写入 Trace。它实现：轮生命周期、逐工具审批、工具并发、MergeQueue 汇流、中断补发、自动重连、上下文压缩。

你几乎不应在业务插件里「再写一个循环」——产品扩展点在 Skill、审批策略、模型配置。

- **挂点**：`packages/core/src/engine/context-engine.ts`  
- **何时改**：循环语义本身（高风险）；更常见是调 `max_turns`、重连次数、压缩阈值。

### 2.4 OmniMessage

OmniMessage 是协议信封：分片（partial_*）、完整 model 消息、事件（request_begin/end、approval_decision、abort、compaction_*、subagent 指针等）。引擎不做厂商协议转换——那是 LLM 适配器的事；引擎只搬运 OmniMessage。

- **挂点**：`packages/core/src/omnimessage/`  
- **何时改**：新增事件类型时，必须同步 Web 渲染、Trace 过滤规则、文档。

### 2.5 Trace

Trace 是 append-only JSONL。一份文件对应一段完整模型上下文；压缩轮转新文件。它是 Session 恢复的唯一事实来源。写入器对大记录用单次 write，避免撕裂；恢复前探测残行。

- **挂点**：`packages/core/src/trace/writer.ts`、`resume.ts`  
- **何时改**：落盘性能、容错策略；不要轻易改「完整消息才落盘」的契约。

## 3. 模型与提示词

### 3.1 GenerativeModel 与 AgentHub

`GenerativeModel` 实现 `LLMInterface`：把 OmniMessage 译成网关请求，再把流译回 OmniMessage。真正的 Provider 差异在 `@prismshadow/agenthub`。core 保持「薄模型层」，因此接 OpenAI 兼容网关（含 newapi）不需要改 ContextEngine。

模型身份永远是 `(provider, model_id)`。禁止用字符串拼接猜测「这是哪个厂商」。

### 3.2 配置从哪里来

- **Project**：`.project_config.toml`——模型表与凭据（0600）。  
- **环境变量回退**：条目缺 key 时可用 `DEEPSEEK_API_KEY`、`OPENAI_API_KEY` 等。  
- **Agent**：`system_config.yaml` 的运行参数、`thinking_level`；`AGENTS.md` 人格与规范。  
- **Session**：创建时锁定模型；UI `/model` 通常开启新 Session。

### 3.3 系统提示如何装配

State 层把 AGENTS.md、Skill **元数据**、工具相关说明等装配成 system prompt。Skill 正文不全部塞进提示词——否则 Token 会被说明书吃光。

- **挂点**：`packages/core/src/llm/`、`state/model-catalog.ts`、`state/*config*`  
- **何时改**：新厂商优先走 AgentHub/自定义端点；新「规矩」优先改 AGENTS.md / Skill。

## 4. 工具与执行世界

### 4.1 设计取向

内置工具很少：`read_file` / `edit_file` / `write_file` 做精确文件手术；`exec_command`（及 `input_command`）做通用壳；子 Agent 与图像工具按需出现。每个工具都要值得占用 schema Token。

### 4.2 Environment 统一收尾

工具实现只需 yield 增量输出；Environment 负责：分帧、超时、截断（默认保留头部约 16k 字符）、stop_reason 归并、空输出补 `[no output]`、把 note/图片附在截断范围外。错误折叠为 `tool_call_output`，供模型阅读。

过长输出还可在 Session 侧归档 recovery 文件——用户所见窗口与模型所见窗口仍一致，完整文本另存。

### 4.3 MCP

配置的 MCP Server 在首次 `listTools` 时连接；Session 用 `mcp_connect_begin/end` 包裹，失败可见。动态工具与内置工具一样进入审批与 Trace。

- **挂点**：`packages/core/src/environment/`  
- **何时改**：新通用能力 → 新 BuiltinTool 或 MCP；领域步骤 → 仍优先 Skill。

## 5. 人机协作

### 5.1 审批 ApproveFn

每个完整 `tool_call` 触发一次 `approve`。未注入时默认偏保守（全拒绝）。决策写入 `approval_decision` 事件。deny 则合成 aborted 输出（文案提示用户拒绝），模型据此改主意。

CLI 在终端问；Server 把模式与人工决策落到运行时/SQLite，经 SSE 驱动 Web UI。

### 5.2 steer

运行中插话：入队为 `[user_steering]`，随下一 Request 输入投递并落 Trace。没有 Task 时返回 false——宿主应改发普通 Task。这与 DSH Inbox 的 next-turn/next-step 两桶模型不同。

### 5.3 中断 signal

任意时刻 abort：产出 abort 事件，构造 carry-over（已完成工具结果结构化补齐，未完成工具占位），保证 tool_call 与 output 配对，便于下次 run 继续。

- **挂点**：`interfaces.ts` 的 ApproveFn；`ContextEngine.steer`；Server `approvals.ts`  
- **何时改**：产品审批策略（自动允许只读等）在 Human/Server；不要在 Environment 里偷偷放行未审批调用。

## 6. Skill 与自进化

### 6.1 形态与渐进加载

Skill = 目录 + `SKILL.md` frontmatter + 正文 + 可选附件。系统提示经占位符只注入元数据；模型匹配后用 `read_file`/Shell 读全文。也可在消息里用 `[use_skills]` 显式点名。

文件即真源：无缓存；Agent 自己也能编辑优化 Skill（这是「自进化」故事的技术基础）。

### 6.2 安装

装到 `agent_state/skills/<name>/`，整目录替换。`default_agent` 初始化预装库（`preinstall: false` 的除外）。库本体在 npm 包 `@prismshadow/penguin-skills`。

### 6.3 Snapshot 与 Benchmark

`snapshots/` 存 Agent State 版本包；`benchmarks/` 存题库与得分。评测→找失分→改 Skill→发 N+1，形成闭环。

- **挂点**：`packages/skills`、`state` 中 skill 安装、文档 `skills.zh.md`  
- **何时改**：业务能力优先新增/修改 SKILL.md，而不是加专用工具。

## 7. Goal、Subagent、压缩

### 7.1 Goal

`run(..., { goal })` 进入外环：每轮一个普通 Task，输入带 goal 协议块，直到 GOAL 状态完成/阻塞或预算用尽。外环不替代内环 ReAct。

### 7.2 Subagent

`run_subagent` / `input_subagent`：子 Session 有自己的 Trace；父 Trace 留指针事件。默认深度 1，防止无限套娃。

### 7.3 Compaction

阈值（上下文占用/轮次）或手动 `compact`：`summarize` 或 `discard`。成功则换新 LLM 对象并可能轮转 Trace 文件；失败则保留原上下文，下次再试。压缩请求本身也走 LLM，有独立重连预算。

- **挂点**：`goal/goal-loop.ts`、subagent tools、`ContextEngine.compact*`  
- **何时改**：长程任务策略（Goal 文案、压缩模式）多于改引擎。

## 8. Server 与产品面

### 8.1 SessionManager

Web 的执行枢纽：创建/恢复会话、`startTask`、`drive` 把 OmniMessage 推上 SSE、处理断线补发语义。引擎逻辑零拷贝委托给 core。

### 8.2 鉴权、项目、用量、调度

多用户登录、项目授权、用量聚合在 Server+SQLite。定时任务定义仍在文件层 `schedule/*.toml`，由 Server 调度触发。

### 8.3 Web 与 Desktop

Web 是协议渲染器：会话列表、轨迹、模型页、Skill 库、评估中心。Desktop 内嵌 server，打开即登录，并可附着已运行的 CLI server。

- **挂点**：`packages/server/src/runtime/`、`packages/web/src`、`packages/desktop`  
- **何时改**：API/UI；不要在 React 组件里实现工具循环。

## 10. 按需求反查

```text
对话循环异常          → ContextEngine + message-flow 文档
模型 401/路由错       → project_config / AgentHub / 环境变量
工具超时或截断        → Environment 配置与 recovery note
想教模型新流程        → Skill
要自治直到目标完成    → Goal
要并行委派            → Subagent（注意深度）
上下文爆了            → Compaction 设置
Web 看不到历史        → Trace 文件是否在；是否读错 session
多用户权限            → Server auth / project
```

## 11. 本章总结

1. 主干五件套：**Agent、Session、ContextEngine、OmniMessage、Trace**——各有单一职责。  
2. 模型走 **AgentHub + 二元组身份**；提示词装配刻意不塞满 Skill 正文。  
3. 工具少而硬，**Environment 统一收尾**；审批在 Human 边界。  
4. **Skill 是一等扩展机制**；Goal/Subagent/压缩是引擎能力。  
5. Server/Web 是 Human 与索引，**不争 Trace 真源**。
