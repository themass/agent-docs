## 1. 这是什么？

**PenguinHarness**（仓库名 `penguin-harness`，npm 上常见 `@prismshadow/penguin-*`）是 Prism-Shadow 开源的 **Agent 构建与运行平台**。语言是 **TypeScript**，要求 **Node ≥ 24**，协议许可 **Apache-2.0**。

它不是「又一个 while 循环 + 几个工具的 demo」，而是一套已经产品化的系统：

- 有 **执行引擎**（`ContextEngine`）：负责 ReAct——调模型、审批工具、执行工具、再调模型。  
- 有 **统一消息协议**（`OmniMessage`）：流式输出、落盘历史、引擎内部，用同一种信封。  
- 有 **文件型 Agent 状态**：人格、Skill、密钥、模型表都是磁盘上的文件，可编辑、可快照。  
- 有 **三种 Human 表面**：CLI（`penguin`）、浏览器 Web（默认 `http://127.0.0.1:7364`）、桌面 Electron——共用同一套 core 和同一数据目录。

README 上的产品主张可以压缩成三句：

1. **更少工具、更低成本**，对 DeepSeek 等开放模型友好。  
2. **用 Agent 构建 Agent**——一句话生成带检索/脚手架的应用。  
3. **自进化**——Benchmark、Snapshot、Skill 自评自改。

和「智能体框架」一词对照时，更准确的说法是：

| 说法 | 是否贴切 |
|------|----------|
| Agent 运行时 / Harness | ✅ 核心是跑 Session |
| Agent 构建平台 | ✅ 强调 Skill、脚手架、评估中心 |
| Cordis 式可逆插件底座 | ❌ **没有**插件运行时 |
| 训练框架 | ❌ 不管权重 |

一句话记住：

> **固定三接口的 ReAct 引擎 + OmniMessage/Trace 真源 + 文件即定义的 Skill/配置 + 产品化 CLI/Web/Desktop。**

## 2. 给谁用、怎么跑起来

### 2.1 三类用户

| 角色 | 典型诉求 | 入口 |
|------|----------|------|
| 终端用户 / 研究者 | 打开就能聊、能改文件、能看轨迹 | 桌面 App 或 `penguin web` |
| 应用开发者 | 嵌入自己的程序、换模型、写 Skill | `createAgent` → `session.run` |
| 自托管运维 | 多用户、常驻服务、用量统计 | `penguin server` + 反向代理 |

数据默认落在 **`~/.penguin/data`**（环境变量 `PENGUIN_HOME` 可改）。桌面端与命令行**共用**这份数据；同一目录同一时刻只应跑一个服务端。

### 2.2 最小上手（已安装 CLI）

```bash
penguin web
# 浏览器打开 http://127.0.0.1:7364
# 首次：用户名 admin，密码看终端边框提示（形如 penguin-1234），登录后尽快改掉
# 然后在「模型」页配 API Key / 自定义端点
```

### 2.3 从本仓库开发

```bash
cd /Users/gqli/work/deepagents/penguin-harness
pnpm install
pnpm build
pnpm penguin web          # 脚本常把 PENGUIN_HOME 指到 ~/.penguin/dev-data
# 或前后端热更：
pnpm dev                  # concurrently server + web
```

### 2.4 SDK 最小形状（心智模型）

```ts
const agent = await createAgent({ agentId: "default_agent" });
const session = await agent.createSession({ workspaceDir: process.cwd() });

for await (const msg of session.run([userText("整理 data/ 下的 CSV")], {
  approve: async () => "allow",
})) {
  // msg 是 OmniMessage：partial_* / 完整消息 / 事件
}
```

你不需要实现「Human 接口类」——**调用 `session.run` 本身就是 Human 边界**。

## 3. 解决什么问题（设计动机）

### 3.1 工具太多 → Token 与错误路径爆炸

很多 Agent 栈把「能做的事」堆成几十个工具。模型每轮都要在巨大 schema 里做选择，调用次数与失败重试一起涨。Penguin 的取向相反：**内置工具刻意很少**——精确读写文件用专用工具，其余交给 `exec_command`；每个工具都要「对得起它占用的 schema Token」。

### 3.2 「框架胶水」太重 → 想用 Agent 生成 Agent

用 LangChain 类库手写流水线，人是瓶颈。Penguin 把「做 Agent 应用」本身产品化：Skill 库里有 `agent-creation`、`penguin-sdk`、`benchmark-design` 等，让模型去脚手架、去评测、去出 N+1 版。

### 3.3 历史不可回放 → 无法调试与进化

若对话只活在内存数组，崩溃即丢，也无法做轨迹观测与回归。Penguin 把 **Trace JSONL** 定为恢复唯一事实来源：流出去的同时落盘，分析页与 resume 都读它。

### 3.4 扩展方式两极分化

一端是「改引擎源码」，一端是「巨型插件系统」。Penguin 选第三条：**没有插件运行时**；领域能力用 `SKILL.md` 目录表达——元数据进系统提示，正文按需 `read_file`。可编辑、可版本、可快照。

## 4. 功能全景（展开讲）

下面不是功能名清单，而是「它在产品里意味着什么」。

### 4.1 对话与工具执行

一次用户发送 = 一次 **Task**。Task 里可以有多轮 **Request**（每次 LLM 调用）。模型若产出 `tool_call`，会先走 **ApproveFn**（人审或策略），再进 **Environment** 执行。文件工具带行号/精确替换；Shell 跑命令；子 Agent 可委派。

### 4.2 Skill 系统

Skill = 目录 + `SKILL.md`（+ 可选 icon/附件）。已安装 Skill 在 `agent_state/skills/<name>/`。系统提示只注入 **name+description**；真正长文在任务匹配时由模型自己读文件——**渐进式披露**，省 Token。

分组大致包括：办公（数据分析、爬取）、软件开发（Web/工程）、AI 应用（SDK/CLI/本地推理）、Agent 调优（创建/评测/优化）。

### 4.3 模型接入

身份恒为 **`(provider, model_id)`** 二元组。Project 的 `.project_config.toml` 持有模型表与凭据；`api_key` 空时可回退环境变量（如 `DEEPSEEK_API_KEY`）。任意 OpenAI 兼容端点可自定义（含公司 newapi 网关）。思考等级 `none|low|medium|high|xhigh` 可配置，可在单次 run 覆盖。

### 4.4 Goal 模式

不是单轮问答，而是「目标文件说停才停」：外环每轮开一个普通 Task，直到 complete/blocked 或预算耗尽。适合长程自治。

### 4.5 审批、轨迹、压缩、评测

- 审批：每个 tool_call 一次决策，写入审计事件。  
- 轨迹：Web「轨迹观测」读 Trace。  
- 压缩：上下文或轮次阈值触发 summarize/discard。  
- 评测：`benchmarks/` + Snapshot，支撑自进化叙事。

### 4.6 Web / Desktop 产品能力

多会话、Agent/技能/模型管理、用量统计、评估中心、定时任务（schedule toml）。Desktop 打开即登录，内嵌服务端。

## 5. 设计思路：五条总纲（每条有论证）

### 5.1 一个协议，三种职责

**OmniMessage** 同时是：

1. SDK 对外流式接口  
2. Trace 落盘行格式  
3. 引擎内部通货  

论证：若「流里一种结构、磁盘另一种、喂模型又一种」，转换层会成为 bug 温床，且「用户所见 ≠ 模型所见」。Penguin 要求三者同构（分片例外：partial 不进 Trace，完整消息会补写）。

### 5.2 三接口，无 Human 类

- **Human**：就是 `session.run(newMessages, { approve, signal })`  
- **LLM**：`LLMInterface.streamGenerate`  
- **Environment**：`listTools` / `executeTool`  

论证：CLI 与 Server 只是不同的 Human 实现；换沙箱只换 Environment；换厂商只换 AgentHub 背后的适配。引擎内核保持干净。

### 5.3 事实来源分层（文件 > 索引）

| 层 | 承担 | 不承担 |
|----|------|--------|
| 文件（`~/.penguin/data`） | 可编辑定义 + Trace 历史 | 计算 |
| SDK | 让消息流动 | 多用户持久化 |
| Server | 常驻、鉴权、SSE、SQLite **索引/用量** | 争当对话真源 |
| CLI/Web | 渲染与交互 | 业务状态 |

论证：CLI 与 Web 必须能混用同一 Agent；若真源在 SQLite 而 CLI 只认文件，必然分叉。

### 5.4 无插件，有 Skill

官方文档写得很硬：**Penguin has no plugin mechanism**。扩展靠 Skill 目录与可替换 LLM/Env 实现。

论证：插件系统要解决热加载、依赖、权限、版本兼容——成本高。Skill 是「给模型看的说明书 + 资源」，用文件系统版本管理即可，且 Agent 自己能改自己的 Skill。

### 5.5 错误收敛为消息

LLM 与 Environment **不向引擎抛裸异常**；结果带六值 `stop_reason`：`completed | failed | aborted | timeout | malformed | auth`。除 `auth` 外，LLM 侧失败会引擎内重连（有上限、指数退避）。

论证：抛异常会打断 async generator 契约，前端与 Trace 难以统一处理；把失败变成模型可读的消息，才符合 Agent 自我修正的路径。

## 6. 和 DeepSeek Harness / LangChain 的对比

| 维度 | PenguinHarness | DeepSeek Harness | 典型 LangChain App |
|------|----------------|------------------|--------------------|
| 扩展 | Skill 文件 | Cordis 插件树 | Chain/Tool 类组合 |
| 循环 | 固定 ContextEngine | 默认可替换 loop 插件 | 自写或预置 agent executor |
| 历史真源 | Trace JSONL | SessionEvent 日志 | 常为内存或自选 DB |
| 插话 | `steer` | Inbox 两桶 | 各异 |
| 产品面 | 自带 Web/Desktop/评测 | 偏框架 + Web profile | 通常自建 UI |
| 心智负担 | 六层运行模型 + 三接口 | Profile/Bundle/Seam/事件域 | 抽象层多 |

选型直觉：

- 要 **可逆插件、一切可替换循环** → 偏 DSH。  
- 要 **开箱产品 + 文件 Skill + 低工具数** → 偏 Penguin。  
- 要 **嵌进已有 Python 数据栈** → 可能仍偏 LangChain/自研，但可只把 Penguin 当外部 runner。

## 7. 仓库你会看到什么

```text
penguin-harness/
  packages/
    core/       # 引擎真相：context-engine、omnimessage、llm、environment、state、trace
    cli/        # penguin 命令
    server/     # Hono + SQLite 索引 + SessionManager + SSE
    web/        # React SPA（只渲染 OmniMessage）
    skills/     # 内置 SKILL.md 库（npm 包）
    desktop/    # Electron
    docs/       # 官网文档内容（architecture.zh.md 等）——权威短文
    landing/    # 营销站
  doc-sn/       # 本目录：学习向中文长文
  examples/     # 示例
```

读官方短文从 `packages/docs/content/architecture.zh.md` 进；读故事与对照从本 `doc-sn` 进。

## 9. 本章总结

1. PenguinHarness 是 **产品化的 TS Agent 平台**：引擎 + 协议 + 文件状态 + CLI/Web/Desktop。  
2. 核心主张：**少工具、OmniMessage 三职合一、Trace 为历史真源、Skill 代替插件**。  
3. Human 不是接口类，**`session.run` 就是边界**。  
4. 与 DSH 最大差别：无 Cordis；扩展与产品形态不同。  
5. 本地 Web 地址默认是 **http://127.0.0.1:7364**。
