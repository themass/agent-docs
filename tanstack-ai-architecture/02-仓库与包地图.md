# 02. 仓库与包地图

## 先从包族定位代码

这个仓库是 pnpm workspace + Nx monorepo。修改前先判断能力属于 Core、Client、Provider、Framework 还是 Optional package；不要为了一个 Provider 特性直接把逻辑塞进 `packages/ai`。

## 顶层目录

| 路径 | 作用 |
|---|---|
| `packages/` | 发布到 npm 的公共包，绝大多数 `@tanstack/*` 运行时和 Provider 都在这里 |
| `docs/` | 面向使用者的官方文档与 API 文档源文件 |
| `examples/` | React、Solid、Vue、Svelte、Vanilla 等示例应用，默认私有、不发布 |
| `testing/e2e/` | Playwright + aimock 的跨包端到端测试与测试路由 |
| `codemods/` | 内部迁移脚本 |
| `scripts/` | 文档、模型元数据、发布和维护脚本 |
| `.agents/` / `.claude/` / `.grok/` | 仓库协作规则与技能文件 |

构建系统使用 Nx，包管理器由根 `package.json` 固定为 `pnpm@11.9.0`。贡献规范要求改动完成后覆盖相关的单元、类型、构建、文档链接以及 E2E 路径。

## Core 包：`@tanstack/ai`

```text
packages/ai/src/
├── activities/
│   ├── chat/                 TextEngine、Tools、Middleware、MCP、Subagents、StreamProcessor
│   ├── embed/                Embedding 活动
│   ├── evaluate/             choice / score / boolean 决策活动
│   ├── files/                File API 活动
│   ├── generateAudio/        音频生成
│   ├── generateImage/        图像生成
│   ├── generateVideo/        视频生成
│   ├── generateSpeech/       TTS
│   ├── generateTranscription 语音转文本
│   ├── generateVoice/        声音创建
│   ├── generateWorld/        World generation
│   ├── generateLiveVideo/    实时视频 / 直播生成
│   ├── rerank/               重排序
│   └── summarize/            摘要
├── byok/                     Provider key / keyed adapters
├── interrupts*.ts            定义、序列化、恢复与校验
├── middlewares/              内置内容安全、OTel、Tool Cache 等
├── realtime/                 Realtime 事件与连接类型
├── stream-to-response.ts     SSE / HTTP / JSON / durability 边界
├── stream-to-websocket.ts    WebSocket 适配
├── types.ts                  消息、工具、活动和 AG-UI 事件公共类型

```

Core 的公共出口集中在 `packages/ai/src/index.ts`。`activities/index.ts` 再汇总各活动，因此新增公共能力时必须同时考虑源码模块、类型导出、包 `exports` 和文档/API 生成。

| 包 | 主要职责 | 关键入口 |
|---|---|---|
| `@tanstack/ai-client` | Headless 客户端、连接适配器、ChatClient、GenerationClient、RealtimeClient、恢复和本地存储 | `chat-client.ts`、`connection-adapters.ts` |
| `@tanstack/ai-react` | React `useChat`、generation hooks、Realtime hooks、可选 chat UI | `use-chat.ts`、`chat-ui/` |

| `@tanstack/ai-solid` | Solid hooks 与 UI | `src/` |
| `@tanstack/ai-svelte` | Svelte 5 bindings | `src/` |
| `@tanstack/ai-preact` | Preact bindings | `src/` |
| `@tanstack/ai-angular` | Angular signals | `src/` |

`@tanstack/ai-react-ui`、`ai-vue-ui`、`ai-solid-ui` 是迁移/兼容包，当前文档建议从主框架包的 `/ui` 子路径导入。

## Provider 包

Provider 包可以粗分为四类：

### 1. 原生模型 Provider

`ai-openai`、`ai-anthropic`、`ai-gemini`、`ai-grok`、`ai-groq`、`ai-mistral`、`ai-cohere`、`ai-elevenlabs` 等。

它们通常提供：

- `text` Adapter：Chat、Tool Calling、Reasoning、Structured Output。
- 专属 Media Adapter：Image、Audio、Video、TTS、Transcription、Embedding 等。
- Provider tool converter：把统一 Tool 转成供应商函数或托管工具。
- 模型元数据：模型 ID、输入模态、工具能力、价格和 Provider options。

### 2. 兼容或网关 Provider

`ai-openrouter`、`ai-vercel-gateway`、`ai-llmgateway`、`ai-lovable`、`ai-bedrock`、`ai-cloudflare`、`ai-vertex`、`openai-base` 等，重点是把兼容协议或托管网关的差异收敛到统一 Adapter。

### 3. Harness Adapter

`ai-claude-code`、`ai-codex`、`ai-grok-build`、`ai-opencode`、`ai-acp`。它们不是简单的 HTTP 模型调用，通常需要本地工具、会话、Sandbox 或 Agent Client Protocol 能力，因此会声明 Middleware Capability 或依赖 `ai-sandbox`。

### 4. Media 专用 Provider

`ai-fal`、`ai-worldlabs`、`ai-reactor`、`ai-byteplus`、`ai-octane` 等主要面向图像、视频、声音或世界生成。

## Agent 能力包

| 包 | 边界 |
|---|---|
| `ai-mcp` | Host 侧 MCP client/server、tools/resources/prompts、stdio、session、auth、task |
| `ai-memory` | Memory Middleware + in-memory、Redis、Mem0、Hindsight、Honcho Provider |
| `ai-compaction` | 上下文窗口压缩 Middleware |
| `ai-persistence` | Store Contract、Transcript/Run/Interrupt/Artifact/Blob/Metadata 持久化与 reconstruct |
| `ai-durable-stream` | `StreamDurability` 的 HTTP durable-streams 实现，不拥有事件本身 |
| `ai-code-mode` | 把 Tool binding 暴露给模型，让模型生成并执行 TypeScript orchestration program |
| `ai-sandbox` | 统一 SandboxHandle、Workspace、Process、FS、Git、Snapshots、Policy、Durability |
| `ai-isolate-*` | Code Mode 的具体执行后端：Node、QuickJS、Cloudflare、Daytona、E2B 等 |
| `ai-skills` | 将 `SKILL.md` 解析成可装载 Middleware 与资源工具 |
| `ai-event-client` | Devtools、可观测性与运行时事件的类型化事件客户端 |
| `ai-devtools` | Core Devtools 面板和 Provider/Framework 侧集成 |

## 依赖方向

```mermaid
flowchart LR
  Core[@tanstack/ai] --> Utils[ai-utils]
  Client[ai-client] --> Core
  Framework[ai-react / vue / solid / svelte / preact / angular] --> Client
  Provider[ai-openai / anthropic / gemini / ...] --> Core
  Persistence[ai-persistence] --> Core
  Memory[ai-memory] --> Event[ai-event-client]
  MCP[ai-mcp] --> Core
  Code[ai-code-mode] --> Sandbox[ai-sandbox]
  Isolate[ai-isolate-*] --> Sandbox
  Dev[ai-devtools] --> Core
  Dev --> Event
```

理解这个方向很重要：Core 不应依赖某个 UI 框架；Provider 不应持有 `ChatClient`；Persistence 通过 Middleware/Store Contract 进入 Core，而不是修改 TextEngine 的数据库代码。

## 修改任务到源码落点

| 目标 | 首选落点 | 同步检查 |
|---|---|---|
| 增加新 Provider 的 Chat | `packages/ai-<provider>/src/adapters/text.ts` | 模型元数据、Tool converter、wire tests、exports |
| 修改 Agent loop | `packages/ai/src/activities/chat/index.ts` | stream events、tool calls、interrupt、structured output、E2E |
| 增加公共流事件 | `packages/ai/src/types.ts` + normalize/processor | AG-UI 合规、SSE/HTTP/WS、client reducer |
| 增加客户端传输 | `packages/ai-client/src/connection-adapters.ts` | abort、truncation、reconnect、run correlation |
| 增加 UI 框架支持 | 新 `packages/ai-<framework>` | headless 行为、类型测试、框架 smoke |
| 增加持久化字段 | `ai-persistence/src/types.ts`、middleware、reconstruct | Store conformance、迁移、重连和中断测试 |
| 增加工具审批 | Core interrupt 定义/校验 + client interrupt manager | 全批次校验、重复提交、恶意输入、恢复 |
| 增加 Code Mode isolate | `ai-sandbox/src/contracts.ts` + 新 provider | capability、abort、limits、conformance |
| 增加文档 | `ai/docs/` + 本架构文档必要章节 | `pnpm test:docs` |
