# AI Agent 框架上下文压缩与记忆机制深度对比

> **基于源码实证分析** - 本文档严格基于各框架的源码实现，确保准确性

## 📊 核心发现总结

| 框架 | 是否有内置压缩 | 实现方式 | 关键特性 |
|------|--------------|---------|---------|
| **AgentScope** | ✅ 是 | `CompressionConfig` + LLM摘要 | 结构化摘要、标记机制、可自定义schema |
| **crewAI** | ❌ 否（但有统一记忆） | `UnifiedMemory` + EncodingFlow/RecallFlow | 向量数据库、LLM分析、智能召回 |
| **smolagents** | ❌ 否 | `step_callbacks`手动管理 | 用户自定义回调清理内存 |
| **MetaGPT** | ❌ 否 | 基础Memory类 | 简单列表存储+关键词检索 |
| **deer-flow** | ✅ 是 | LangChain中间件 | `SummarizationMiddleware` |
| **Hermes Agent** | ✅ 是 | 六层记忆架构 | 工作记忆+长期记忆+向量检索 |

## 🔍 深度框架分析

### 1. AgentScope - 最完善的内置压缩机制

#### 源码位置
- `agentscope/src/agentscope/agent/_react_agent.py`
- `agentscope/docs/tutorial/en/src/task_agent.py`

#### 实现架构

```python
# 启用压缩的配置
compression_config=ReActAgent.CompressionConfig(
    enable=True,
    agent_token_counter=CharTokenCounter(),  # Token计数器
    trigger_threshold=10000,                 # 触发阈值
    keep_recent=3,                           # 保留最近3条不压缩
)
```

#### 压缩流程（5步）

1. **监控Token计数**：实时跟踪memory中的token数量
2. **识别待压缩消息**：通过`exclude_mark`标记未压缩的消息
3. **保留最近上下文**：保持`keep_recent`条最新消息不被压缩
4. **LLM生成结构化摘要**：将旧消息发送给LLM生成摘要
5. **标记并存储**：
   - 原消息标记为`MemoryMark.COMPRESSED`
   - 从后续检索中排除（`exclude_mark=MemoryMark.COMPRESSED`）
   - 摘要单独存储在memory中

#### 关键创新：**标记机制而非替换**

```python
# 重要：不是删除旧消息，而是标记它们
# 旧消息仍然保留，但被标记为COMPRESSED
# 通过exclude_mark在检索时过滤掉
update_messages_mark(mark=MemoryMark.COMPRESSED)
update_compressed_summary(summary)
```

#### 默认摘要结构（5个字段）

```python
class DefaultSummary(BaseModel):
    task_overview: str          # 用户核心请求和成功标准
    current_state: str          # 已完成的工作、文件和输出
    important_discoveries: str  # 技术约束、决策、错误和失败方法
    next_steps: str            # 完成任务所需的具体行动
    context_to_preserve: str   # 用户偏好、领域细节和承诺
```

#### 高度可定制化

```python
# 自定义摘要schema
class CustomSummary(BaseModel):
    main_topic: str = Field(max_length=200)
    key_points: str = Field(max_length=400)
    pending_tasks: str = Field(max_length=200)

# 自定义配置
compression_config=ReActAgent.CompressionConfig(
    enable=True,
    summary_schema=CustomSummary,           # 自定义结构
    compression_prompt="...",               # 自定义提示词
    summary_template="...",                 # 自定义展示模板
    compression_model=faster_model,         # 可用小模型降低成本
)
```

#### 优势
- ✅ **完整性最高**：端到端的自动化压缩方案
- ✅ **灵活性最强**：可自定义schema、prompt、template、model
- ✅ **保留原始数据**：标记机制允许随时恢复完整历史
- ✅ **成本优化**：支持使用小模型进行压缩
- ✅ **工具调用保护**：确保tool use和result成对保留

### 2. crewAI - 统一记忆系统（非传统压缩）

#### 源码位置
- `crewAI/lib/crewai/src/crewai/memory/unified_memory.py` (1063行)
- `crewAI/lib/crewai/src/crewai/memory/encoding_flow.py` (548行)
- `crewAI/lib/crewai/src/crewai/memory/recall_flow.py` (14.6KB)

#### 核心设计理念

**不是传统的"压缩"，而是"智能编码+自适应召回"**

```python
class Memory(BaseModel):
    """Unified memory: standalone, LLM-analyzed, with intelligent recall flow."""
    
    llm: BaseLLM | str                    # LLM用于分析
    storage: StorageBackend               # 向量数据库（默认LanceDB）
    embedder: Any                         # 嵌入模型
    recency_weight: float = 0.3           # 时效性权重
    semantic_weight: float = 0.5          # 语义相似度权重
    importance_weight: float = 0.2        # 重要性权重
```

#### EncodingFlow - 编码流程（5步并行流水线）

#### RecallFlow - 自适应深度召回

```python
class RecallFlow(Flow[RecallState]):
    """Adaptive-depth recall using confidence-guided exploration"""
    
    # 三层置信度策略
    if confidence > 0.8:
        return results  # 高置信度：直接返回
    elif confidence < 0.5:
        deep_explore()  # 低置信度：触发深度探索
    else:
        medium_explore()  # 中等置信度：适度扩展
```

#### 复合评分算法

```python
def compute_composite_score(
    semantic_similarity: float,
    created_at: datetime,
    importance: float,
    config: MemoryConfig
) -> float:
    """综合评分 = 语义相似度 × 时效性衰减 × 重要性"""
    
    # 时效性衰减（指数衰减）
    days_old = (now - created_at).days
    recency_score = 0.5 ** (days_old / half_life_days)
    
    # 加权组合
    score = (
        semantic_weight * semantic_similarity +
        recency_weight * recency_score +
        importance_weight * importance
    )
```

#### 关键特性

1. **LLM驱动的智能分析**
   - 自动推断scope（作用域）
   - 自动提取categories（分类）
   - 自动评估importance（重要性）

2. **层次化作用域**
   ```python
   root_scope="/crew/research"
   # 记忆存储为: /crew/research/market-analysis
   ```

3. **记忆合并（Consolidation）**
   ```python
   consolidation_threshold=0.85  # 相似度>85%触发合并
   # 相似记忆会被LLM分析并合并
   ```

4. **异步保存**
   ```python
   _save_pool = ThreadPoolExecutor(max_workers=1)
   # remember()立即返回，后台线程执行编码
   ```

#### 与传统压缩的区别

| 维度 | 传统压缩 | crewAI统一记忆 |
|------|---------|---------------|
| **目标** | 减少token消耗 | 提高检索质量 |
| **方法** | 摘要替代原文 | 向量+元数据增强 |
| **存储** | 保留原文+摘要 | 原文+embedding+metadata |
| **检索** | 线性扫描 | 向量相似度搜索 |
| **智能化** | 规则驱动 | LLM驱动分析 |

#### 优势
- ✅ **检索质量高**：向量搜索+多维度评分
- ✅ **智能化强**：LLM自动分析和分类
- ✅ **可扩展**：支持多种存储后端（LanceDB、Chroma等）
- ✅ **批处理优化**：并行编码和检索

#### 局限
- ❌ **不减少token**：原文全部保留，只是增强了元数据
- ❌ **复杂度高**：需要向量数据库和嵌入模型
- ❌ **成本更高**：每次保存都需要LLM分析+嵌入

#### 设计理念

> "The logic for agents fits in ~thousand lines of code. We kept abstractions to their minimal shape above raw code!"

- **极简主义**：约1000行代码实现核心逻辑
- **用户控制**：不提供自动化，让用户自己决定如何管理
- **透明性**：所有memory操作都是显式的

#### 优势
- ✅ **简单易懂**：没有复杂的抽象
- ✅ **完全可控**：用户可以精确控制每一步
- ✅ **轻量级**：无额外依赖

#### 局限
- ❌ **无自动化**：需要用户自己实现压缩逻辑
- ❌ **容易出错**：忘记清理会导致token爆炸
- ❌ **不适合长对话**：没有内置的长期记忆

### 4. MetaGPT - 基础记忆实现

#### 源码位置
- `MetaGPT/metagpt/memory/memory.py`

#### 核心实现

```python
class Memory(BaseModel):
    """The most basic memory: super-memory"""
    
    storage: list[Message] = []
    index: DefaultDict[str, list[Message]] = defaultdict(list)
    
    def add(self, message: Message):
        """添加消息并更新索引"""
        self.storage.append(message)
        if message.cause_by:
            self.index[message.cause_by].append(message)
    
    def get(self, k=0) -> list[Message]:
        """返回最近的k条记忆，k=0返回全部"""
        return self.storage[-k:] if k > 0 else self.storage
    
    def try_remember(self, keyword: str) -> list[Message]:
        """尝试回忆包含关键词的消息"""
        return [msg for msg in self.storage if keyword in msg.content]
```

#### 特点

1. **简单列表存储**
   - 所有消息保存在list中
   - 按cause_by建立索引

2. **基础检索**
   - `get(k)`：获取最近k条
   - `try_remember(keyword)`：关键词匹配
   - `get_by_role(role)`：按角色过滤
   - `get_by_content(content)`：内容包含

3. **无压缩机制**
   - 没有token监控
   - 没有自动摘要
   - 没有向量检索

#### 优势
- ✅ **极其简单**：易于理解和调试
- ✅ **快速**：列表操作非常快

#### 局限
- ❌ **功能有限**：只有基础存储和检索
- ❌ **无压缩**：长对话会超出context window
- ❌ **检索弱**：仅支持关键词匹配

- ❌ **定制性较低**：受限于LangChain中间件接口

### 6. Hermes Agent - 六层记忆架构

#### 源码位置
- `hermes-agent/agent/memory_manager.py`
- `hermes-agent/agent/memory_provider.py`

#### 六层架构

```
┌─────────────────────────────────────┐
│ 第6层: 训练数据记忆 (Trajectory)     │ ← 用于模型微调
├─────────────────────────────────────┤
│ 第5层: 技能记忆 (Skills Registry)    │ ← 缓存已加载的技能
├─────────────────────────────────────┤
│ 第4层: 长期记忆 (Vector DB)          │ ← 向量数据库持久化
├─────────────────────────────────────┤
│ 第3层: 会话记忆 (Session Memory)     │ ← 跨任务持久化
├─────────────────────────────────────┤
│ 第2层: 工作记忆 (Working Memory)     │ ← 当前任务的上下文
├─────────────────────────────────────┤
│ 第1层: 即时记忆 (Immediate Context)  │ ← 当前step的消息
└─────────────────────────────────────┘
```

#### 压缩策略

1. **工作记忆压缩**
   - 监控token数量
   - 超过阈值时生成摘要
   - 保留最近N条消息

2. **长期记忆检索**
   - 向量相似度搜索
   - 只检索相关记忆到工作记忆
   - 避免全部加载

3. **技能缓存**
   - 已加载的技能缓存在内存
   - 避免重复加载相同的skill文件

#### 优势
- ✅ **分层清晰**：每层职责明确
- ✅ **可扩展**：支持多种存储后端
- ✅ **性能优化**：缓存和懒加载

#### 局限
- ❌ **复杂度高**：六层架构学习曲线陡峭
- ❌ **配置繁琐**：需要配置多个组件

## 💡 关键洞察

### 1. 压缩 vs 增强的两种哲学

**压缩派**（AgentScope, deer-flow, Hermes）：
- 目标：减少token消耗
- 方法：用摘要替代原文
- 优势：成本低，适合长对话
- 劣势：可能丢失细节

**增强派**（crewAI）：
- 目标：提高检索质量
- 方法：保留原文+添加元数据
- 优势：信息完整，检索准确
- 劣势：成本高，需要向量数据库

### 2. 自动化 vs 控制的权衡

**高自动化**（AgentScope, crewAI）：
- 优点：开箱即用，减少开发工作量
- 缺点：黑盒化，难以调试和优化

**高控制**（smolagents, MetaGPT）：
- 优点：透明，可精确优化
- 缺点：需要大量手动工作

### 3. 标记机制的创新

AgentScope的**标记机制**是一个巧妙的设计：
- 不删除原消息，而是标记为`COMPRESSED`
- 通过`exclude_mark`在检索时过滤
- 保留了随时恢复完整历史的能力
- 避免了数据丢失的风险

### 4. 批处理优化的重要性

crewAI的**批处理流水线**展示了高性能设计：
- 一次性嵌入所有文本（减少API调用）
- 并发搜索和LLM分析（提高吞吐量）
- 批量写入存储（减少I/O开销）

这种设计在生产环境中至关重要。
