## 1. 怎么用这张全景图

每个子系统下面固定四段：

| 段 | 含义 |
|----|------|
| **一句话** | 它解决什么用户/工程问题 |
| **挂点** | 常见 `ctx.*` / 事件域 |
| **协作** | 上下游谁调用谁 |
| **你何时改它** | 典型需求 → 落点 |

读完本章，你应能回答：「我想加 X，大概属于哪一类子系统？」然后去 PART 或 `source/` 深挖。

## 2. 核心主干（对话机器）

### 2.1 Agent（`ctx.agents`）

- **一句话**：对外的「智能体句柄」——创建/恢复、投递消息、取消、拦截。
- **挂点**：`ctx.agents`；状态经 Agent 事件与 Session。
- **协作**：UI/SDK → Agent → Inbox → AgentLoop 工厂创建的驱动器。
- **何时改**：换入口语义（followup/steer）、多 Agent 生命周期、取消行为。

### 2.2 Agent Loop（`ctx.agentLoop`）

- **一句话**：默认「思考→工具→再思考」驱动器（`ReactLoopAgent`）。
- **挂点**：`ctx.agentLoop.setFactory`；`agent/pre-step`、`agent/request`、`agent/turn-stopping`…
- **协作**：读 Inbox、写 Session、调 systemPrompt / llm / tools。
- **何时改**：改循环算法（极少）；多数需求用事件钩子而不是换工厂。

### 2.3 Session（`ctx.sessions`）

- **一句话**：对话**唯一真源**——只追加事件，用投影得到 messages。
- **挂点**：`append`、`deriveMessages`、`session/event`；`SessionEventMap`。
- **协作**：Loop/Tools/UI/Persistence 都订阅或写入它。
- **何时改**：新事件类型、投影规则、Turn/Step 边界语义。

### 2.4 Inbox（Agent 投递队列）

- **一句话**：把「下一轮用户话 / 插入指令」变成**可持久的 spliced 事件**，再被 turn 认领。
- **挂点**：`agent/inbox/spliced`、`claimed`；`claim()`。
- **协作**：`followup`/`steer`/`inject` → splice → wake → claim。
- **何时改**：投递语义、崩溃恢复队列、多来源合并策略。

### 2.5 Scope（作用域）

- **一句话**：按 Agent（等）隔离注册表，避免全局工具/钩子串台。
- **挂点**：Scope 上下文、注册标识。
- **协作**：tools / systemPrompt / 各类 Provider 注册。
- **何时改**：多 Agent、子 Agent 能力隔离。

### 2.6 Core 类型与不变式

- **一句话**：品牌化 ID、联合类型模式、`ctx.invariants` 运行时检查。
- **何时改**：加新领域类型、加必须守住的断言。

## 3. 模型与提示词

### 3.1 LLM（`ctx.llm`）

- **一句话**：模型适配器注册 + 流式协议（chunk → 消息块）。
- **挂点**：`ctx.llm`；`llm/*`；DeepSeek / 回放等 Provider。
- **协作**：Loop `buildRequest` → stream → Session `assistant/*`。
- **何时改**：新模型厂、流式协议差异、请求字段映射。

### 3.2 System Prompt（`ctx.systemPrompt`）

- **一句话**：每次请求前**拼** system 段 + 工具 schema 贡献。
- **挂点**：段落 Provider、工具 Provider 结果。
- **协作**：pre-step 通过后 → assemble → 进 LLM 请求。
- **何时改**：加人格/规则段、按会话改工具可见性。

### 3.3 Token Meter（`ctx.tokenMeter`）

- **一句话**：基于日志修订号的不可变用量度量（给压缩/计费用）。
- **协作**：compaction、遥测。

## 4. 工具与执行世界

### 4.1 Tools（`ctx.tools`）

- **一句话**：工具注册 + **受保护执行流水线**（prepare → guards → execute → finalize）；含 Code Mode。
- **挂点**：`ctx.tools`；`tools/pre-execute`、`execute`、`post-execute`。
- **协作**：Loop 的 `executeToolCalls` → ToolRuntime → Session `tool/*`。
- **何时改**：新工具、审批挂钩、改结果形状、Code Mode 折叠。

### 4.2 Filesystem（`ctx.fs`）

- **一句话**：读/写/编辑文件的统一 seam（可被沙箱约束）。
- **协作**：`tool-fs`、sandbox 策略。
- **何时改**：换存储后端、只读策略、观测文件状态。

### 4.3 Shell（`ctx.shell`）与 Subprocess（`ctx.subprocess`）

- **一句话**：bash 便捷层 vs 完全显式的进程 spawn。
- **协作**：`tool-bash`、沙箱 `ConfinedArgv`、终端。
- **何时改**：执行环境、环境变量 `DSH_*`、输出读取。

### 4.4 Sandbox

- **一句话**：每会话策略：文件效果模式、执行约束、故障关闭。
- **关键**：换沙箱必须 **fs + subprocess（等）成对**，否则策略空转。

### 4.5 Terminal / Code Runtime / LSP / Web 访问

| 子系统 | 一句话 |
|--------|--------|
| Terminal | 持久终端会话、有界读输出 |
| Code Runtime | 跑一段代码、捕获日志 |
| LSP | 跳转/符号等 IDE 导航 |
| Web（search/fetch） | 联网检索与抓取（工具侧） |

### 4.6 Attachment / Spill

- **Attachment**：持久图片等二进制附件。  
- **Spill**：过大文本外置存储，消息里留引用。

## 5. 人机协作（审批、提问、命令）

### 5.1 Approval（审批）

- **一句话**：一次性「允不允许」；策略可按会话；结果进审计。
- **协作**：常挂在 `tools/pre-execute` 或专用 guard。
- **场景**：危险 bash、写系统目录 → deny 则工具失败结果回模型。

### 5.2 User Questions（Ask User）

- **一句话**：结构化向用户提问并等答案（选项/自由文本）。
- **协作**：`tool-ask-user`、UI 表单。

### 5.3 Commands（斜杠命令等）

- **一句话**：人类命令注册表——**不一定**变成模型消息，可直接改领域状态。
- **何时改**：加 `/xxx`、适配不同 UI。

### 5.4 Plan Mode

- **一句话**：计划协作状态（仅记日志的 mode、退出计划审阅）。
- **协作**：与审批/命令交叉。

### 5.5 Permission Presets

- **一句话**：权限预设层（含 custom），变更记 `permission/preset` 事件。

## 6. 上下文与记忆类能力

### 6.1 Compaction（压缩）

- **一句话**：上下文太长时压缩；事件 `compaction/*`；引擎可替换。
- **协作**：常与 `agent/request-error`（上下文溢出）联动重试。
- **工具结果修剪**：`toolResultPruner` 可无模型先砍工具输出。

### 6.2 Skills（技能）

- **一句话**：发现/加载技能包；模型侧可有 `skill` 工具。
- **协作**：目录优先级、会话前缀、system prompt 贡献。

### 6.3 Schedule（会话内提醒）

- **一句话**：Session 内提醒记录 → 到点当普通对话交付。

---

## 7. 委派与外环编排

### 7.1 Subagent（`ctx.subagents`）

- **一句话**：启动子 Agent（进程内等 Provider）；能力在启动时与运行时拆分。
- **协作**：`tool-subagent`、独立或关联 Session。
- **何时改**：委派策略、结果汇总回父会话。

### 7.2 Workflow（`ctx.workflowEngine`）

- **一句话**：脚本化编排：`agent()`、子 Agent、步骤事件 `workflow/*`。
- **注意**：外环仍应落 Session，勿另造 transcript。

### 7.3 Goal（`ctx.goals`）

- **一句话**：持久目标 + Round 归属——同会话内为目标再开轮次。

### 7.4 Jobs（`ctx.jobs`）

- **一句话**：后台任务运行时（品牌化 JobId、消费方视图）。

### 7.5 Agent Presets

- **一句话**：按会话组合 Agent 能力（工具集/人格等）。

## 8. 会话周边

| 子系统 | 一句话 | 何时碰 |
|--------|--------|--------|
| **Persistence** | JSONL/SQLite 落盘、flush、崩溃恢复 | 换存储、修丢历史 |
| **Session Query** | 有界读事件、关系追踪、筛选/全文 | 做历史搜索 UI |
| **Session Projection** | 纯函数投影单元 + 快照切面 | 自定义 UI 视图 |
| **Session Title** | 日志支撑的标题、异步命名 Provider | 自动标题 |
| **Session Reference** | 跨会话结构化引用准备 | 「引用另一会话」 |
| **Message Feedback** | 对消息点赞/反馈记录 | 产品反馈 |
| **Session Telemetry** | 脱敏上报 sink（如 OTel） | 观测 |

## 9. 平台与宿主

### 9.1 Web Server / Client Modules / ApiProxy

- **WebServer**：HTTP 路由、静态、index 挂点。  
- **Client Modules**：`dsh.client` 声明拼出浏览器模块图。  
- **ApiProxy / Host**：浏览器 ↔ 宿主能力桥。

### 9.2 Settings / Credentials

- **Settings**：命名空间、分层解析（默认→base→用户）、热提交。  
- **Credentials**：配置里只有 `CredentialRef`，运行时按操作解析——**永不把密钥写进会话日志当明文真源**。

### 9.3 Storage / Workspace

- **Storage**：非会话域存储 hub + Domain。  
- **Workspace**：工作区实体与会话 `cwd` 关系。

### 9.4 Extensions / Typert

- **Extensions**：动态装插件（审批、版本、撤销）。  
- **Typert**：远程调用描述符与 Host Gateway——跨进程/扩展边界的类型化 RPC。

### 9.5 Hooks（Claude Code / Codex 兼容）

- **一句话**：对接外部钩子生态，把外部生命周期映射到 Harness 事件/工具。

## 10. 能力分组速查表

按「我想做的事」找组：

```text
改对话循环本身          → Agent / AgentLoop / Inbox / Session
换模型或提示词          → LLM / SystemPrompt
加工具或拦工具          → Tools + Approval
改文件/命令执行环境      → FS / Shell / Subprocess / Sandbox
上下文太长              → Compaction / TokenMeter / Spill
让用户点确认或填表      → Approval / UserQuestions / Commands
开子任务                → Subagent / Workflow / Goal / Jobs
历史落盘与搜索          → Persistence / Query / Projection
做 Web 产品面           → WebServer / ClientModules / ApiProxy
配置与密钥              → Settings / Credentials
```

官方完整表：`docs/subsystems/README.zh.md`（约 40+ 页，每页含类型与 Cordis API）。

## 本章总结

1. **主干五件套**：Agent 句柄、Loop 司机、Session 日志、Inbox 队列、Scope 隔离。  
2. **模型侧**：LLM 适配 + SystemPrompt 组装；用量靠 TokenMeter。  
3. **执行世界**：Tools 流水线 + FS/Shell/Subprocess；沙箱要成对换。  
4. **人机**：审批 ≠ Ask User ≠ 斜杠命令（权限 / 问答 / 直改状态）。  
5. **外环**：Subagent / Workflow / Goal / Jobs 决定「再开一轮」，不替代 Turn/Step。  
6. **周边**：持久化、查询、投影、标题、设置、凭据、Web 宿主——都订会话或挂 `ctx`，不另造 transcript。

记不住细节时：先用第 10 节「我想做的事」表定位组，再进官方 `docs/subsystems/` 看类型。
