## 1. 这是什么？

**DeepSeek Harness（DSH）** 是 DeepSeek AI 开源的 **Agent 外壳 / 智能体框架**。

命令行入口叫 **`dsh`**。你装上之后，可以：

- 打开 **Web 界面** 跟智能体聊天（默认 `http://127.0.0.1:3080`）  
- 用 **无界面模式** 跑一次性任务  
- 通过 **SDK / ACP** 把同一套能力接到自己的程序里  

它负责的是模型 **外面** 那一层工程：

| 它管 | 它不管 |
|------|--------|
| 怎么一轮轮对话（Turn/Step） | 模型权重训练 |
| 会话历史如何记、如何给模型看 | 替你选业务产品形态细节 |
| 工具怎么注册、审批、执行 | 某一个垂直行业的全部业务规则 |
| 文件/Shell 跑在本地还是沙箱 | — |
| 插件怎么热插拔扩展 | — |

一句话：

> **DSH = 可插件化的 Agent 运行时 + 会话真源 + 工具/执行环境 + 多种人机入口。**

技术栈：**TypeScript（ESM）**，npm 包 `@deepseek-ai/dsh-*`，Node `^22.19 || >=24`。  
阶段：**开发者预览**——破坏性变更会发生，磁盘格式无长期兼容承诺。

## 2. 给谁用、怎么跑起来

| 角色 | 典型诉求 |
|------|----------|
| 终端用户 / 试用者 | `npx @deepseek-ai/dsh web` 直接聊 |
| 应用集成方 | SDK / ACP 订阅会话事件、创建 Agent |
| 框架扩展作者 | 写插件：新模型、新工具、新策略、新 UI 块 |
| 研究/对照读者 | 理解「插件化 Harness」与 Session 事件溯源 |

### 最快上手

```bash
# 需要本机 Node
npx @deepseek-ai/dsh web
```

从源码：

```bash
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness && pnpm install && pnpm run build
pnpm dsh web
```

无界面示例（需配置 API Key，以官方 README 为准）：

```bash
dsh --profile headless "你的任务描述"
```

查看实际装了哪些插件配置：

```bash
dsh --profile web --dump-config
```

## 3. 解决什么问题（设计动机）

自己写一个「能调工具的 Agent」很容易；做成 **可扩展、可回放、可换执行环境、可多入口** 很难。典型失败：

### 3.1 双份真相

内存里一份 `messages[]`，磁盘或 UI 另一份 transcript。刷新、fork、崩溃恢复后模型和界面各说各话。

**DSH 对策**：会话 **只追加事件日志** 为唯一真源；给模型的历史每次用 `deriveMessages()` **投影**出来。口诀：**模型可见 ⟺ 已记录。**

### 3.2 策略缠死在循环里

审批、沙箱、压缩、换模型……全写进一个巨大的 `while`。想加策略只能 fork。

**DSH 对策**：循环只负责在固定检查点触发扩展（尤其 waterfall 事件）；策略以插件形式挂上，卸载即撤销。

### 3.3 换沙箱要改十处

Bash、读文件、PTY、LSP 各自判断「本地还是远程」。

**DSH 对策**：**执行世界绑定**——文件系统 Provider 与进程 Provider 成对指向同一世界（本地或 E2B 等）。

### 3.4 循环不可替换

工具、会话都 import 某个具体 Loop 类内部 API → 无法试验新 Driver。

**DSH 对策**：对外契约在 `Agent` / `ctx.agents`；默认实现 `ReactLoopAgent` 在 `agent-loop` 包。扩展依赖 `dsh-agent`，不依赖 loop 私有文件。且 **loop 本身也是插件**。

### 3.5 产品面复制粘贴

Web 一套循环、CLI 又抄一套。

**DSH 对策**：**Profile + Bundle** 组装。Web / Headless 差在装哪些插件，不差两套内核。

## 5. 设计思路（五条总纲）

后面所有章节都是这五条的展开。先背熟：

### 5.1 一切皆插件（含默认循环）

底座 **Cordis**：插件声明 `inject`，往 `ctx` 挂服务，用 `effect`/`on` 做可逆注册。  
没有「打补丁才能改」的特权内核——扩展方式是 **挂旁边**，卸载即撤销。

**容易误会**：「Loop 也是插件」≠ Turn/claim 每步都是拼出来的。默认 `ReactLoopAgent` 内部流程是**写死的**；插件指的是整包 `@deepseek-ai/dsh-agent-loop` 经 Patch 装上并 `setFactory`，可整包替换。日常改行为挂 waterfall。详见 [GLOSSARY · 一切皆插件](./GLOSSARY.md#一切皆插件到底指什么含-loop)。

### 5.2 日志是真源，历史是投影

`Session.append` 写入事实；`deriveMessages` 生成模型输入。  
UI 可订 `assistant/chunk` 做打字机；模型看折叠后的 `assistant/message`。两者同源。

### 5.3 策略在扩展点，不在巨类里

关键检查点（入门级）：

- `agent/pre-step`：这一步进不进模型、消息改成啥  
- `agent/request`：provider/model 等  
- `agent/request-error`：失败是否 retry  
- `agent/turn-stopping`：停轮前最后机会  
- `tools/pre-execute` 等：工具策略  

Waterfall：**不调 `next()` = 短路**（例如直接拒绝）。概念上就是中间件 / Spring Filter；名字是 Cordis 事件调度分类，不是新算法——见 [GLOSSARY · Waterfall 与 Filter](./GLOSSARY.md#waterfall-与-filter中间件)。

### 5.4 可替换能力要成套（Seam）

定义（`ctx.xxx`）+ Provider + Consumer。  
换远程：FS 与 Subprocess **成对**换，保持同一执行世界。

### 5.5 组装决定产品面

```text
空配置
  → Bundle（如 dsh-base → dsh-web-app）
  → profile patch → home patch → --patch
```

`dsh-base`：模型、工具、持久化、沙箱、审批、设置、凭据等。  
`dsh-web-app`：浏览器应用。  
`dsh-headless`：一次性运行器，不带服务器。

## 6. 和常见方案的对比

| 方案 | 特点 | 和 DSH |
|------|------|--------|
| 单文件 ReAct Demo | 快，不可扩展 | DSH 把 Demo 里的 while 工程化 |
| 某云 Agent SDK | 厂商闭环 | DSH 强调自托管插件树 + 日志真源 |
| Microsoft Agent Framework | Provider 管道 + 工作流图强 | DSH 更强调 Cordis 可逆插件 + Session 事件；对照见第七章 PART3 |
| LongHorizon-Harness 类 | 外环 Manager/Executor/Auditor | DSH 是 **自研内环**；LHH 是包在外部 CLI Agent 外的验收环 |

## 7. 仓库与发行形态（打开仓库会看到什么）

```text
deepseek-harness/
  packages/
    core/          会话、提示词、工具、agent、agent-loop、scope
    llm/           模型 seam 与适配器
    fs/ shell/ …   执行世界
    web/ host/ …   界面与网关
    subagent/ …    委派
    bundle/        base / web-app / headless 发行层
    boot/          Profile 组装
  docs/            官方权威短文档（双语、有字数预算）
  doc-sn/          本学习文档（中文长文）
```

npm：`packages/<组>/<包>` → `@deepseek-ai/dsh-<包名>`。

官方架构入口：`docs/architecture.zh.md`（改 `packages/` 前必读）。  
本目录 `doc-sn` **不**进 `doc-sync`，用于把故事讲完整；行为冲突时以官方 docs + 测试为准。
