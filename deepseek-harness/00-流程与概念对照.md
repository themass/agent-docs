## 1. 总对照表（新词 → 你已经会的东西）

| DSH 词 | 一句话 | 接近的旧知识 | **不是** |
|--------|--------|--------------|----------|
| **Cordis** | 插件运行时：装上挂服务，卸掉撤销 | OSGi / Spring 容器 + 可卸载 Bean | 又一个 Agent 框架语义层 |
| **`ctx`** | 进程里找服务的挂架 | Spring `ApplicationContext` | 某次 HTTP Request |
| **Profile** | 可启动的菜单（点哪些料包） | `application-web.yml` 激活哪套依赖 | Bundle 本身 |
| **Bundle** | 可发布的料包（自带一份配置补丁） | Spring Boot Starter | 启动入口 |
| **Patch** | 改「装哪些插件行」的 YAML 操作列表 | 多层 `application-*.yml` 覆盖 | git diff |
| **Waterfall** | 必须 `next()` 的中间件事件 | Filter / Interceptor / Koa middleware | 新算法 |
| **Agent** | 对外句柄：followup/steer/… | 一个会话上的 Facade | 循环源码类 |
| **Agent Loop / Driver** | 真正跑 while 的实现 | 司机；默认 `ReactLoopAgent` | 「每步都是小插件」 |
| **「Loop 是插件」** | **整包**经 Patch 装上并 `setFactory` | 换一个实现了接口的 Bean | while 被拆成积木 |
| **Session** | 只追加的事件日志 | Event Sourcing 的 event store | `messages[]` 数组本身 |
| **`deriveMessages`** | 从日志投影出给模型的 messages | 读模型 / CQRS 查询端 | 第二份真源 |
| **surface / surfaceOp** | 哪些事件算「对话历史上的点」 | 物化视图；replace≈压缩改写 | 磁盘格式专用名词 |
| **Inbox** | 两个待办桶（也落日志） | 双队列：next-turn / next-step | 纯内存、可丢的 list |
| **splice** | 入队并写 `inbox/spliced` | 持久化 enqueue | 立刻写成 user/message |
| **claim** | 出队并记账 | dequeue + ack | 和 splice 同一动作 |
| **wake / kick** | 空闲则启动驱动；kick=while turn | 线程从 sleep 到 run；kick=工作循环 | tool 结束后的轮询铃 |
| **Turn** | 一轮大边界 | 一次「打开到关闭」的业务轮 | Pi 的 turn（Pi 的 turn≈DSH Step） |
| **Step** | 一次模型调用（可含工具） | 内环一拍 | Turn |
| **Seam** | 可替换能力的定义+实现+使用方 | 端口/适配器 | 随便一个接口 |
| **执行世界** | fs+subprocess 必须同一本地/远程 | 同一 chroot/沙箱 | 只换其中一个 |

## 2. 发一句话：逐步到底（含写了什么）

场景：Web 空闲，用户发送「重构这段」。

源码锚点：`ReactLoopAgent.send/followup/wakeDriver/kick/turn/preStep`（`packages/core/agent-loop/src/agent.ts`），`Inbox.splice/claim`（`packages/core/agent/src/inbox.ts`）。

### 总览（三拍）

```text
① 入队 splice（日志里已有排队事实）
② 唤醒 wake → kick（空闲才真正开跑）
③ 认领 claim → Turn/Step → 写表面 → 调模型/工具
```

### 逐步：输入 / 动作 / Session 多了什么 / 内存变什么 / 插件能拦吗

#### 步骤 1 — UI 调用 `agent.followup(userMessage)`

| | |
|--|--|
| **输入** | 一条 `UserMessage`（文本等） |
| **动作** | `followup` → `send(msg, 'next-turn', wakeup=true)` |
| **Session 写入** | 尚无 `user/message` |
| **对照** | 业务 Facade 接到请求 |

#### 步骤 2 — `inbox.splice('next-turn', …)`

| | |
|--|--|
| **动作** | 先 `session.append('agent/inbox/spliced', { target, inserted, … })`，再改 Inbox 内存数组 |
| **Session 写入** | **`agent/inbox/spliced`**（可回放「当时队列有什么」） |
| **内存** | `next-turn` 桶多一条 |
| **还不是** | 对话历史上的用户气泡节点（表面尚未 append user/message） |
| **对照** | 持久化消息队列 enqueue，不是直接 insert 聊天记录 |

#### 步骤 3 — `wakeDriver()` → `kick()`

| | |
|--|--|
| **若 idle** | `phase=running`，异步跑 `kick()`：`while (await turn()) {}` |
| **若已 running** | 一般直接 return（自己会 claim）；特殊 abort/maintenance 才闩 `wakeRequested` |
| **Session** | 本步通常不写 |
| **对照** | 线程池里提交任务；已在跑则不用再 start |

#### 步骤 4 — `turn()` 开头：`session.append('turn/start', { turn })`

| | |
|--|--|
| **Session 写入** | **`turn/start`** |
| **含义** | 打开大边界；后面可以有 0..N 个 Step |

#### 步骤 5 — `preStep` → `inbox.claim(...)`

| | |
|--|--|
| **动作** | 领光 `next-step`，再领 `next-turn` 队头 1 条；写**删除型** `inbox/spliced`；发 `claimed` 通知 |
| **Session 写入** | 又一条 **`agent/inbox/spliced`**（removed） |
| **内存** | 对应桶变短；得到 `claimed: UserMessage[]` |
| **对照** | dequeue + consumer ack |

#### 步骤 6 — `systemPrompt.assemble` + waterfall `agent/pre-step`

| | |
|--|--|
| **动作** | 拼系统提示；监听器可改 messages 或 **`reject`** |
| **Session** | 通常还不写 user/message |
| **插件** | ✅ 可拦（压缩、策略拒绝等） |
| **对照** | Filter 链；不调 `next` / 返回 reject ≈ 短路 |

#### 步骤 7a — 若 reject 或首步 messages 为空

| | |
|--|--|
| **Session 写入** | **`turn/end`**（可能**没有任何** `step/*`） |
| **含义** | 开了轮次边界，但没调模型 |

#### 步骤 7b — 若 enter 且有消息：开 Step

| | |
|--|--|
| **写入** | `step/start` → 对每条 claimed：`user/message`（**`surfaceOp: append`**） |
| **此时** | UI 历史 / `deriveMessages` 才看到这句用户话 |
| **对照** | 出队成功后才写入业务流水 |

#### 步骤 8 — `deriveMessages()` → LLM stream

| | |
|--|--|
| **读** | 只从 Session 表面投影，**不**另维护真 messages[] |
| **写** | 流式 `assistant/chunk*`（常不进表面）；结束折叠 `assistant/message`（进表面） |
| **对照** | Event store 上建读模型，再调外部 API |

#### 步骤 9 — 若有 tool-calls

| | |
|--|--|
| **写** | `tool/call` →（waterfall pre/execute/post）→ `tool/result`（可带 `sourceEventSeqs`） |
| **插件** | ✅ `tools/*` 可审批、改写、超时包装 |
| **对照** | 网关后的下游调用 + 中间件 |

#### 步骤 10 — `step/end`；或许 `turn-stopping`；`turn/end`

| | |
|--|--|
| **若本轮该停且 `next-step` 空** | serial `agent/turn-stopping`（最后插话机会） |
| **若 `next-step` 仍有** | 继续下一步，`target=next-step`（**不必再 wake**） |
| **kick 结束** | `phase=idle`；若闩过且还有 pending → 再 wake |

#### 步骤 11 — UI

| | |
|--|--|
| **读** | 订 `session/event` 刷新；不是另有一套 WS 业务协议真源 |

### 一张「写了什么」清单（成功路径）

```text
agent/inbox/spliced     ← 入队
turn/start
agent/inbox/spliced     ← claim 删除
step/start
user/message           ← 首次进入对话表面
assistant/chunk*        ← 可选，多给 UI
assistant/message
tool/call, tool/result  ← 若有
step/end
turn/end
```

## 3. 固定流程 vs 插件到底什么意思

```text
你看到的固定 while：
  ReactLoopAgent 源码里的 kick/turn/claim/step
  → 这是「默认司机」的算法，当然是固定的

文档说的「皆插件」：
  @deepseek-ai/dsh-agent-loop 和 tools/llm 一样
  出现在 cordis.patch.yml 的一行
  启动时 setFactory；卸掉则无法 create Agent
  → 「整包是部署单元」，不是「while 每行是插件」
```

| 你想改的 | 正确做法 |
|----------|----------|
| 某步拒绝对话 / 改消息 | 挂 `agent/pre-step` waterfall |
| 工具审批 / 超时 | 挂 `tools/*` |
| 换模型厂 | 换/加 llm Provider 插件 |
| 换整套循环哲学 | **换 agent-loop 插件（新 Factory）** |
| 在默认 while 里加 if remote | ❌ 违反设计；用执行世界成对 Provider |

详见 [GLOSSARY · 一切皆插件](./GLOSSARY.md#一切皆插件到底指什么含-loop)。

## 4. followup / steer / inject / 唤醒

| API | 桶 | 唤醒 | 何时用 |
|-----|----|------|--------|
| **followup** | next-turn | ✅ | 用户新话 |
| **steer** | next-step | ✅ | 插话且希望马上被处理（含空闲时） |
| **inject** | next-step | ❌ | 只塞上下文，不独自开跑 |

**唤醒 ≠ tool 结束后的检查。**  
running 时 step 边界自己看队列；唤醒只解决 **idle → 开 kick**。  
steer 带唤醒，是因为空闲时也要插一句能跑；已在跑时 wake 基本空操作。

## 5. Session / Inbox / messages：谁真谁假

```text
真源：SessionEvent 日志（只追加）
  ├─ Inbox 状态 ← 一串 inbox/spliced 的投影（和对话一样可回放）
  ├─ 对话表面 ← 带 surfaceOp 的事件折叠
  └─ deriveMessages() ← 给模型的 messages[]（读模型，可丢可重建）

假源（不要维护）：
  ✗ 与日志并行的第二份「真」messages[]
  ✗ 只活在内存、不写 spliced 的排队（刷新即谎）
```

| 操作 | 进表面？ | 进 deriveMessages？ |
|------|----------|---------------------|
| `inbox/spliced` | 否 | 否 |
| `user/message` + surfaceOp append | 是 | 是 |
| `assistant/chunk` | 通常否 | 通常否 |
| `assistant/message` | 是 | 是 |

和 Pi：`AgentMessage[]` 常是热路径工作集，`convertToLlm` 在调用边界转换；DSH 热路径也 append，投影只读。细表见 [05](./05-对照-Pi-与-DSH.md)。

## 6. 和 Pi 差在哪（一眼表）

| | Pi | DSH |
|--|----|-----|
| 跑法 | 一次 `prompt` 跑完一段 | 常驻 Driver，idle 可再 wake |
| 排队 | 内存 steer/followUp，run 内 drain | Inbox 两桶 + 持久 spliced |
| 历史 | 数组 + Session 树分层 | 事件日志唯一真源 |
| 给模型 | convertToLlm | deriveMessages |
| 扩展 | 回调 / Extension | Cordis 插件 + waterfall |
| 「turn」 | ≈ DSH Step | Turn ⊃ Step |
