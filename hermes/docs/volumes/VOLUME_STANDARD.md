## 1. 阅读结构

每卷先用一段话说清**本卷的问题与边界**，再给目录；正文采用“整体关系 → 各角色职责 → 一次真实流程 → 分支/失败/恢复 → 总结与源码入口”。

首次出现易混概念时用一句人话解释；可以在第一节集中对照，也可以跟随相关分述解释。旧 MANIFEST 对“是否以先澄清开篇”的限制不作为本轮增补的硬性格式约束；重要的是读者在读第一张图前就理解名词，而不是机械统一标题。

一个专题至少回答：

1. 它解决什么问题？如果没有它，会发生什么？
2. 谁调用谁，谁持有状态，状态放在哪？
3. 输入、输出与身份是什么？
4. 成功路径怎样走？失败/中断/并发/重启怎样处理？
5. 哪些是本模块责任，哪些不是？
6. 实际读了哪些源码，还有什么没核对？

<a id="standard-evidence"></a>
## 2. 证据与源码解读

- 记录本地源码 root、commit 和 dirty 状态；不把本地提交冒充远端 latest。
- 引用 `文件:符号`，优先真实类名/方法名；行号只用于快照内的定位，不作为长期身份。
- 分开**事实**、**设计解释**、**示意伪代码**和**未验证假设**。设计动机没有作者证据时写“解读/取舍”，不伪造 ADR。
- 摘录可以加中文注释，但必须标明哪些是新增解读、是否省略外壳；不要伪称可直接运行。
- 读过测试断言可以作为设计验证入口；没运行就不能写“测试已通过”。
- 不能从 AST 找到了名字，推出线程安全、恢复可靠或端到端行为已经验证。

<a id="standard-diagrams"></a>
## 3. 图表规则

| 图 | 应解释的问题 | 禁止误用 |
|---|---|---|
| 架构图 | 组件、边界与依赖/数据通路 | 把每个函数都当成独立服务 |
| 类图 | 持有/继承/依赖与接口契约 | 为了美观虚构类或继承 |
| 时序图 | 单个场景按时间怎么发生 | 把所有可选分支挤成必然发生的步骤 |
| 流程图 | 条件、裁决、恢复 | 忽略提前返回或失败分支 |
| 状态图 | 什么状态由什么动作改变 | 混合不同账本的同名状态 |

每图解释线的含义，明确是事实路径还是机制示意。一张图过密就按阶段拆；正文里的大图必须有短说明，不能只留代码围栏。

Markdown 中 Mermaid 可维护；渲染验证与文本检查是不同验收。未渲染的图不得声称已完成视觉验收。

<a id="standard-depth"></a>
## 4. 覆盖深度

| 级别 | 意味着什么 | 不意味着什么 |
|---|---|---|
| L0 清点 | 文件在受控源码清单中，分类与 hash 可复查 | 已理解实现 |
| L1 导航 | 有职责说明、入口和对应卷 | 核心分支已审计 |
| L2 源码专题 | 读到关键实现，讲清主路径、状态边界与重要失败分支 | 整个模块逐行验证、所有平台行为一致 |
| L3 运行验证 | 指定场景实测/测试有记录 | 全局正确性证明 |

本轮主要增加 L2 专题，生成 L0 清单与 L1 地图；**没有新增 L3 运行时验证**。原“达标”沿用旧文的结构评价，不可替代这套实现覆盖深度。

<a id="standard-validation"></a>
## 5. 增量维护与验收

现行正文是 `volumes/`。`archive/legacy/` 保存历史证据，不再作为手写现行章的自动覆盖来源。

`_merge/build_volumes.py` 已有 `HERMES_REBUILD_VOLUMES=1` 保护。不要为了“刷新目录”开启这个变量重建：它会覆盖手写卷和 MANIFEST，不能替代现行章维护。要考古重建时，应使用另一个隔离输出目录/副本，先明确要保存什么。

新增专题默认追加到对应卷；跨卷大主题可以增开卷并更新导航。保留旧文但发现冲突时用日期/快照/澄清注说明当前证据，而不是悄悄删掉旧结论。

本轮工具：

```sh
# 在 docs 仓库根执行；只读取 Hermes 源码，不 import/启动应用。
python3 hermes/docs/_merge/audit_source.py --check
python3 hermes/docs/_merge/verify_volumes.py
# 换源码快照后显式重建机械清单；专题证据仍需人工复核。
python3 hermes/docs/_merge/audit_source.py --write
```

验收至少检查链接、锚点、代码围栏、新增引用符号、清单漂移与原文保全。图表数量、字数只能说明增量规模，不说明设计完整。


### 章内专题增补的保全例外

用户要求在原章内补充时，可插入有成对边界标记的新增节和目录项，仍不得删除或改写旧段落。卷三第4章采用 `compression-detail` / `compression-toc` 两个限定区域；保全检查剥离它们后核对原文字节，其他文件保持追加式检查。该例外不表示可以任意跳过其他章节的改动。
