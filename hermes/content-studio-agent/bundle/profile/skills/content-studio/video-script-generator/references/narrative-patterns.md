# GitHub 视频叙事链模式库

脚本生成时优先寻找项目之间的关系。不要把项目当作孤立 TOP3，而要组织成能解释趋势的链路。

## 模式 1：标准 -> 增强 -> 成本 -> 落地

适合 Skill、Agent、开发工具、工程化项目。

```text
标准制定者 -> 工程增强包 -> 成本压缩网关 -> 本地落地载体
```

示例角色：

- 标准制定者：定义 SKILL.md、协议、模板、规范。
- 工程增强包：提供命令、规则、子 Agent、测试、审查、权限。
- 成本压缩网关：解决 Token、上下文、缓存、调用成本。
- 本地落地载体：把上面能力接进真实开发环境。

开场 thesis 示例：

```text
这期 GitHub 热榜真正爆发的不是单个工具，而是 AI 开发环境开始进入职业化部署阶段。
```

## 模式 2：底座 -> 调度 -> 记忆 -> 应用

适合 Agent 框架、长期记忆、多智能体、个人助手。

```text
模型/框架底座 -> Agent 调度 -> 记忆/上下文 -> 应用场景
```

重点解释：

- 底座解决「能不能做」。
- 调度解决「怎么拆任务」。
- 记忆解决「怎么长期工作」。
- 应用解决「普通用户为什么需要」。

## 模式 3：痛点 -> 方案 -> 验证 -> 生态

适合新工具、效率产品、开发者基础设施。

```text
真实痛点 -> 开源方案 -> Demo/数据验证 -> 生态扩展
```

适合开场：

```text
这期热榜说明一个问题：开发者不缺更聪明的 AI，缺的是能稳定跑在真实项目里的工作流。
```

## 模式 4：个人工具 -> 团队流程 -> 企业标准

适合从个人配置、模板、插件演进到团队工程实践的主题。

```text
个人效率工具 -> 团队协作规范 -> 企业级治理
```

可用角色：

- 个人效率放大器。
- 团队流程标准化工具。
- 企业治理/审计/安全层。

## 模式 5：视觉 Demo -> 生产能力 -> 商业机会

适合 UI、视频、设计、数据可视化、多模态项目。

```text
惊艳 Demo -> 可复用工具链 -> 内容/商业生产机会
```

重点：

- 开场用画面冲击。
- 项目段解释「为什么不只是玩具」。
- 收尾给创作者或独立开发者机会。

## 选链规则

优先级：

1. 能解释本期 Top10 共性。
2. 项目之间有因果或能力补齐关系。
3. 每个项目角色清晰。
4. 画面表达容易做：概念卡、流程图、GitHub 滚动红框。
5. 结尾能给出长期判断。

如果没有完美链路，选择 2 个强相关项目 + 1 个补充项目，但必须解释第三个项目如何扩展主题。

## 反例

不要这样组织：

```text
第一个项目很好用，第二个项目也很好用，第三个项目很酷。
```

应该改成：

```text
第一个项目定义标准，第二个项目把标准变成工程流程，第三个项目解决流程落地后的成本问题。
```
