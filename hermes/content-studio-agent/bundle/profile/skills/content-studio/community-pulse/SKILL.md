# GitHub 30 天社区热点简报

把 **GitHub Trending 排名** 和 **过去 30 天社区真实讨论** 拼在一起：日报告诉你「哪些项目在涨」，本 Skill 告诉你「大家在 Reddit / HN / YouTube / GitHub 上怎么评价这些项目」。

底层引擎：[`last30days`](https://github.com/mvanhorn/last30days-skill)。本 Skill 是 GitHub Agent 的上层封装，负责选题、调用、归档、质量门禁和推送。

---

## 触发条件

- Cron 每日 08:45（在日报 08:00 之后）
- Chat：`社区脉搏` / `community pulse` / `大家在说什么` / `last30days`
- 手动：`content-studio.sh community-pulse [YYYY-MM-DD]`

---

## 前置检查

```
1. 今日日报是否存在？
   → reports/YYYY/MM/YYYY-MM-DD.md
   → 不存在：先执行 github-daily，再继续

2. last30days 是否可用？
   → 优先检查 ~/.hermes/skills/research/last30days/scripts/last30days.py
   → 不存在：提示运行
     hermes skills install mvanhorn/last30days-skill --force

3. Python 3.12+ 可用？
   → python3.12 --version 或 python3 --version
```

## 执行步骤

### Step 1 — 从日报提取研究对象

读取今日日报 `reports/YYYY/MM/YYYY-MM-DD.md`：

1. 从「Top 15 热门项目」或「今日总览」表格提取 **排名前 3** 的项目
2. 每个项目记录：`排名`、`owner/repo`、GitHub URL、一句话简介
3. 若详情区不可用，才从正文中的 GitHub repo URL 去重提取

**硬规则**：研究对象必须来自当日日报，不得自行搜索 GitHub Trending 另找项目。

### Step 2 — 调用 last30days 做跨平台检索

定时任务和 shell 入口使用确定性 runner：

```
python3 skills/content-studio/community-pulse/scripts/generate_community_pulse.py \
  reports/YYYY/MM/YYYY-MM-DD.md \
  reports/YYYY/MM/YYYY-MM-DD-community-pulse.md \
  YYYY-MM-DD
```

runner 对每个 Top 3 项目调用 last30days engine：

```
last30days "{repo-name} GitHub repository" \
  --days 30 \
  --github-repo owner/repo \
  --search hackernews,polymarket \
  --emit md \
  --quick \
  --plan reports/YYYY/MM/YYYY-MM-DD-community-pulse-raw/YYYY-MM-DD-plan-{owner-repo}.json
```

**失败策略**：任何一个项目的 last30days 调用失败、超时或返回空输出，整个简报生成失败。不得生成降级简报，不得用项目 README 摘要冒充社区讨论。

### Step 3 — 合成社区脉搏

将 3 份 last30days raw 结果合并为一份结构化简报：

```
reports/YYYY/MM/YYYY-MM-DD-community-pulse.md
reports/YYYY/MM/YYYY-MM-DD-community-pulse-raw/{DATE}-community-pulse-raw-{owner-repo}.md
```

模板：

```markdown
# 30 天社区热点简报

📅 {DATE} | 数据源：last30days（Reddit / HN / GitHub / …）
📎 基于日报：reports/YYYY/MM/YYYY-MM-DD.md

---

## 今日研究对象（来自 Trending Top 3）

| # | 项目 | 社区研究原始记录 |
|---|------|------------------|
| 1 | [owner/repo](url) | `{raw_path}` |
| 2 | ... | ... |
| 3 | ... | ... |

---

## 项目 1：{name}

### last30days 摘要摘录
保留 last30days 输出里的证据、引用和链接。

### 值得跟进
- 1-2 条 actionable 结论

---

## 项目 2：{name}
（同上结构）

---

## 项目 3：{name}
（同上结构）

---

## 横切结论

1. 今日 Trending 项目的共同叙事是什么？
2. 社区情绪：兴奋 / 质疑 / 观望？
3. 对开发者或内容创作者的 1 条建议

---

*Generated by Content Studio + last30days @ {timestamp}*
```

### Step 4 — 归档与推送

1. 通过 `report_dispatcher.py` 更新 `reports/index.md` / `index.html`
2. 在 Chat / stdout 输出简报摘要（3 条要点 + 文件路径）
3. 若配置了 webhook（`CONTENT_STUDIO_WEBHOOK_URL` 等），通过 report_dispatcher 推送

---

## 质量标准

- 每个项目必须有一份非空 last30days raw 输出
- 不得编造讨论内容；证据不足时标注「社区讨论较少」
- 中文结构化说明，项目名和 @handle 保留英文
- 不得生成降级简报；失败必须暴露给 shell / cron 日志

## 配置（可选）

环境变量（写入 `~/.hermes/profiles/content-studio/.env` 或 `~/.config/last30days/.env`）：

| 变量 | 作用 |
|------|------|
| `LAST30DAYS_SCRIPT` | 显式指定 `last30days.py` 路径 |
| `CONTENT_STUDIO_COMMUNITY_STABLE` | 默认 `1`。为 `1` 时即使 shell 里配置了更广的源，也只会使用 `hackernews,polymarket` |
| `CONTENT_STUDIO_COMMUNITY_SOURCES` | 仅在 `CONTENT_STUDIO_COMMUNITY_STABLE=0` 时生效；可设为 `reddit,hackernews,github,polymarket,youtube` |
| `LAST30DAYS_MEMORY_DIR` | last30days raw 输出目录，默认 `~/Documents/Last30Days/` |
| `BRAVE_API_KEY` | 增强 Web 搜索 |
| `XAI_API_KEY` 或浏览器 Cookie | X/Twitter 检索 |
| `SCRAPECREATORS_API_KEY` | TikTok / Instagram |
| `CONTENT_STUDIO_WEBHOOK_URL` | 简报 webhook 推送 |

安装 YouTube 支持：

```bash
brew install yt-dlp
```
