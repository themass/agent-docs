## 1. 为什么要单独成包？

| 问题 | AgentKit 解法 |
|------|----------------|
| 每个新项目复制 trace、Session、OSS | **一次沉淀，入库 wheel 引用** |
| DeerFlow import 散落 | **只在 `agentkit.adapters.deerflow` import** |
| `util.py` 垃圾堆 | 包内 **`agentkit.common`** 统一维护 |
| 启动慢 | `create_app` + `TraceMiddleware` + Actor 基类开箱即用 |

**原则（P2 升级）：** 跨项目复用代码 **必须进 AgentKit**，产品仓库只留 **业务域**。

### 3.1 `observability`：监控是底层能力，不是某个产品的功能

为什么它进包而不是留在 job-come：**每个 agent 服务都要回答同一个问题——「这 16 秒
花在哪了」**。回答它需要一套跨服务一致的词汇（指标名、标签集、分桶边界），而不是每个
项目各写一套再加总对比。

三步接入（完整示例见 `libs/agentkit/README.md`）：

```python
from agentkit.observability import configure, CONTENT_TYPE, render_metrics

configure(application="my-service", environment="prod")

@app.get("/metrics", include_in_schema=False)
async def metrics() -> Response:
    return Response(content=render_metrics(), media_type=CONTENT_TYPE)
```

打点：`@method_metrics()` 注解、`record_llm_metrics()`、`record_agent_phase()`。

三条强制约束（有测试钉住）：

| 约束 | 原因 |
|---|---|
| 标签不取无界值 | 不带 user_id / session_id / 异常文本。series 爆炸是指标后端最常见的死法 |
| 记录绝不抛异常 | 指标失败不能影响它观察的请求 |
| 「没有数据」≠ 0 | 服务不可达时联邦结果保留失败行，不从列表消失 |

**多 worker 必须额外一步**，且只能在启动脚本里做：

```bash
export PROMETHEUS_MULTIPROC_DIR=/var/tmp/my-service-metrics   # import 之前
```

prometheus_client 在 import 时决定计数器的存储方式（`values.py`:
`ValueClass = get_value_class()`）。在应用里、在 `.env` 里、在 import 之后设置都
**无效**，而且失败是静默的：指标看起来正常，每个 worker 各算各的，抓一次只拿到一个
worker 的数字。这一条是实测踩出来的，见 ADR-010。

**多服务面板**：每个服务暴露 `/metrics/snapshot`（同一 registry 的 JSON 视图），
由面板所在的服务用 `collect_peer_snapshots()` 并发拉取。面板按服务分 tab 而不是
合并——两个进程的计数器起始时间不同，加起来是没有任何服务产生过的数字。

## 4. 新产品如何依赖

### 4.1 Python（uv / pip）

```toml
# <product>/pyproject.toml
dependencies = [
  "agentkit",
  "sqlalchemy[asyncio]>=2.0",
  # 产品特有…
]

[tool.uv.sources]
agentkit = { path = "wheels/agentkit-<版本>-py3-none-any.whl" }
```

```bash
cd my-product && uv sync
```

wheel 由 `libs/agentkit/scripts/build.sh` 产出并分发，见 §7。

### 4.2 产品 main.py 示例

```python
from agentkit.common.logging import configure_logging
from agentkit.web import TraceMiddleware, create_app

configure_logging(json_logs=True)
app = create_app(title="MyProduct")
app.add_middleware(TraceMiddleware)

# 挂载产品 routers…
```

### 4.3 脚手架命令（建议）

```bash
# 未来可提供（M2）
# uv run agentkit new-project my-app --prefix ma_
```

## 5. 贡献规则（进包门槛）

代码 **合并进 AgentKit** 须满足：

1. **≥2 个产品会用**，或 **明确是 Agent 产品标配**（如 DeerFlow client）
2. **无产品域名词**（不出现 `Profile`、`Interview`、`jc_`）
3. **有单元测试**（`libs/agentkit/tests/`）
4. **semver**：破坏性变更升 minor/major，changelog 写明影响产品
5. DeerFlow / boto3 等重依赖放 **`[project.optional-dependencies]`**

## 6. 与「项目内 common/」的关系

| 阶段 | 做法 |
|------|------|
| **探索期** | 可先写在 `{pkg}/common/`，稳定后 **上提到 agentkit** |
| **稳定后** | 产品删除重复 `common/`，改 `from agentkit.common import …` |
| **禁止** | 产品 `common/` 与 agentkit **长期双份维护** |

JobCome：W0 起 **新代码优先 agentkit**；已有 `src/jobcome/common/` 随 W0 迁移合并。

## 7. 版本与发布

| 环境 | 方式 |
|------|------|
| 本仓库产品 | 入库 wheel：`agentkit = { path = "wheels/agentkit-<版本>-py3-none-any.whl" }` |
| 部署机 | 同上——装 wheel 不需要 monorepo 源码 |
| 私有 PyPI（可选） | `agentkit==0.1.x` |
| 版本 | 由 `build.sh` 生成：`0.1.0+YYYYMMDD.<内容哈希8位>` |

**不要用 `path = "../libs/agentkit", editable = true`。** 实测它让部署机 `uv sync`
失败（`Distribution not found at: file:///.../libs/agentkit`）：部署机没有 monorepo，
而 path 依赖把它变成了硬要求。

改 agentkit 后的唯一流程：

```bash
libs/agentkit/scripts/build.sh            # 构建 + 改版本 + 分发到每个产品
libs/agentkit/scripts/build.sh --check    # 校验源码与已提交 wheel 一致（CI 用）
```

校验比的是**内容摘要**而非版本号——版本号没变而内容变过，是已经发生过的事故。
见 [`libs/agentkit/VERSION_SCHEME.md`](../../libs/agentkit/VERSION_SCHEME.md)。
